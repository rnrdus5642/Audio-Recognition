# 2번 문제: 출력 어휘와 IPA 중복 분석 (2026-09-06)

**상태: 분석·문서 정리 완료. 출력 확장·라벨 통합·추가 학습·배포는 보류.**
사용자 요청에 따라 이 부분은 문서만 정리하고 3번 임계값 산출 문제로 넘어간다.
기존 아동 파인튜닝 모델·배포 어휘·임계값은 그대로다. `놔` 출력 행을 추가한
별도 1206 출력 후보도 해당 행을 아직 학습하지 않은 상태로 보존한다.

## 문제의 범위

배포 모델의 출력 1,205항목은 **한글 음절 1,202개 + 특수 항목 3개**다.
자음·모음을 자유롭게 조합하는 출력 방식이 아니므로, 목록에 없는 글자는
그 철자로 정확히 전사할 수 없다.

- 현재 목표 29단어에서는 `놔` 한 글자가 빠져 `놔`·`놔요`가 영향을 받는다.
- 더 넓은 아동 전사 점검에서는 누락 **철자 523종**이 확인됐다. `놔`만 추가한
  후보는 전체 어휘 문제를 해결한 것이 아니다.
- 523은 새로운 발음이나 필수 추가 출력의 수가 아니다. 발음 채점은 IPA를
  비교하므로, 철자가 달라도 IPA가 같은 경우를 구분해야 한다. 정확한 철자
  전사 가능 여부와 정답 확정 가능 여부도 별개다.

## 점검 대상과 정규화

색인 2,765,817행 중 화자 분할에 배정된 **654,677행**을 점검했다. 나머지
2,111,140행은 이번 집계 대상이 아니다. 따라서 523을 전체 색인이나 한국어
전체의 누락 수로 일반화하지 않는다. 길이·어휘 필터 적용 전 전사를 기준으로 했다.

| 분할 | 점검 행 | 누락 철자 종류 | 누락 철자가 하나 이상 있는 행 |
|---|---:|---:|---:|
| train | 407,068 | 467 | 31,485 |
| dev (train 화자에서 분리) | 22,366 | 268 | 1,885 |
| valid | 111,791 | 371 | 8,712 |
| test | 113,452 | 339 | 8,671 |
| 합집합 | 654,677 | **523** | — |

한 행에 누락 철자가 여러 개 있어도 영향 행 수는 한 번만 센다. valid/test는
현황 점검에만 사용했으며 학습 데이터를 새로 선정하지 않았다. 이전 한글·공백
정규식을 재구성한 결과와 현재 NFC 정규화 결과 모두 누락 523종으로 같았고,
추가·제거 문자 집합은 비었다. 실제 음성이나 라벨 품질은 이 검사로 평가하지 않았다.

## 같은 IPA를 내는 글자를 제외하면

실제 런타임 `KoreanG2P.to_ipa`로 글자를 **하나씩 단독으로** 변환했다.
음운 규칙 적용 후 IPA 토큰 배열이 정확히 같은지 비교했으며, 원시 자모 표나
혼동행렬의 근사 점수를 동치 기준으로 쓰지 않았다. 비교 대상은 출력 가능한
한글 1,202개다. 체크포인트와 배포 글자표의 1,205개 토큰 번호 일치도 확인했다.

| 항목 | 결과 |
|---|---:|
| 출력 목록에 없는 철자 | 523종 |
| 기존 글자 하나로 같은 단독 IPA를 낼 수 있는 철자 | **110종 (21.0%)** |
| 그러한 기존 글자가 없는 철자 | **413종** |
| 남은 413종을 같은 단독 IPA끼리 묶은 수 | **391가지** |

예를 들어 `밧`·`받`·`밭`은 모두 `[p, a, t̚]`다. `꾀`·`꿰`도 현재 프로젝트
변환기에서는 같은 IPA다. `놔`의 `[n, w, a]`와 같은 단독 IPA를 내는 기존 글자
하나는 없어서 `놔`는 남은 413종에 포함된다.

**391은 기본 자음·모음의 수가 아니라 음절 IPA 조합의 수**다. 최소 추가 출력
수나 모델이 낼 수 없는 전체 발음의 수가 아니다. 기존 글자를 여러 개 출력하는
경우와 단어 전체의 문맥은 위 집계에 포함하지 않았다.

## 문맥이 붙으면 달라지는 경우

아래는 실제 음성 인식 결과가 아니라 프로젝트 G2P에 구성한 문자열을 넣은 결과다.

| 입력 | 음운 규칙 적용 결과 | IPA |
|---|---|---|
| 밧 / 받 / 밭 | 받 | `p a t̚` |
| 밧아 | 바사 | `p a s a` |
| 받아 | 바다 | `p a t a` |
| 밧이 | 바시 | `p a s i` |
| 받이 | 바지 | `p a tɕ i` |
| 밭이 | 바치 | `p a tɕʰ i` |

110종 각각에서 같은 IPA를 내는 기존 글자 중 **정렬 순서상 첫 후보 하나만**
골라 제한된 앞·뒤 음절을 붙였다. 540회 G2P 호출에서 선택한 110쌍 중 102쌍에
반례가 있었다. 나머지 8쌍도 그 시험에서 반례가 없었을 뿐 모든 문맥의 동일성을
입증한 것이 아니다. 특정 후보의 반례를 다른 모든 대체 후보의 실패로 일반화하지 않는다.

따라서 110종을 무조건 삭제·치환하거나 391개만 추가하면 끝이라고 정하지 않는다.
발음 기준으로 통합하려면 **실제 단어 전체의 IPA를 보존하는지** 확인해야 한다.

## 출력 항목과 학습 필요성은 별개

- 발음 채점만 목적이라면 같은 발음의 철자를 반드시 별도 출력으로 둘 필요는
  없다. 다만 모델이 실제 음성을 듣고 그 대체 표기를 선택하는지는 이번 검사로
  알 수 없다. 같은 IPA 대응표가 있다는 사실이 음향 학습을 대신하지는 않는다.
- 현재 학습 데이터 선별은 철자 기준이므로 누락 글자가 포함된 발화를 여전히
  제외한다. IPA 분석만으로 해당 음성이 학습에 포함되거나 모델이 개선되지 않는다.
  이번에 학습 라벨을 재작성하지 않았다.
- 각 음절의 단독 녹음이 없어도 문장 속 음성으로 학습할 수 있다. 기존 코퍼스에
  `놔`·`놔요` 단독 발화가 없다는 것은 제품 조건의 단어 단위 평가 자료가 부족하다는
  뜻이지 추가 학습 자체가 불가능하다는 뜻이 아니다.
- 기존 아동 파인튜닝 가중치를 이어받는 것과 원본 출력 목록을 고정하는 것은
  별개다. 원본과 같은 어휘는 필수 조건이 아니지만 새 모델과 글자표·전처리
  설정은 서로 맞아야 하고 웹·Unity에서 함께 검증해야 한다.

## 재개할 때 결정할 것

1. 목표가 정확한 철자 전사인지 발음 구별·채점인지 구분한다.

   확장·통합 범위를 정한다. 523/110/413/391을 그대로 학습 목록으로 쓰지 않는다.
3. 발음 통합을 택하면 단어 전체의 라벨과 G2P 후처리 계약을 함께 검토한다.
4. 학습 후 기존·신규 단어의 인식과 오확정을 평가하고, 모델·어휘를 짝지어
   내보낸 뒤 실제 Unity 추론까지 검증한다.
