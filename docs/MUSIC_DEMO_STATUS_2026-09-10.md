# 악기놀이 발표 임시 적용 현황 · 0.8.5

이 문서는 0.8.5의 검증 기록이다. [최신 0.8.6 적용·재검사 결과](MUSIC_TWO_SPEAKER_VALIDATION_2026-09-12.md)에서
북채·잡아 조정과 새 녹음 결과를 확인한다. 아래 오확정 수치는 변경된 두 단어와 1·4·8단계 재검사에서도 유지됐다.

2026-09-10 기준 최신 현황이다. 9/12 발표를 위한 체험과 실제 아동 녹음 재생에 사용할
12개 표현·9단계 프로필을 구현했다. 사용자는 아래 측정 결과와 남은 한계를 확인한 뒤
현재 상태의 문서 갱신과 Git 커밋을 요청했다. 현장 마이크·게임 빌드 검증은 별도다.

## 잡아의 유사 표현과 남은 실패

추가로 각 표현마다 화자를 분산해 30개씩 선정하고 오답으로 분류해 검사했다.

| 오답으로 분류한 발화 | 0.8.4 → 0.8.5 오확정 | 현재 비율 |
|---|---:|---:|
| 작아 | 0 → 0/30 | 0% |
| 서랍 | 0 → 0/30 | 0% |
| 잡지 | 0 → 0/30 | 0% |
| 접어 | 1 → 1/30 | 3.3% |
| 잡아먹… 포함 문장 | 21 → 21/30 | 70% |
| 잡아당… 포함 문장 | 25 → 25/30 | 83.3% |

긴 문장에서 ‘잡아’가 먼저 들어오면 뒤의 다른 동작이 나오기 전에 확정할 수 있다.
현재 비교 조건만으로 문장 끝까지의 의미를 판별하지는 않는다.
‘0.8.5에서 추가 오확정 없음’은 바로 전 버전과 비교한 변화량이며 기존 오확정의 해소를 뜻하지 않는다.
앞선 0.8.4 완화에서는 잡아·때려·연주해·내려놔의 일부 오확정이 늘었다.

사용자의 실제 잡아 녹음 5개는 기본 재생에서 0/5 → 4/5 통과했고 작아 녹음 2개는 모두 거절했다.
시작을 0/125/250/375ms 바꾼 재생에서는 잡아 15/20 통과, 작아 0/8 오확정이다.
독립 녹음 수는 7개다. 47번은 계속 실패하며 45번은 250ms 조건에서 실패한다.
자세한 모델 출력과 측정 과정은 [실제 잡아 녹음 검증](GRAB_REAL_VOICE_2026-09-10.md)에 있다.

## 구현과 표시 정책

- `shared/music_presentation.json`에 12단어의 임계값·연속 횟수·전체 발화 하한·경쟁 동작 마진을 둔다.
  흔들어는 1회, 나머지는 2회 확인한다. [설정과 패키지 API](../unity/Packages/com.domicube.phoneme-matching/Documentation~/music-presentation.md).
- 잡아·쳐·때려·연주해·내려놔에 등록된 악기 접두 표현을 처리한다. 접두 음소와 동작 음소가 겹치면 보완하지 않는다.
- 잡아·때려·연주해·내려놔에는 길이와 전체 단어 점수를 함께 검사하는 짧은 발화 조건이 있다.
- 0.8.5 잡아는 기존 조건 실패 시 같은 추론의 CTC 후보 점수를 추가 확인한다. 원래 인식 문구를 바꾸지 않고 현재 프레임의 근거와 연속 2회를 요구한다.
- 모델 혼동 또는 잡아 보조 판정에 의존한 차이는 발음 오류 안내에서 보류한다. 남은 지적이 없으면
  발표 화면에는 ‘발음에 문제 없어요.’를 표시한다. 원본 차이와 보류 사유는 기록에 남고 임상적인 발음 진단으로 사용하지 않는다.
- Unity 진단 로그에는 인식 문구·음소·음량·판정 이유·실효 임계값·연속 횟수와 음향 후보 점수가 들어간다.

## 검증 자료와 적용

오확정 표의 분자·분모 및 이전 버전 비교는 [개인 음성이 없는 집계 JSON](data/music-demo-0.8.5-validation.json)에 보관한다.
원본 오디오, 개별 아동 전사·경로, 모델 가중치, 임시 추론 캐시, tgz는 이 커밋에 포함하지 않는다.
자료는 조정에 사용한 보유 데이터이며 새 아동·성인·현장 마이크의 독립 평가 결과가 아니다.

0.8.5 배포 당시 전체 작업 트리에서 Python 621개, C# 216개가 통과했다.
별도 Unity 2022.3.62f2 + Sentis 1.2에 실제 tgz를 설치한 EditMode 검사 42개도 통과했다.
사용자 녹음 28개 시작 조건·139개 창의 원래 인식 문구와 확정 결과를 Python과 비교했다.
실제 게임 통합, 마이크 체험과 최종 빌드 점검은 이 패키지 검사와 구분한다.

이번 커밋에 포함할 파일만 별도 경로로 내보내 다시 검사한 결과는 **Python 550개·C# 216개 통과**다.
별도 모델 학습 실험 변경은 커밋에서 제외했으므로 앞선 전체 작업 트리의 621개와 검사 범위가 다르다.
새로 받은 소스에서도 검사할 수 있도록 [테스트 입력 준비 절차](../README.md#10-테스트)를 적고,
어휘 검사 테스트의 로컬 학습 폴더 의존성을 제거했다.

기존 프로젝트는 0.8.5 tgz를 프로젝트 안에 보관하고 패키지 의존성을 갱신한 뒤 인식기를 다시 준비한다.
`PronunciationSession`/`PronunciationListener`는 잡아의 보조 판정을 자동 연결한다.
직접 `StreamingMatcher.Push`를 호출하면 현재 추론의 `AcousticEvidence.Collect` 결과를 전달해야 한다.
모델 재다운로드·재학습은 필요 없다. 이전 0.8.4 tgz로 의존성을 되돌리면 이전 판정으로 복귀한다.

이번 문서 갱신과 커밋은 로컬 Git 기록이며 원격 push나 태그·릴리스 게시를 포함하지 않는다.
배포 검증에 사용한 바탕화면 0.8.5 tgz는 그대로 보관하고, 이 문서 갱신만으로 다시 포장하지 않는다.
