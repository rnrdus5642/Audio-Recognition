# 청취 후 원인 분석 — 2026-09-27

현재 상태·마이크 테스트·남은 문제: [작업 현황](CHILD_JAMO_STATUS.md).
후속 분석: [전체 자음·모음과 원인 단계별 검사](CHILD_JAMO_GLOBAL_CAUSES_2026-09-27.md).
검증 1,500개 전체 집계, 청취 27개 인코더 통제 실험, 원본/전처리/평가 기준의
구분을 완료했다. 아래는 그 이전의 진단·수정 기록이다.

사용자의 오류 검토 18개, 학습 라벨 확인 6개, 품질 문제 확인 4개를 기존 모델·음성에 연결했다.
디코딩, 모델 내부의 문맥 처리, 녹음 크기와 원본 여백을 분리해 검사했다.
원인 진단 후 확인된 데이터 결함 2개를 별도 학습 목록에 수정하고 전처리 검사를 보강했다.
이후 원래 인식 오류를 설명하는지 확인하기 위해 65개 원음에 길이·음향 조건 대조 실험을 했다.
기존 모델은 보존했다. 발음 비교 6쌍과 첫 비교 재학습을 완료했다. 후속 상태는 연결된 실험 문서를 따른다.

## 이 분석 시점의 결론

- **원본 전사를 실제 발음 정답으로 쓸 때의 불일치 근거가 추가됐다.** 새 학습 청취
  18개는 일치 13·다름 4·모호함 1이다. 다름 중 3개는 원본 전체 음성을 사용했고
  G2P도 문구를 바꾸지 않았다. 이 세 청취 불일치는 우리 자르기나 문자 변환 이전의
  음성·전사 쌍에서 나온 것으로 볼 근거가 있다. 사용자는 입력 글자가 정밀 발음
  표기가 아닐 수 있다고 밝혔으므로 새 자모 정답이나 발음 오류 수로 바꾸지 않았다.
  모델이 다름 4개 중 3개를 라벨대로 출력해, 전사 일치만으로 라벨을 검증할 수 없다는
  한계도 확인했다. 원래 직접 녹음 오류와의 인과 관계는 여전히 미확정이다.
  18개는 모두 완료됐으며 자세한 해석은 [라벨 재점검](CHILD_JAMO_LABEL_AUDIT_2026-09-27.md)을 따른다.
- **확인된 자료 결함 2개만으로 원래 인식 오류의 원인이 설명된 것은 아니다.**
  후속 실험에서 다른 화자의 `책` 22개는 여백을 줄인 뒤에도 모두 전사와 일치했고,
  그중 16개는 1.5초 미만이었다. 짧은 전체 길이만으로 오류를 설명하기는 어렵다.
- 음높이·속도를 바꾸면 직접 녹음의 `샙 → 책`, `나리 → 나비`, `귀어 가요 → 뛰어가요`
  출력 변화가 생겼다. 반대로 정상 인식도 틀어져, 음향 조건에 대한 민감성을 확인했다.
  **사용자는 새 비교 6쌍 모두 같은 발음으로 들린다고 확인했다.** 나이·기기·음높이 중
  어느 것이 실제 녹음에서 원인이었는지나, 일괄 음성 변환이 해결책인지는 확정하지 않는다.
- 새 발음 비교 6쌍(<http://127.0.0.1:8771/>)은 **완료**됐다. 원래 오류 3개는
  같은 발음을 유지한 변환에서 사람 청취와 일치하게 바뀌었고, 정상 인식 2개는 틀어졌다.
  `쌕` 1개는 변환 전후 모두 오답이며, 변환 후의 `책`을 개선으로 세지 않는다.
  같은 발음에 대한 모델의 불안정성은 확인했지만, 개선책의 효과는 아직 검증 중이다.
- 기존 학습에는 특징 마스킹은 있었지만 음높이·속도 변화 학습은 없었다.
  기존 모델에서 같은 음성을 같은 순서로 추가 학습하되 음향 변환만 다르게 하는
  **별도 비교 재학습**을 실행했다. 직접 녹음은 학습에 넣지 않으며 기존 서비스 모델도 보존한다.
- 첫 128회 비교에서는 일반·변형 검증 성능이 조금 바뀌었지만 원래 문제 사례는
  개선하지 못했다. 변환 학습 모델이 실제 `쌕`도 `책`으로 바꿔 채택 조건을 통과하지 못했다.
  이를 해결된 모델로 배포하지 않았다. 학습량을 늘린 후속 비교도 같은 부작용 기준으로 판단한다.
- **품질 확인 4개도 완료됐다. 학습 자료의 실제 결함 2개를 확정했다.**
  `작은 다람쥐`는 잘못된 발화 시간에 따라 자르면서 말소리가 빠졌고,
  `하늘에서 눈이 내렸어요`는 원본부터 문장 없이 배경 소음만 있었다.
  제공된 원본 라벨 JSON에도 같은 시간·문장 정보가 들어 있었다.
- **이 자료를 통과시킨 검사 결함도 확인했다.** 기존 감사는 `peak == 0`인 완전한
  무음만 배제하고, 숫자로 유효한 발화 시간이 실제 말소리와 맞는지는 검사하지 않았다.
  파일명·오프셋·PCM 해시는 올바르게 연결돼 있었다.
- 추가 `책`은 다른 사람 목소리가 섞였다는 답변으로 판정을 보류했다.
  추가 `놔요`는 사용자가 마지막을 `놔요`로 적었는데 모델은 `나요`를 내므로,
  이 부분의 모델 오류를 확인했다. 문장 앞부분도 다르게 적었으므로 전체를 새 정답으로 쓰지 않는다.
- 전체 **154,752개** 음성을 다시 읽어 해시를 검증하고 음향 조건을 점검했다.
  학습 150,253개 중 **검토 후보 52개**를 발견했다. 이는 확정 오류 수가 아니다.
  확인된 2개에 한해 구간 복원 1개·제외 1개를 별도 학습 목록에 적용했다.
  수정본은 **150,252개**이며 기존 학습·검증·테스트 목록과 모델은 보존했다.
  확정 불량 자료가 새 학습에 다시 들어오면 모델을 읽기 전에 차단한다.
- **추가 청취 6개가 모두 완료됐고 모두 `match`다.** 사람이 적은 말도 띄어쓰기를
  제외하면 학습 표기와 모두 같다. 이번 표본에서는 잘못된 학습 라벨의 근거가
  나오지 않았다. 전체 학습 라벨의 정확성을 보증하는 결과는 아니다.
- 청취에서 기대 발음에 동의한 **오류 사례 8개**는 모두 빔 서치(폭 50)로도 같은
  잘못된 문자열이 1위다. 그리디 디코더만 바꿔서 해결되는 사례로 보지 않는다.
- `나비 → 나리`는 **주변 무음에 대한 인코더의 attention이 자모 판정을 바꾸는 것**을
  통제 실험으로 확인했다. 음성 샘플과 음성 구간의 특징을 그대로 유지해도 바뀐다.
  원본 녹음의 앞뒤 0.2/0.5초를 복원하거나 음량을 12dB 낮춰도 `나비`가 나온다.
  입력 조건에 대한 민감성이 이 사례의 오류를 만드는 요인임을 확인했다.
- `뛰어가요 → 귀어 가요`도 위치 문맥과 attention을 분리하면 출력이 바뀐다.
  일부 내부 실험에서 `뛰어가요`가 나오지만, 일반 무음 추가에서는 계속 `귀어 가요`다.
  구현에 바로 적용할 수정으로 검증된 것은 아니다.
- `책 → 샙`은 원본 여백·음량·DC 조건에서는 `책`이 되지 않았다. `ㅊ`과 받침 `ㄱ`의 점수가
  최종 모델 출력에서 이미 낮다. 모델이 해당 소리를 잘못 구분하는 지점까지는
  확인했지만, 어떤 학습·발화·녹음 조건이 이 취약성을 만들었는지는 미확정이다.
  원본 여백 복원, 음량 변경, DC 제거로도 사람의 청취와 같아지지 않았다.
- 짧은 발화의 학습 분포 차이는 확인했다. 이것이 오류의 유일한 원인이라는
  인과 증거는 아직 없다. 확인한 학습 음성은 정상 인식하지만 새 녹음에서 실패하는
  점은 일반화 문제와 일치한다. **학습량 부족이나 라벨 오류를 단일 원인으로
  확정하거나, 원인 분석이 모두 끝났다고 판단하지 않는다.**

## 청취 답변 해석

기존 SQLite 답변은 수정하지 않았다. 사용자가 “전사와 모델 둘 다 맞을 때도
모델대로 들림을 골랐다”고 보충했으므로, `prediction` 5개는 전사 오류의 증거가 아니다.

- `expected` 11개 중 3개는 자모가 같은 대조군이다. 실제 불일치 분석 대상은 8개다.
- `prediction` 5개 중 1개는 띄어쓰기만 다른 대조군이다. 나머지 4개도 배타적인
  모델 정답으로 확정하지 않았다.
- `child1_17`의 사람이 들은 말은 `쌕`이다. 빔 서치가 `책`을 낸다고 해결로 세지 않는다.
- 다른 자유 입력 `나는 예쁜 장미꼬슬`은 철자와 발음 표기가 섞일 수 있으므로
  문장 전체를 강제 음성 정답으로 변환하거나 새 학습 라벨로 쓰지 않았다.

## 무음이 영향을 주는 단계

13개 직접 녹음에서 앞만 0.5초, 뒤만 0.5초, 양쪽 0.2/0.5/1초 무음을 넣었다.
원래 음성 샘플은 그대로다. `나비`는 앞만 0.5초면 복구되지만 뒤만 0.5초면
`날비`가 나온다. 길이만 맞추면 항상 좋아지는 현상은 아니다.

그중 오류 4개와 대조군 2개에서 특징 추출기 이후를 나눴다. 음성 구간 특징은
원본과 같게 고정하고, 무음이 위치 convolution과 attention 각각에 들어가는지를 바꿨다.
양쪽 0.5초에서는 고정하기 전 음성 특징도 원본과 비트 단위로 같다.

| 음성 | 둘 다 제외: 원본 대조 | 위치 문맥만 추가 | attention 문맥만 추가 | 둘 다 추가 |
|---|---|---|---|---|
| child1_09 | 나리 | 나리 | 나비 | 나비 |
| child1_17 | ㅐㄱ | 책 | 책 | 책 |
| child1_18 | 샙 | 카 | 해 | 캅 |
| child1_22 | 귀어 가요 | 뛰어가요 | 귀어 가요 | 귀어 가요 |
| child1_01 | 아빠 | 아빠 | 아빠 | 아빠 |
| child1_02 | 엄마 | 엄마 | 엄마 | 엄마 |

0.2/0.5/1초의 18조건에서 대조 출력을 확인했다. 내부 문맥을 전부 제외하면
원본 출력과 일치하고, 조작 없는 인코더 재실행은 실제 패딩 입력 계산과 일치한다.
1초 패딩에서는 특징 추출의 수치 차이(최대 약 8e-6)가 있어, 원본 특징으로 고정한
실험의 logit과 원래 패딩 logit에는 최대 약 0.006 차이가 있었다. 토큰 출력은 일치했다.

`나비`는 3개 길이 모두 attention 문맥만 넣으면 `나비`가 되고 위치 문맥만으로는
그렇지 않았다. `뛰어가요`는 0.5/1초의 위치 문맥만 넣을 때 `ㄸ`이 돌아왔다.
이는 **학습된 인코더의 문맥 의존성에 대한 증거**이며 attention 구현 자체의 버그라는 뜻은 아니다.
내부 조작은 다른 예에서 `엄마 → 엄네`도 만들므로 그대로 제품 수정으로 채택할 수 없다.

| 4 · 책상 밑에다 놔요 | `책쌍 믿엣스다 놔요` | 마지막 `놔요`에 대한 모델의 `나요` 출력 오류 확인; 앞부분 표기는 별도 미확정 |

4번의 `different` 선택을 마지막 단어도 틀린 라벨이라는 뜻으로 처리하지 않았다.
자유 입력의 마지막 `놔요`는 학습 라벨과 일치한다. 입력 전체를 G2P로 바꿔 새 학습
정답으로 쓰지도 않았다. 3번 역시 `책`이라는 단어를 언급했다는 이유로 사용자가
명시한 판정 보류를 뒤집지 않았다.

화면에는 모델 답을 보여주지 않고 먼저 듣도록 구성했다. 소리를 키운 버전은
클리핑이 없음을 확인했고 원본과 구분해 표시했다. 모호함/판단 어려움 선택이 있으며
어떤 답도 미리 선택하지 않는다. 4문항의 6개 재생 파일, 문항별 선택 검증, 저장과
새로고침 복원, 모바일 화면을 임시 DB에서 검사했다. 원래 6문항 화면도 재검사했다.

이 4개는 오류 후보를 골라 원인을 확인하는 표본이다. 여기서 발견한 문제의 비율을
전체 학습 자료의 오류율로 확대하지 않는다. 현재 이 묶음에서 추가 청취를 요구하는
미응답은 없다.

## 확인된 결함이 들어온 경로와 전체 영향 점검

### 원본 자료와 기존 검사 경로

4개 모두 제공된 라벨 tar의 JSON 원문을 찾아 `FileName`, `FileLength`, `SpeechStart`,
`SpeechEnd`, `LabelText`를 인덱스·학습 매니페스트와 대조했다. WAV tar의 실제 헤더에
적힌 파일명·크기와 payload 해시도 일치했다. 같은 이름의 라벨은 각 1개였으며,
4개 모두 원본 `QualityStatus`가 `Good`이었다.

따라서 확인된 두 결함은 인덱스 변환이나 카탈로그 오프셋이 잘못된 사례가 아니다.
**제공 자료의 발화 시간·음성/문장 불일치를 실제 소리로 검증하지 않은 채 학습에
사용한 것**이 직접 확인된 문제다.

- 자르기: `audio.span`은 숫자로 유효한 시작/끝에 0.25초 여유를 더한다. 해당 시간에
  라벨의 말소리가 실제로 들어 있는지는 확인하지 않는다.
- 감사: `manifest.audit`는 읽기 오류, 길이, 완전한 0 값 무음, CTC 길이 적합성,
  자르기 정책 일치, PCM 중복 등을 검사한다. 음성/라벨 내용의 일치는 검사하지 않는다.
- 배경 소음 사례의 최대 진폭은 약 **0.00711**이므로 `peak == 0` 조건에 걸리지 않았다.
  잘린 `작은 다람쥐` 구간의 최대 진폭도 약 **0.07828**이어서 통과했다.
- `작은 다람쥐`는 전체 파형 에너지의 약 **0.379%**만 학습 구간에 남았다.
  이 수치는 말소리 누락을 단독으로 판정한 기준이 아니라 사용자 청취를 보강하는 측정이다.

### 전체 154,752개 음성 재점검

학습 150,253개·검증 1,500개·테스트 2,999개 전부에서 원본 WAV와 잘린 PCM 해시를
재검증했다. 불일치나 읽기 실패는 **0개**다. 음향 점검은 원본·학습 구간의 RMS,
20ms 구간 최대 RMS, 잘린 뒤 남은 에너지 비율 등을 측정했다.

| 집합 | 전체 | 검토 후보 | 학습/평가 구간 RMS < -50dBFS | 강한 소리 대부분을 제외한 자르기 후보 |
|---|---:|---:|---:|---:|
| 학습 | 150,253 | 52 | 44 | 8 |
| 검증 | 1,500 | 1 | 1 | 0 |
| 테스트 | 2,999 | 6 | 6 | 0 |

조건은 중복될 수 있다. 짧은 입력에 긴 자모 정답이 붙은 조건도 별도로 표시했다.
학습의 1.5초 미만 37개 중 10개가 하나 이상의 조건에 걸렸다. 에너지는 말소리
검출기가 아니므로 이 숫자를 불량 음성 수로 해석하거나 후보를 자동 삭제하지 않는다.

후보 59개는 같은 모델로 다시 비교했다. 자르기 후보 8개 중 **7개는 원본 전체에서
라벨과 일치하지만, 학습 구간과 같은 길이·위치의 무음 대조 입력에서는 불일치**했다.
그중 사용자가 누락을 확인한 것은 현재 `작은 다람쥐` 1개다. 나머지 6개도 우선 검토할
강한 후보이지만 사람 확인 없이 확정하지 않는다.

반대로 작게 녹음된 검증 1개·테스트 6개는 **7개 모두 원래 입력에서도 라벨과
일치했다.** 학습 후보 중에도 작은 소리지만 일치하는 예가 있다. 따라서 `-50dBFS`
같은 단일 음량 기준으로 학습 자료를 제외하는 수정은 근거가 부족하다.

### 적용한 데이터 수정과 남은 인과 검증

`verified-training-repair-proposal.json`의 확인된 2개만 대상으로 수정본을 생성했다.

- `작은 다람쥐`: 사람이 확인한 원본 전체 2.88초를 사용하도록 시간 정보와 PCM
  식별자를 갱신했다. 실제 학습용 `data.collate`로 이 수정 행을 읽었을 때 원본 전체와 샘플
  단위로 같고, 자모 정답이 바뀌지 않는 것까지 검증했다.
- 말소리 없는 `하늘에서 눈이 내렸어요`: 해당 음성/라벨 쌍을 수정본에서 제외했다.

수정본은 `.venv/hubert-child-20260914/manifest-train-repaired-20260927.jsonl`이다.
SHA256은 `095ab47072b4f24b0624fe6afb9d26dc3a16982dd75e6af3b255f94ee201b892`이며,
같은 폴더의 `audit-train-repaired-20260927.json`이 원본 감사·청취 근거·수정 규칙·품질
보고서와 연결한다. 원본 학습 150,253개를 모두 다시 읽어 WAV/PCM 해시를 확인했다.
수정본의 나머지 **150,251개 행은 바이트 단위로 동일**하고, 화자·PCM의 평가 집합 중복도 없다.

`manifest.py audit`에도 확인된 수정 규칙을 적용하고 원본/학습 구간의 RMS·남은 에너지
비율 등을 기록하도록 보강했다. `peak == 0`만으로 지나치던 후보를 별도 보고서로 남긴다.
이 측정은 발화 검출기가 아니므로 작은 소리만으로 불량 판정을 내리지 않는다. 나머지
검토 후보 50개는 그대로 보존했고, 이전 전수 검사에서 확인된 미확정 후보와 일치한다.
`책`의 다른 목소리와 `놔요` 문장 앞부분도 보류 항목으로 남겼다.

새 학습은 `--train-split train-repaired-20260927`을 지정해 수정본을 선택한다. 확인된
잘못된 구간이나 소음 자료가 남은 새 학습은 인코더를 적재하기 전에 거부한다. 기존
체크포인트의 재개는 원래 데이터 계약을 유지하며 수정본으로 몰래 바뀌지 않는다.
실제 자료를 사용한 입력 로더·해시 검증과 관련 테스트 **39개**가 통과했다.

이번에 확정한 것은 **학습 자료 검증의 결함과 실제 모델의 판별 오류가 함께 존재한다**는
점이다. 이 두 행의 수정만으로 직접 녹음의 `책 → 샙`, `나비 → 나리` 등을 모두
해결할 수 있다는 뜻은 아니다. 모델 성능에 미친 영향을 측정하려면 기존 결과를 보존한
별도 학습 실험과 화자가 겹치지 않는 짧은 단어 평가가 필요하다. 현재 단계에서는
이 두 행의 데이터·전처리 수정과 검증을 완료한 시점에는 재학습을 시작하지 않았다.
이후 원래 인식 오류를 대상으로 진행한 비교 재학습은 아래 후속 조사와 연결된 실험 문서에 기록했다.

## 원래 인식 오류에 대한 후속 대조 실험

동일한 기존 체크포인트에서 **65개 원음**을 비교했다. 학습에 포함되지 않은 화자의
단독 단어 46개(`책` 22·`엄마` 24), 사람이 학습 표기를 확인한 6개, 직접 녹음 13개다.
직접 녹음 중 11개만 배타적인 사람 청취 정답이 있다. 여러 변환 결과를 서로 독립적인
표본으로 세거나, 가장 잘 나온 변환을 골라 새 정확도로 보고하지 않는다.

### 전체 길이와 주변 여백

20ms 구간의 RMS로 소리가 있는 구간을 추정하고, 앞뒤 0.16/0.32초 여유를 남겼다.
남긴 샘플은 바꾸지 않았다. 잘라낸 구간을 같은 위치의 0 값으로 대체해 원래 길이를
복원하는 대조도 했다. 이 경계는 사람이 확인한 발화 경계가 아니므로 자동 자르기
정책으로 채택하지 않는다.

| 원음 집합 | 원래 전사와 일치 | 여유 0.16초로 줄인 뒤 일치 | 줄인 뒤 1.5초 미만 |
|---|---:|---:|---:|
| 다른 화자의 책 22개 | 21 | 22 | 16 |
| 다른 화자의 엄마 24개 | 22 | 23 | 16 |
| 사람이 확인한 학습 음성 6개 | 6 | 6 | — |

다른 화자의 `책`에서는 원래 에너지의 최소 99.9705%를 유지했다. 사람이 확인한 학습
`책` 하나도 1.658초에서 0.62초로 줄였지만 여전히 `책`이다. 직접 녹음 `책 → 샙`은
양쪽 0.4초의 무음을 더하면 `캅`, 오른쪽 무음으로 2초를 맞추면 `캡`이다.
따라서 **전체 길이가 짧다는 사실만으로 오류를 설명할 수 없다.** 학습 분포 차이가
다른 음향 조건과 함께 영향을 주었을 가능성까지 배제하는 실험은 아니다.

### 음높이·속도 변경과 대조

길이를 유지한 음높이 변경(±2/±4 반음), 음높이를 유지하도록 설계된 속도 변경
(0.65/0.80/1.25배), 별도 리샘플러로 음높이와 속도를 함께 낮추는 변환을 비교했다.
각 변환의 이득 조절·PCM 해시·출력을 기록했다. 음높이 변경은 음색과 포먼트도 바꾸며,
변환 알고리즘 자체의 소리 왜곡 가능성도 있어 생물학적 음높이만 분리한 실험은 아니다.

- 원래 `샙`이던 `책`은 길이를 유지하고 2반음 낮추면 `책`이다. 별도 리샘플러로
  음높이·속도를 함께 낮춘 두 조건에서도 `책`이 됐지만, 같은 길이의 0 값 추가는 실패했다.
- `나비 → 나리`도 음높이·속도를 함께 낮추면 `나비`로 바뀐다.
- `뛰어가요 → 귀어 가요`는 속도 0.65배 조건에서 `뛰어가요`로 바뀐다.
- 정상 인식하던 학습 `예쁜 나비`는 길이를 유지하고 2반음 올리면 `예쁜 나리`가 됐다.
  다른 화자의 단어 46개는 원래 43개가 전사와 일치했으나, 길이 유지·2반음 내림에서는
  34개로 줄었다. **일괄 음높이 변경은 검증된 해결책이 아니다.**
- 사용자가 `쌕`으로 들은 음성도 변환 후 모델은 `책`이라고 한다. 전사와 같아졌다는
  이유로 이 결과를 실제 발음 인식의 개선으로 세지 않는다.

같은 변환 경로에서 변경량을 0으로 둔 대조는 65개 모두 원래 출력과 같았다.
위상 보코더와 별개인 리샘플러에서도 핵심 변화가 재현돼, 한 변환 구현에만 의존하는
관찰은 아니다. 다만 이것만으로 변환 후 자음·모음까지 보존됐다고 입증하지는 못한다.

### 원본 MP3의 샘플레이트 처리

두 원본 MP3는 모두 48kHz 스테레오다. 원래 헤더의 샘플레이트를 읽어 모노·16kHz로
다시 만들고 동일한 구간을 잘라 다른 리샘플러와 비교했다. 13개 중 12개 출력이 같았고,
`책 → 샙`, `쌕 → ㅐㄱ`, `뛰어가요 → 귀어 가요`도 유지됐다. `나리`는 `날비`로 바뀌어
여전히 사람 청취와 달랐다. 두 처리의 파형 상관계수는 모두 0.99992 이상이었다.
샘플레이트 단위 오류가 원래 오류를 만든다는 근거는 얻지 못했다. MP3 디코더 전체를
독립 구현으로 검증한 것은 아니며, 전처리 차이에 대한 모든 민감성을 배제하지 않는다.

### 새 발음 비교 6쌍과 다음 단계

<http://127.0.0.1:8771/>에서 A 원음과 B 변환음을 비교한다. 모델 출력은 공개 API와
화면에 넣지 않았다. 음높이·속도의 차이를 제외하고 자음·모음이 같은지 고르며,
다름·모호함·왜곡으로 판단 불가를 구분한다. 답은 별도 DB에 이력을 남겨 저장한다.

| 번호 | 기존 사람 청취 | 비교 조건 | 실제 재생 파일의 모델 출력 A → B |
|---|---|---|---|
| 1 | 책 | 음높이·속도 함께 내림 | 샙 → 책 |
| 2 | 나비 | 음높이·속도 함께 내림 | 나리 → 나비 |
| 3 | 뛰어가요 | 속도 0.65배 | 귀어 가요 → 뛰어가요 |
| 4 | 쌕 | 음높이·속도 함께 내림 | ㅐㄱ → 책 |
| 5 | 예쁜 나비 | 길이 유지·음높이 2반음 올림 | 예쁜 나비 → 예쁜 나리 |
