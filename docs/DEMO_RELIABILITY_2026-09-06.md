# 데모 신뢰도: 보정된 정확일치 1프레임 확정 (2026-09-06)

> 이 문서는 당시 설정과 검증의 기록입니다. 현재 정답표·0.8.5 설정·오확정률은 [최신 적용 현황](MUSIC_DEMO_STATUS_2026-09-10.md)을 참고하세요.

## 무엇을 바꿨나

확정 규칙에 예외를 하나 더했다. **보정으로 허용된 단어에 한해**, 한 프레임의
점수가 **정확히 1.0** 이면 그 프레임 하나로 확정한다. 점수 1.0 은 **그
프레임에서 채점에 쓰인 구간**(문맥 제한으로 최근 몇 음소만 남긴 부분)이
설정된 정답 음소열과 그대로 일치했다는 뜻이다. 인식기 전사 전체가 정답
하나뿐이었다는 뜻도, 음향 확신도 100% 라는 뜻도, 아이가 정확히 발음했다는
인증도 아니다. 0.9999 나 0.995 는 해당하지 않는다.

기존 **연속 2회** 규칙은 그대로다. 예외는 다음이 모두 참일 때만 켜진다.

- 그 단어가 보정에서 `allow_exact_single_frame` 을 받았고,
- `consecutive` 가 정확히 2이며,
- 지금 돌고 있는 설정이 **보정 스냅샷과 같을 때**.

스냅샷은 보정이 단어마다 `targets_child.json` 에 적어 둔 기록이다 — 어떤
매트릭스(`matrix_id`)에서, 어떤 스트리밍 프로파일(`skip_cost`·`coverage`·
`context_mult`)로, 어떤 임계값·음소열·표기의 단어를 쟀는지. 런타임은
**확정하려는 프레임마다** 지금 값과 그 기록을 대조하고, 하나라도 다르면
예외를 끈다. 자기 매트릭스가 스스로와 일치하는지 보는 것이 아니라,
**허가를 내준 그 설정과 같은지**를 본다. 그래서 프로파일이 유효한 다른
매트릭스로 바꿔도, 매처를 만든 뒤에 임계값이나 음소열을 고쳐도 예외는
상속되지 않는다.

매트릭스는 이름이 있어야 한다. 두 런타임이 이름을 얻는 방법은 원래
달랐다 — Python 은 JSON 에 `matrix_id` 가 없으면 **파일 이름**으로
대신하고(예전 동작, 이번에 건드리지 않았다), C# 은 JSON 문자열만 받으므로
파일 이름을 알 수 없어 `unknown` 이 된다. 그래서 아동 v2 JSON 세 벌에
`matrix_id` **한 줄만** 넣었다(비용·프로파일·주석·버전 불변). 이제 두
런타임 모두 파일이 스스로 밝힌 이름을 읽으므로 일반 경로에서 값이
같아지고, C# 의 `LoadMatrix(json)` 한 인자 호출도 신원 확인이 된다.
`matrix_id` 가 없는 예전 파일을 C# 으로 읽으면 `unknown` 이 되는데,
`unknown` 은 아무 매트릭스도 지목하지 않으므로 예외를 받지 못한다
(필요하면 `LoadMatrix(json, "ko_child_v2")` 로 직접 알려 준다).

`skip_cost` 나 커버리지를 손으로 바꾼 호출자는 보정된 조건 밖이므로 예외가
스스로 꺼진다. 플래그가 없는 데이터, 성인용 타깃, 카탈로그에 없는 입력 단어,
명시적 `consecutive` 1 또는 3 은 전부 예전 그대로다. 형식이 깨진 스냅샷
(필드 누락, 문자열로 적힌 숫자, `true`/`"false"` 같은 값)은 예외를 통과시키지
않고 조용히 꺼진다 — Python 과 C# 이 같은 파일을 같은 이유로 거절한다.

확정이 예외로 일어나면 보고되는 streak 은 **진짜 1** 이다. 한 프레임을 두 번
성공한 것처럼 표시하지 않는다.

## 왜 필요했나

짧은 발화는 정답 음소열이 나오는 프레임이 딱 하나뿐인 경우가 있다. 발화가
2.5초 창 **안에 그대로 남아 있어도** 창 안에서의 상대 위치가 바뀌면 모델의
전사·IPA·점수가 같다는 보장이 없기 때문이다(채점은 문맥 제한으로 오래된
앞부분을 잘라내기도 한다). 그래서 다음 hop 에서 점수가 무너지고 연속 2회를
영원히 못 채운다. 공개 대상 단어 **책** 이 이 모양으로 확인된 사례다.

## 어떻게 보정했나

`derive_thresholds.py --exact-single-frame` 이 **같은 오확정 예산(0.01,
10초당 이벤트율, 기준 발화 4,998건에서 단어당 최대 32건)** 으로 단어별 판단을
한다.

1. 평소대로 0.025 격자에서 일반 임계값을 구한다.
2. 정확히 1.0 프레임만으로도 이미 예산을 넘으면 → **플래그를 끄고** 일반
   임계값을 그대로 둔다. 와요가 여기 해당한다.
3. 아니면 일반 경로를 0.001 격자에서 **조여** 결합 규칙이 예산에 들어오는
   최소 임계값을 찾는다. 예산을 늘려서 통과시키는 일은 없다.

결과: **29단어 중 28단어**가 예외를 받았고, **와요만 제외**. 임계값은
**책 0.825 → 0.826** 한 건만 바뀌었다. 나머지 28개는 그대로다.

산출물에는 단어별 측정 오확정 건수·비율과 `feasible` 플래그가 함께 기록된다.
`build_targets` 는 `feasible: false` 인 정책을 거부한다 — 예산을 못 맞춘
폴백 값이 정상값인 척 배포되지 않도록.

## 쓰는 법

재생성 명령은 `python/tools/child_tuning/README.md` 에 있다. 웹 실시간
화면에서 아동 확정 정책을 그대로 쓰려면 모델·매트릭스·카탈로그를 **셋 다**
지정해야 한다(README 와 같은 명령).

```powershell
python -m python.tools.web_test --model python/tools/child_finetune/runs/child/best --matrix shared/confusion_matrices/ko_child_v2.json --targets shared/targets_child.json
```

`--matrix` 나 `--targets` 가 빠지면 정책이 상속되지 않는다 — `--targets`
만 주고 기본 매트릭스(ko_child_v1)로 두면 카탈로그가 다른 매트릭스용이라
스냅샷이 맞지 않는다. 카탈로그 단어는 출하된 임계값을 쓰고(임계값 표시에
"출하 설정"), 카탈로그에 없는 입력 단어는 어느 쪽이든 예외를 받지 않는다.
**이미 띄워 둔 UI 는 이 설정을 반영하지 않으므로 다시 시작해야 한다.**

**`--model` 은 자동으로 확인되지 않는다.** 런타임 가드가 대조하는 것은
매처의 매트릭스·스트리밍 프로파일과 단어의 임계값·음소열이지 **음향 모델의
신원이 아니다.** 인식기 해시를 확인하는 장치는 이번에 만들지 않았다. 따라서
`--matrix ko_child_v2` 와 `--targets targets_child.json` 을 준 채 모델만
다른 것(또는 기본값)을 쓰면 예외가 그대로 적용되지만, 그 보정은 아동
파인튜닝 모델에서 잰 값이므로 더 이상 측정된 값이 아니다. **모델을 맞추는
것은 호출자의 책임이다.** 다른 모델을 쓸 거라면 다시 보정하거나 플래그를
끄고, 위의 세 인자를 모두 준 조합만 검증된 구성으로 취급한다.

오디오 창·추론 설정도 이 스냅샷에 포함되지 않는다. 이번 재생 검사의 기본
조건은 16 kHz 모노, 2.5초 창, 0.5초 hop이다. 모델이나 이러한 입력 조건을
바꾸면 기존 보정 결과가 그대로 유효하다고 가정하지 말고 다시 확인해야 한다.

패키지 사용자는 **패키지 갱신과 새 아동용 JSON 두 개(`targets_child.json`,
`ko_child_v2.json`)가 모두** 필요하다. 이번에 매트릭스에도 `matrix_id` 가
들어갔으므로 예전 매트릭스 파일을 그대로 두면 `unknown` 으로 읽혀 예외가
켜지지 않는다. 설치기는 기존 사용자 JSON 을 일부러 보존하므로, Git URL
갱신만으로 데이터가 자동으로 덮어써지지는 않는다.
