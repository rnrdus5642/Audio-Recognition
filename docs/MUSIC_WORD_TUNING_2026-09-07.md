**횟수는 같은 발화를 연속해서 검사한 횟수다.** 아동에게 해당 횟수만큼 반복 발화를 요구하는 설정이 아니다. 점수 역시 실제 정답일 확률이 아니라 음소 거리로 계산한 유사도다.

부분 일치 임계값만 낮추면 긴 문장 안의 비슷한 소리가 통과했다. 그래서 전체 발음의 유사도도 함께 확인한다. 전체 비교에는 같은 동작의 표현을 참고할 수 있지만 다른 동작의 좋은 점수를 빌리지 않는다. `들어`는 다른 동작과의 점수 차이가 작은 경우를 허용하도록 `contrast_margin = 0.08`을 사용한다. 다른 단어의 마진은 0이다. `쳐요·놔요`는 짧은 단어에 “요”가 붙어 전체 길이가 늘어나는 경우를 비교 표현으로 반영했다. `들어요·놓아요·흔들어요·두드려요·때려요`도 판정 테스트를 통과한다. 활용형 검사는 음소 입력 검사이며 별도의 아동 음성 성공률은 아니다.

`실로폰`은 한 번만 높은 점수가 나오는 녹음을 살리기 위해 1회로 바꿨다. `북`은 1회로 바꾸면 짧은 유사음에 반응해서 3회로 설정했다. `쳐·두드려`는 유효한 발화가 기존 임계값 아래에 머무르는 문제를 조정했다. `흔들어`는 1회로 판정하되 0.95로 높여 `두드려` 합성 음성에 반응했던 사례를 막았다. `때려`를 0.56까지 낮추면 합성 음성 하나가 추가로 통과하지만 실제 `들어`도 잘못 통과해서 0.84를 채택했다.

웹의 단계 선택은 이 표를 그대로 사용한다. 매 단계에 12개 전체를 정답으로 넣으면 다른 동작도 정답이 되므로 반드시 해당 단계의 표현만 전달한다. Unity 마이크 테스트 창에서는 아동 모델을 지정하고 **악기놀이 발표용 (12단어)** 설정을 선택한다. `PronunciationListener`는 `targets_music_demo.json`과 `ko_child_v2.json`을 지정하고, 해당 단계의 정답을 `TargetWords`에 넣는다. 직접 세션 API를 호출할 때는 `PronunciationSession.Begin(정답목록)`을 사용한다.

이번 검사는 기존 아동 녹음 83개(아동 2명), Microsoft Heami 합성 음성 24개(12단어 × 2속도), 기존 비교 음성 4,998개를 사용했다. 아동·합성 음성 107개는 현재 아동 모델로 다시 인식하여 534개 구간을 얻었다. 모델, 음운 규칙, 음소 혼동 행렬, 창 크기, 검사 간격은 변경하지 않았다. 임계값 0.50~1.00을 0.005 간격으로, 연속 검사 1~3회, 전체 비교 조건과 동작 비교 여유를 비교했다. 커버리지 0.5/0.65/0.8과 건너뛰기 비용 0.005/0.02도 먼저 비교했으며, 최종적으로 기존 커버리지 0.8과 비용 0.005를 유지했다.

분모는 **녹음과 질문을 조합한 검사 건수**다. 같은 녹음이 여러 질문에 쓰이므로 독립적인 아동 수나 현장 성공률이 아니다. 정답의 활용형이나 해당 동작일 수 있는 문장은 오답 집계에서 제외했으며 정답 집계에 추가하지 않았다. 기존 설정은 등록된 단어의 아동 설정을 사용하고, 미등록 단어는 기존 웹 도구가 비교 음성으로 산정하던 임계값을 사용했다.

남은 문제는 다음과 같다.

- 실제 정답 녹음 중 `실로폰·들어·쳐·놔` 각 1개는 여전히 미확정이다. 다른 말에 가까운 음소로 인식되어 임계값만으로 복구하기 어렵다.
- `와`를 `놔`로 인정한 아동 녹음이 1개 있다. 두 발화의 인식 결과가 같아, 해당 정답을 살리는 설정에서는 오확정도 함께 남는다. ③·⑦ 두 단계에서 같은 사례를 세어 단계별 오확정은 2건이다.
- `실로폰채·놓아·탬버린·북채·때려`는 이번 자료에 정확히 해당하는 아동 녹음이 없다. 설정은 적용했지만 아동 음성 성능은 아직 미검증이다. 특히 `놓아·때려`는 합성 음성에서도 각 1개가 실패했다.
- 현장 마이크, 배경 악기 소리, 새 아동 발화까지 검증한 결과는 아니다. 파일 테스트는 도착한 음성으로 같은 판정 과정을 확인하는 용도다.

판정 코드 검증: Python 전체 550개, 변경 후 웹 관련 65개, .NET 180개가 통과했다. Unity 2022.3와 Unity 6의 Editor 검사는 각각 28개가 통과했다. 실제 인식 결과를 넣은 Python/C# 대조는 **2,247개 질문, 10,962개 검사 구간**에서 점수·정답·연속 횟수·차단 이유가 일치했다. 이는 판정 코드 대조이며 실제 Unity 마이크나 Sentis 음향 추론의 성공률을 뜻하지 않는다. 실행 중인 웹 서버에 실제 아동 정답 녹음 13개를 업로드한 검사에서도 **9/13**, 비교 판정과 차이 0건을 확인했다.

새 음성이 도착하면 웹에 업로드하거나 다음처럼 평가한다. CSV는 `file,text` 열을 사용하며 파일 경로는 CSV 폴더를 기준으로 읽는다.

```powershell
.\.venv-gpu\Scripts\python.exe -X utf8 -m python.tools.evaluate_music_demo --audio-csv recordings/evaluation.csv
```

비교 음성까지 재검사하려면 `--reference`를 추가한다. 결과는 기본적으로 `recordings/music_demo_report.json`에 저장한다. 아동별 원음이나 인식 문장은 보고서에 쓰지 않는다. 이번 실행의 상세 집계는 로컬 `.venv/music-tuning-0907/evaluation.json`에 있다.
