# 악기놀이 0.8.6 · 북채·잡아 조정과 재검사

새 두 사람의 정답 녹음 46개에서 기본 단계 통과가 **37/46 → 39/46**으로 개선됐다.
실패했던 북채 1개와 잡아 1개를 회복했고, 기존 성공이 실패하거나 다른 정답으로 바뀐 사례는 없었다.
기본 실패 7개는 남아 있다. 이 문서는 해당 자료로 값을 고른 뒤 재검사한 결과이며 새 화자 정확도는 아니다.

## 적용한 설정

| 항목 | 0.8.5 | 0.8.6 |
|---|---:|---:|
| 북채 일반 임계값 | 0.78 | 0.74 |
| 잡아 음향 보조 판정 최소 CTC 로그확률 | -11 | -14 |
| 잡아와 원래 인식 문구의 최대 로그확률 차이 | 9 | 13 |

프로필은 `music_demo_2026_09_12`다. 북채 전체 점수 하한 0.65, 잡아의 일반/짧은 발화 기준
0.97/0.85와 작아 비교 조건, 두 단어의 연속 2회는 유지한다. 나머지 10개 정답 설정과 모델,
발음 안내 코드는 변경하지 않았다. 음향 보조 판정으로 확정한 경우의 표시도 ‘발음에 문제 없어요.’다.

설정 원본 `shared/music_presentation.json`에서 Python과 Unity의 네 정답 카탈로그를 재생성했다.
단계별 후보는 기존 12단어·9단계 표를 그대로 사용한다.

## 정답 녹음 결과

각 녹음을 시작 지연 0/125/250/375ms로 검사했다. 기본 결과는 0ms 조건이다.
2.5초 입력 창, 0.5초 간격, 파일 종료 후 hop 정렬 및 1초 무음을 사용하는 실제 웹 재생 경로다.
원본·분할 WAV와 음량은 바꾸지 않았고 정답 라벨을 인식 모델에 전달하지 않았다.

| 측정 | 0.8.5 | 0.8.6 |
|---|---:|---:|
| 기본 단계 통과 | 37/46 · 80.4% | 39/46 · 84.8% |
| 라벨과 같은 표현으로 기본 확정 | 36/46 | 38/46 |
| 네 시작 조건 모두 통과한 녹음 | 29/46 | 31/46 |
| 전체 시작 조건의 단계 통과 | 133/184 · 72.3% | 142/184 · 77.2% |
| 잡아 기본 / 전체 시작 조건 | 5/6 · 18/24 | 6/6 · 23/24 |
| 북채 기본 / 전체 시작 조건 | 1/2 · 4/8 | 2/2 · 8/8 |

화자 1의 기본 통과는 17/23→18/23, 화자 2는 20/23→21/23이다.
놓아를 내려놔로 확정한 기본 녹음 1개는 같은 단계의 허용 정답이므로 단계 통과에 포함된다.
잡아에서 남은 1/24 실패는 기본 재생에서는 성공하는 녹음의 375ms 조건이다.

기본 실패는 들어 2개, 놔 2개, 내려놔 2개, 놓아 1개다.
들어는 전사 삽입·치환과 전체/경쟁 동작 조건, 놓아는 누로 축약된 전사,
내려놔는 내려/내려아와 내려와의 경쟁 때문에 막힌다. 현재 모델 출력 사전에 놔 음절이 없다.
이 단어의 임계값을 크게 낮추는 실험은 다른 명령의 오확정을 늘려 이번 버전에 넣지 않았다.

## 오답 자료와 이전 사용자 녹음

기존 모델 출력과 해당 프레임의 음향 증거를 이전/새 설정에 각각 재생했다.
다음 묶음은 독립 전체 표본으로 합산하지 않는다. 정답이나 관련 표현을 제외하므로 분모도 다르다.

작아·서랍·잡지 각 30개는 0/30, 접어는 1/30, 잡아먹…은 21/30, 잡아당…은 25/30으로 유지됐다.
긴 문장의 앞부분에서 먼저 잡아로 확정하는 기존 문제는 남는다.
이전 사용자 잡아 5개×4시점은 15/20→16/20, 작아 2개×4시점은 0/8 오확정이다.
추가 오확정 0건은 이번 비교 자료에서의 변화량이며 현장 오확정률 0%라는 뜻이 아니다.

## 추가 오정답률 검사 · 같은 날 별도 실행

0.8.6 설정과 패키지를 유지하고 0.8.5와 다시 비교했다. 기존 비정답 자료의 9단계 전체와
북채·잡아 단독 검사에서 추가 오정답과 사라진 오정답은 각각 0건이었다. 기존 표의 비율도 유지됐다.

새 녹음 46개는 각 단어가 허용 정답이 아닌 단계에 넣어 교차 검사했다.
원래 정답 단계에서 일찍 확정된 뒤의 구간까지 포함해 1,100개 입력 창을 새로 추론했다.

| 교차 검사 조건 | 0.8.5 | 0.8.6 | 증가 |
|---|---:|---:|---:|
| 기본 시작 시점 · 녹음×오답 단계 | 6/308 · 1.95% | 6/308 · 1.95% | 0건 · 0%p |
| 네 시작 시점 · 녹음×오답 단계×시점 | 18/1,232 · 1.46% | 18/1,232 · 1.46% | 0건 · 0%p |

1,232개는 독립 녹음 수가 아니라 같은 46개의 반복 조건이다. 이 비율을 실사용 전체 오류 확률로
해석하지 않는다. 각 조건에서 오정답이 생겼는지 비교했으므로 새 오류와 사라진 오류가 상쇄된 결과도 아니다.

기존 오정답은 3개 녹음에서 관찰됐다. 내려놔를 내려로 인식한 뒤 때려로 확정하는 두 녹음,
잡아 발화의 앞부분 자를 쳐로 먼저 확정하는 한 녹음이다. 2·5·9단계에서 반복된 18건이며
이전 버전도 동일했다. 기본 시점에서는 이 중 2개 녹음이 3개 단계에서 반복된 6건이다.

실제 0.8.6 tgz를 설치한 별도 Unity 2022.3 + Sentis 1.2에서도 교차 검사 통합 테스트 1개가
통과했다. 실제 추론 1,100회, PCM 해시 확인 1,103회, Session 프레임 14,734개를 처리했다.
1,232조건×이전/현재의 2,464개 결과에서 확정 여부·단어·시점이 Python과 일치했고,
원래 전사·음소 차이는 0건이었다. 현장 마이크·게임 빌드 검증을 추가한 것은 아니다.

[추가 검사 집계](data/music-demo-0.8.6-false-accept-audit.json)에 단계별 분자·분모를 기록했다.
