# 잡아 실제 녹음 보완 · 로컬 0.8.5

[전체 9단계·12단어의 최신 적용 현황과 오확정률](MUSIC_DEMO_STATUS_2026-09-10.md)을 함께 참고한다.

사용자가 제공한 ‘잡아’ 녹음 44~48번과 ‘작아’ 녹음 50~51번을 사용했다.
원본 m4a는 변경하지 않았고, 분석용 16kHz 모노 복사본은 Git에서 제외되는
`.venv/grab-real-0910`에 보관했다. 합성 음성에 맞춰 값을 선택하지 않았다.

## 원인과 변경

0.8.4에서 잡아 5개가 모두 실패했다. 실제 모델 출력은 접어/작아/작하/저하/서랍/저랍
등이었다. 특히 잡아와 작아가 동일한 음소열로 인식되는 경우에는 기존 음소 점수와
연속 횟수만으로 두 발화를 구분할 수 없다.

잡아에만 `acoustic_keyword_policy`를 추가했다. 일반 규칙이 실패할 때 같은 추론에서
얻은 CTC 출력으로 잡아·원래 인식 문구·작아의 전체 시퀀스 로그확률을 계산한다.
모델 추론을 추가 실행하거나, 정답 글자로 인식 결과를 덮어쓰거나, 녹음을 참조해
목소리를 외우는 방식은 아니다. 일반 음소 기준 0.97/짧은 발화 기준 0.85는 유지한다.

| 보조 조건 | 값 |
|---|---:|
| 최소 음소 유사도 | 0.65 |
| 인식 음소 수 | 3~6 |
| 잡아의 최소 CTC 로그확률 | -11 |
| 원래 인식 문구 대비 최대 로그확률 차이 | 9 |
| 작아 대비 최대 로그확률 차이 | 6 |
| 연속 확인 | 2회 유지 |

CTC 로그확률은 정답률이나 임상적인 발음 평가 점수가 아니다. 다른 동작과의 비교 검사도
거쳐야 하며, 해당 프레임의 음향 근거가 없으면 기존 방식으로 판단한다.
다른 11개 단어 설정, 9단계 정답 목록과 아동 모델 파일은 변경하지 않았다.

보조 판정에 의존해 정답을 확정한 경우 원래의 음소 차이는 기록하되 발음 오류 안내는
보류한다. 내부 사유는 `acoustic_keyword_recovery`, 발표 화면 문구는 기존 요청대로
‘발음에 문제 없어요.’다. 진단 JSON에는 원래 인식 문구와 CTC 점수가 남는다.

## 비교 발화와 남은 문제

| 자료 | 측정 항목 | 0.8.4 → 0.8.5 |
|---|---|---:|
| 잡아가 포함된 기존 아동 발화 77개 | 정답 확정 | 68 → 68 |
| 기존 아동의 다른 발화 698개 | 오확정 | 14 → 14 |
| 기준 자료 4,995개 | 오확정 | 1 → 1 |
| 추가 작아/서랍/잡지 발화 각 30개 | 오확정 | 각 0 → 0 |
| 추가 접어 발화 30개 | 오확정 | 1 → 1 |
| 추가 잡아먹 포함 문장 30개 | 오확정 | 21 → 21 |
| 추가 잡아당 포함 문장 30개 | 오확정 | 25 → 25 |

추가 오확정은 관찰되지 않았지만 기존 오확정은 남아 있다. 특히 긴 문장 안의 ‘잡아’가
먼저 확정되면 뒤의 ‘먹어/당겨’가 나오기 전에 청취가 끝나는 문제가 있다.
추가 비교 자료는 6개 표현마다 화자를 분산해 30개씩 선정했다. 이 자료들은 조정에
사용한 평가 자료이며 새 화자에 대한 독립 검증 성공률로 제시하면 안 된다.

기존 캐시 중 새 보조 판정의 음소 조건을 만족하는 프레임은 원본 음성에서 CTC 점수를
다시 계산했다. 그 외 프레임은 새 보조 판정 대상이 아니므로 기존 출력을 재사용했다.
추가 비교 음성 180개는 전체를 새로 추론했다. 총 2,482번 음향 추론을 실행했고,
기존 캐시에서 다시 추론한 음소열의 차이는 0건이었다.

## 검증과 배포

- Python 전체 테스트: 621개 통과.
- C# 런타임 테스트: 216개 통과. CTC 전 경로 열거와 forward 합산의 일치,
  현재 프레임 근거/연속 확인/기존 후보 비교/원문 보존/발음 안내를 검사했다.
- 실제 0.8.5 tgz를 설치한 별도 Unity 2022.3.62f2 + Sentis 1.2:
  EditMode 42개 통과. 사용자 음성 28개 시작 조건, 총 139개 창을 실제 아동 ONNX로
  처리했고 잡아 단독 및 1·4·8단계 결과가 Python과 일치했다.
- 같은 음성 창의 Python/Unity 원래 인식 문구 차이는 0건. 잡아 CTC 로그확률의
  최대 수치 차이는 약 0.0102이며 확정 결과는 동일했다.
- 웹의 실제 파일 재생 경로에서도 44/45/46/48 통과, 47 실패, 50/51 거절을 확인했다.
