# 기존 데이터셋의 라벨 오류 가설 재점검

원래 오류는 여전히 미해결이다. 음향 변환을 추가한 비교 학습이 원래 사례를 고치지
못했다는 사실은 라벨 오류를 입증하지도, 배제하지도 않는다. 새 재학습을 시작하지 않았다.

현재 학습 정답은 `Transcription.LabelText`를 정규화하고 프로젝트의 발음 규칙을 적용한
뒤 자모로 분해한 결과다. 실제 아동의 발음을 독립적으로 청취해 기록한 정답은 아니다.
제공 전사에 실제 발음 차이가 빠졌거나, 발음 규칙이 해당 발화에 맞지 않으면 이 경로는
그 차이를 발견하지 못한다. 반면 제공 전사가 모두 제시 문구라고 단정할 근거도 없다.

예를 들어 실제로 `쌕`이라고 말한 학습 음성에 `책`이라는 전사가 있다면, 현재 경로는
그 음성의 정답을 `ㅊㅐㄱ`으로 만든다. **이는 조건부 설명이며, 기존 학습 자료에서
그 특정 조합을 새로 발견했다는 뜻이 아니다.** 직접 녹음의 `쌕` 사례는 학습 자료가 아니다.

## 청취 18개 분석 완료

사용자는 2026-09-27 16:26:52~16:31:43 KST에 18개를 모두 저장했다. 답변 18개·이력
18개를 읽기 전용으로 확인하고, 각 답의 binding, 재생 WAV, 학습 PCM, 원본 WAV,
원본 라벨 JSON을 대조했다. 원본 JSON은 해당 18개 모두 1개씩 발견됐고, 전사·시간·파일
연결은 일치했다. 추가로 모델을 학습하지 않았으며 기존 모델로 진단 추론만 수행했다.

사용자는 입력한 글자가 실제 발음의 정확한 표기가 아닐 수 있다고 명시했다. 따라서
선택한 판단과 자유 입력을 함께 보존하되, 자유 입력을 자모 정답으로 만들거나 글자
편집 거리로 발음 오류 수를 계산하지 않았다. 자유 입력에 G2P를 적용하지도 않았다.

| 선택 | 문항 수 | 해석 |
|---|---:|---|
| 일치 | 13 | 사용자의 일치 판단. 모든 음소에 대한 정밀 전사 인증은 아님 |
| 다름 | 4 | 청취 불일치 보고. 정확한 대체 발음열은 아직 없음 |
| 모호함 | 1 | 원문 라벨 정오를 확정하지 않음 |

일치 중 14번은 `포짝폴짝 뛰어가요`, 17번은 `췍`이라고 적었다. 이를 추가 오류 2개로
세지 않았다. 동시에 이 두 글자열을 정확한 실제 발음이라고 정하거나, 원래 라벨을
음소 수준의 확정 정답으로 인증하지도 않는다. 11번의 `채액`도 모호함 선택을 유지한다.
`나비 덕분에…`, `쌀을 나눠가져요`, `수박을 마니 삽니다` 등의 일반 철자와 띄어쓰기
차이는 새로운 발음 불일치로 세지 않는다.

### 다름을 선택한 4개와 발생 경로

아래 자유 입력은 **사용자가 들은 차이를 설명한 참고 메모**다. 정밀 발음 표기나
새 학습 라벨이 아니다.

| 번호 | 원본 전사와 학습 발음 표기 | 사용자 참고 메모 | 경로 점검 |
|---|---|---|---|
| 1 | 도화지를 준비해요 | 조아지지 준비해요 | 원본 전체 PCM 그대로, G2P로 문구 변화 없음 |
| 4 | 아무리 뀌어도 단 방귀로구나 | 아우리 기어버 단 단이더부나 | 원본 전체 PCM 그대로, G2P로 문구 변화 없음 |
| 10 | 폴짝폴짝 뛰어가요 | 푸푸풀짝 뛰어가요 | 원본 전사는 같음. 시작 0.66초가 제외된 학습 구간이므로 잘림 기여는 미확정 |
| 13 | 폴짝폴짝 뛰어가요 | 포짝포짝 뛰어가요 | 원본 전체 PCM 그대로, G2P로 문구 변화 없음 |

**1·4·13번은 사용자가 보고한 불일치가 원본 음성·전사 쌍에서 이미 존재한다는 근거가
있다.** 우리 자르기나 G2P의 문자 변경으로 이 세 차이가 생긴 것으로 설명할 수 없다.
이는 원본 전사를 실제 발음 정답으로 사용할 때의 적합성 문제다. 데이터 공급자의
전사 지침 위반을 확정하거나 정확한 음소 대치·탈락을 판정한 결과는 아니다.

10번의 전체 원음도 모델은 같은 문구를 냈지만, 사람이 전체 원음을 들은 것은 아니다.
모델 출력만으로 잘림 원인을 배제하지 않는다. 10·13번의 메모는 `뛰어가요` 앞부분의
차이를 나타내므로, 이것으로 `뛰어가요`의 `ㄸ` 라벨이 잘못됐다고 해석하지 않는다.

### 모델과 라벨의 일치가 놓치는 문제

같은 원래 체크포인트로 답변 저장 후 18개를 계산했다. 사용자 자유 입력이나 전사를
추론 입력으로 주지 않았다. ‘다름’ 4개 중 **1·10·13번은 모델이 학습 라벨대로 출력**했다.
4번은 `아무리 뀌어도 단 방귀거구나`였다. 이미 학습한 음성에 대한 결과이며 일반화
성능이나 발음 정확도가 아니다.

이 결과는 모델의 전사 일치 여부만으로 학습 라벨의 발음 정확성을 검사하면 이런 청취
불일치 사례를 놓칠 수 있음을 보여준다. 원본 전사를 따르는 학습이 실제 발음 차이를
보존하지 못할 가능성을 뒷받침하지만, 원래 직접 녹음의 `책 → 샙`, `나비 → 나리` 등의
원인이 이 사례들이었다는 인과 증거는 아니다. 표본 수가 작아 전체 빈도도 추정하지 않는다.

추가된 4개는 정확한 실제 발음이 미확정인 라벨 검토 사례로 보관했다. 새 라벨을
자동 생성하거나 학습 목록에서 자동 제외하지 않았다. 앞서 수정한 결함 2개와 별도로
집계한다. 이 18개까지 청취 완료 문항은 총 52개였다. 이후 괄호 후보 8개와 추가
검수 상황은 [선택형 청취 분석](CHILD_JAMO_INLINE_REVIEW_2026-09-27.md)에 기록한다.

## 확인한 범위

수정된 학습 목록 150,252행의 전사·표면 발음·자모 ID를 재계산했다. 전체 인덱스
2,765,817행에서 이 150,252개 파일의 전사도 대조했다.

- 인덱스 전사 정규화 결과와 학습 전사의 불일치 0개, 누락 0개.
- 현재 발음 규칙의 재계산 결과와 저장된 표면 발음·자모 ID의 불일치 0개.
- `책/쌕`, `책/샙`, `나비/나리`, `뛰어가요/귀어 가요`, `놔요/나요`는 각각 다른 자모열이다.
- 앞서 청취한 품질 사례 4개의 원본 JSON을 보관된 오프셋에서 다시 읽고 해시를 확인했다.
  이 4개에서 `ErrorTagged`와 `GrammaticalError`는 `N/A`다. 전수 필드 조사 결과는 아니다.
- 괄호·대괄호 전사는 해석하지 않고 제외한다. 기존 코드의
  `읽었어요(일저더요)` 같은 예도 실제 실현형 라벨로 쓰이지 않는다.
  전체 인덱스에서 괄호 포함 15,263행, 대괄호 포함 26행을 셌지만 이는 선택된 학습 자료의
  오류 수나 발음 오류 수가 아니다. 제외가 현재 오류를 일으켰는지는 미확정이다.

이 검사는 **문자 처리의 일관성**을 검사한다. 같은 발음 규칙을 재실행하므로 그 규칙의
언어학적 정확성이나 실제 음성과의 일치를 입증하지 않는다. 정상적인 연음 등도 글자를
바꾸므로 전사와 표면 발음이 다른 행 수를 오류 수로 세지 않는다.

앞서 확인된 원본 결함은 소음뿐인 음성에 문장이 연결된 사례와 발화 시간 오류 사례다.
각각 제외·전체 구간 복원을 완료했다. 학습 발음 확인 6개가 모두 일치했다는 결과로
다른 발음 차이가 있는 자료나 전체 라벨의 정확성을 판단하지 않는다.

## 새 청취 18개

화면: <http://127.0.0.1:8772/>

현재 수정 학습 목록에서 기존에 청취한 파일을 제외하고, 모델의 출력·정오 여부를
사용하지 않은 고정 해시 순서로 골랐다. 전체 묶음의 화자는 18명으로 서로 다르다.

| 묶음 | 개수 | 선택 방식 |
|---|---:|---|
| 일반 학습 표본 | 6 | 남은 학습 목록의 고정 해시 순서 |
| 책 | 4 | 단독 `책` 발화의 고정 해시 순서 |
| 나비 | 4 | 전사에 정확한 공백 단어 `나비`가 있는 발화 |
| 뛰어가요 | 4 | 전사에 정확한 공백 단어 `뛰어가요`가 있는 발화 |

화자가 겹치면 다음 파일로 넘어가고, 화면 순서는 별도 해시로 섞었다. 일반 표본도
작고 단어 표본도 의도적으로 포함했으므로 전체 오류율을 추정하지 않는다. 모두 맞아도
라벨 오류 가설 전체를 기각할 수 없다. 첫 단계는 실제 소리와 정답이 다른 사례를 찾고,
그 차이가 원본 전사·발음 변환·구간 자르기 중 어디에서 생겼는지 추적하는 것이다.

선택을 먼저 저장한 뒤 원본 WAV 및 학습 구간의 해시를 검증했다. 재생 파일을 다시 읽은
PCM도 실제 학습 구간과 샘플 단위로 같다. 음성 길이 합계는 78.63초다. 비교 문구는
처음에는 가리고, 원본 전사와 학습 발음 표기를 함께 공개한다. 모델 출력은 계산하거나
보여주지 않는다. 다름·모호함·말소리 없음·녹음 문제를 나눠 답할 수 있다.

사용자 답변은 새 DB에 저장한다. 기존 답변은 그대로 보관한다. 18개 실제 재생과 파일
해시, 참조 표시, 답변 저장·복원, 모호함/말소리 없음, 동시 수정 충돌, 모바일 표시를
임시 DB로 확인했다. 시험 답변은 사용자 DB에 넣지 않았다.

답변을 해석할 때 사용자가 적은 말을 발음 규칙으로 다시 고치거나 새 학습 라벨로
자동 채택하지 않는다. 띄어쓰기·일반 철자 차이와 실제 자음·모음 차이를 구분하고,
불명확한 사례는 그대로 보류한다.
