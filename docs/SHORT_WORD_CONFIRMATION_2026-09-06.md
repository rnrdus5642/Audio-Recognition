# 미해결 문제: 짧은 발화의 연속 2회 확정 누락 (2026-09-06)

> 이 문서는 당시 설정과 검증의 기록입니다. 현재 정답표·0.8.5 설정·오확정률은 [최신 적용 현황](MUSIC_DEMO_STATUS_2026-09-10.md)을 참고하세요.

**상태: 부분 해결 (2026-09-06).** 아래 진단은 그대로 유효하다. 이후 보정된
단어에 한해 **한 프레임이 정확히 1.0 이면 단독 확정**하는 예외를 넣었다
(`docs/DEMO_RELIABILITY_2026-09-06.md`). 문서화된 책 사례는 이 예외로
확정되지만, 정답 IPA 자체가 한 번도 나오지 않는 나머지 미확정은 그대로
남아 있다 — 인식 결과와 정답 표기가 어긋난 경우이고 이 변경으로 닫히지
않는다. 그것이 인식기 오류인지, G2P/정답 표기의 문제인지, 아이가 실제로
다르게 발음한 것인지는 아직 구분하지 않았다.
모델·기본 연속 확인 횟수(2)는 바꾸지 않았고, 임계값은 책 0.825→0.826
한 건만 바뀌었다.

아래 "남은 작업"은 이 예외를 넣기 전에 쓴 목록이다. 첫 항목은 완료 표시를
했고, 나머지는 지금도 유효한 남은 일이다.

## 문제와 영향

짧은 발화가 한 번은 임계값을 넘지만 다음 검사에서는 넘지 못해, **연속 2회**를
채우지 못하고 정답 확정에 실패한다. 같은 음성이 2.5초 창 안에 남아 있어도
창에서의 상대 위치가 바뀌면 모델의 전사·IPA·점수가 같다는 보장은 없다.
단어를 1초 이상 길게 말해야 한다는 규칙은 아니지만, 짧게 말해도 항상 두 번
통과한다는 보장 역시 없다.

- 이전 라벨 테스트와 같은 **0.5초 입력**에서는 수정 전후 결과가 같았다.
  한 번만 통과하는 `책`의 미확정도 수정 전부터 있었다.
- **더 짧거나 불규칙한 입력을 가정한 실험**에서는 기존에 확정되던 `책`이
  수정 후 미확정으로 바뀌었다. 따라서 "기존 문제이므로 추가 악화는 없다"고
  결론 내릴 수 없다.
- 반대로 수정 후에만 확정된 사례도 있다. 전체 통과 건수가 같더라도 개별
  단어의 손실과 개선이 상쇄될 수 있고, 더 자주 검사한다고 항상 유리하지 않다.

## 비교 조건

- 기존 라벨링 아동 음성 83클립: 정식 목표 단어 64건, 카탈로그 밖 임시 목표
  단어 19건을 따로 집계했다. 명시적 오답 질문 8건을 더해 총 91세션이다.
- 기존 파인튜닝 아동 모델 `python/tools/child_finetune/runs/child/best`
  (출력 폭 1205, 가중치 SHA-256 접두사 `ea5d9d9e`), `ko_child_v2`,
  `targets_child`의 동일 음소·임계값을 사용했다. 2번 작업의 미학습 1206 후보는
  사용하지 않았다.
- 정규화 16 kHz 모노 PCM, 창 40,000샘플(2.5초), 수정 후 hop 8,000샘플
  (0.5초), 연속 2회. 클립을 다음 hop 경계까지 무음으로 채운 뒤 1초 무음을
  덧붙였다. 입력 분할 방식마다 총 PCM은 같고 실제 확정 프레임에서 중단했다.
- 수정 전은 `5bdea0084f9828045c891ee38247038e22897aa1`의 웹 콜백,
  수정 후는 진단 당시 작업 트리의 `HopFramer` 적용 웹 콜백이다. 인식·채점
  설정은 같게 두고 실제 모델 결과를 비교했다. 바이트까지 같은 입력 창만
  인식 결과를 재사용했으며, 재사용도 별도의 논리적 채점 프레임으로 센다.
- 세션의 `done`만으로 성공을 세지 않았다. 실제 매처 확정과 확정 결과 객체를
  요구하고, 오류 종료는 실험 실패로 처리했다.

**아래 입력 분할은 실제 브라우저·Unity 전달 기록이 아니라 구성한 실험 조건이다.**
0.5초는 이전 라벨 테스트와 비교하기 위한 기준이다.

## 결과

| PCM 전달 간격 | 정식 목표 64건: 수정 전 → 후 | 임시 목표 19건: 수정 전 → 후 | 정식 목표의 판정 변화 |
|---|---|---|---|
| 0.5초 | 39 → 39 | 7 → 7 | 없음 |
| 0.25초 | 39 → 39 | 9 → 7 | `책` 통과 → 실패, `빵` 실패 → 통과 |
| 1초 | 39 → 39 | 6 → 7 | 없음 |
| 0.4초·0.6초 교대 | 40 → 39 | 7 → 7 | `책` 통과 → 실패 |

0.5초 조건에서는 91세션 모두 수정 전후 창 내용·프레임별 점수·연속 횟수·확정
결과·오디오 기준 시각이 같았다. 정식 목표 64건 중 24건은 한 번도 통과하지
못했고, 1건(`책`)은 한 번만 통과해 미확정이었다. 수정 후에는 네 입력 분할
모두 같은 프레임 결과를 냈다. 즉 **입력 분할 독립성은 확인됐지만, 짧은 발화의
확정 성공까지 보장된 것은 아니다.**

명시적 오답 8건은 모든 조건에서 수정 전후 각각 1건 오확정이었다. 이 작은
표본으로 전체 오확정률이 유지되거나 안전하다고 일반화하지 않는다.

## `책` 추가 확인: 기다림과 시작 위치

위 비교와 별도로 동일한 `책` 클립 하나의 시작 위치와 후행 무음을 바꿨다.
0.5초 입력으로 수정 전후를 모두 비교했으며, 이 결과를 위 64건 집계에 섞지 않았다.

- 후행 무음을 1초에서 **3초로 늘려도** 시작 위치가 같으면 한 번만 통과해
  미확정이었다.
- 클립 앞에 **0.125초 무음**을 넣으면 두 번 연속 통과해 확정됐다.
- 시작 위치 이동 0초·0.25초·0.375초에서는 미확정이었다.
- 4개 시작 위치 × 2개 후행 무음 길이 × 수정 전후 = 16회 비교에서, 같은
  조건의 수정 전후 결과는 모두 같았다.

이 클립에서는 단순히 오래 기다리는 것보다 **창 안에서 발화가 놓이는 위치에
따른 인식 변동**이 원인으로 보인다. 단일 클립의 후속 분석이므로 다른 단어나
카탈로그 밖 미통과 사례까지 같은 원인이라고 확정하지 않는다.

## Unity 관련 확인 범위

실제 패키지의 `AudioWindowBuffer(2.5f, 0.5f)`와
`PronunciationSession.TryPush`에 동일 PCM을 넣었다. 입력 창 해시가 일치할
때만 실제 Python 모델에서 얻은 전사·IPA를 반환하는 캐시 인식기를 사용했다.

**72세션(정식 목표 64 + 명시적 오답 8) × 4개 입력 분할 = 288회,
1,092프레임에서 불일치 0건**이다. 창 해시·종료 샘플·점수·연속 횟수·통과·
프레임별 확정·세션 확정을 비교했다. Python의 종료 샘플은 관찰자가 계산한
기대값이며, C#의 `FrameScore.EndSampleIndex`는 버퍼가 보고한 값이다.

이는 **C# 창 생성·채점 재생 검증**이다. 실제 Unity 마이크, Sentis 음향 추론,
독립 C# G2P, 48 kHz 등의 리샘플링 경로를 이번에 실행한 것은 아니다.
웹과 Unity 전체 추론 경로의 새 실기기 검증으로 해석하면 안 된다.

## 남은 작업

- (완료) 샘플 기준 hop의 입력 분할 독립성을 유지하면서 짧은 발화의 확정
  방식을 보완할 후보를 비교했다. 채택한 것은 보정된 단어 한정 정확일치
  1프레임 예외이며, 임계값 완화 후보는 보류 데이터에서 검출 이득이 없어
  기각했다(`docs/DEMO_RELIABILITY_2026-09-06.md`).
- 위 성공 → 실패 사례와 반대 방향의 사례를 함께 회귀 테스트에 포함한다.
  입력 분할뿐 아니라 발화 시작 위치·후행 무음을 구분해 비교한다.
- (갱신) 한 번의 통과만으로 확정하거나 임계값을 낮추는 것을 그대로 적용하지는
  않았다. 이번 예외는 단어별로 같은 오확정 예산 안에서 보정했고, 보류
  데이터의 오확정 증가(+6 이벤트)까지 함께 재서 공개했다. 앞으로의 후보에도
  같은 기준(정답 검출과 오답·무음·잡음 오확정을 함께 검증)을 적용한다.
- 실제 웹 입력과 Unity 마이크·추론에서도 검증하기 전까지 이 이슈를 닫지 않는다.
