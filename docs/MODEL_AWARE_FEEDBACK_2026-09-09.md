# 모델 혼동을 고려한 발음 안내 · 2026-09-09

> 이 문서는 당시 설정과 검증의 기록입니다. 현재 정답표·0.8.5 설정·오확정률은 [최신 적용 현황](MUSIC_DEMO_STATUS_2026-09-10.md)을 참고하세요.

0.8.3 표시 변경: 발표 요청에 따라 내부 보류 후 남는 지적이 없으면 화면에는
`발음에 문제 없어요.`라고 표시한다. 웹의 보류 음절은 초록색 `문제 없음`이며,
다른 음절의 남은 지적은 유지한다. 아래 보류 기준·내부 상태·원본 기록은 그대로다.

정답 `놔`가 `와`로 인식됐을 때 ㄴ 누락을 아동의 발음 오류로 지적하던 경로를 수정했다.
정답 판정과 발음 안내는 각각 처리하며, 인식 차이의 원인이 불확실하면 발음 안내를 보류한다.

## 원인과 변경

웹의 기존 모델 오류표는 697개 발화의 비교 자료로, ㄴ 누락 항목이 없었다.
기존 코드는 오류표에 없는 차이를 보류하지 않았다. Unity의 한글 설명에는 오류표 기반
검토 과정 자체가 없어 원본 인식 차이를 그대로 안내했다.

이제 웹·Unity가 같은 보류 규칙을 사용한다.

- 오류표가 없거나 모델 ID가 다르면 보류한다.
- 기록이 없는 차이, 관측 2회 미만, 측정되지 않은 삽입을 보류한다.
- 2회 이상 관측됐으며 비율이 2% 이상인 모델 혼동을 보류한다.
- 여러 차이가 하나의 음절 설명으로 묶였을 때 일부가 보류 대상이면 그 설명 전체를 보류한다.
- 다른 음절의 설명은 해당 조건을 만족하면 유지한다.

이 비율은 참고 자료의 차이 빈도이며 개별 발화가 틀렸을 확률이 아니다. 기록이 없다는 것은
모델 오류가 없다는 증거가 아니며, 보류 또한 아동이 정확히 발음했다는 확정이 아니다.

## Unity와 결과 계약

0.8.1 패키지에 아동 모델 오류표를 포함했다. Listener·발표 세션·테스트 창에 연결하며,
기본 악기놀이 화면도 검토된 한글 안내를 표시한다.

결과 계약은 `schema_version: 3`이다.

- `KoreanFeedback`: 화면에 표시할 안내. 보류된 차이의 지적 문장은 제외한다.
- `RawKoreanFeedback`: 보류 전 원본 설명. 개발·디버깅용이다.
- `FeedbackReview`: 보류 상태·정렬 인덱스·이유·관측 수와 비율이다.
- 원본 `Alignment`, 점수, 임계값, 확정 횟수, 이벤트 순서는 유지한다.

`KoreanFeedback.Items`가 비었어도 `Summary`와 보류 상태를 확인해야 한다.
직접 구성하는 세션은 `feedbackErrors`로 모델에 맞는 오류표를 전달할 수 있다.
표가 없으면 원본 비교를 지우지 않고 안내만 보류한다.
[연결 예제와 필드 설명](../unity/Packages/com.domicube.phoneme-matching/Documentation~/pronunciation-feedback.md)

## 실제 파일 재생 결과

기존 파일 전체를 실행 중인 웹 서버의 아동 모델에 전달했다. 새 음성을 생성하거나
단어 부분을 추가로 잘라내지 않았다.

| 파일 종류 | 인식 IPA | 기존 점수 | 수정 후 점수 | 확정 | 발음 안내 |
|---|---|---:|---:|---|---|
| 기존 합성 음성 `놔` | w a | 0.7222222222 | 0.7222222222 | 2회 확인 후 정답 | ㄴ 누락 자료 부족으로 보류 |
| 기존 아동 녹음 `놔` | n a | 0.7222222222 | 0.7222222222 | 2회 확인 후 정답 | w 누락의 모델 혼동 자료에 따라 보류 |

두 사례 모두 기본 화면의 지적 문장이 0개이고, 원본 누락 1개는 확인용 데이터에 남는다.
이는 발음 안내 수정의 재현 검사이며 아동 인식률 전체를 새로 측정한 결과는 아니다.
