**같은 발음은 같은 결과로 평가한다.**

| 발화 목표와 인식 결과 | 발음 기준 평가 |
|---|---|
| 단독 `샅 → 삳` | 같은 발음이므로 철자 차이로 감점하지 않음 |
| `잡아 → 자바` | 같은 발음으로 실현되므로 철자 차이로 감점하지 않음 |
| `놔 → 와`, `잡아 → 작아` | 소리가 달라진 결과로 집계. 모델의 오인식인지 실제 발음 차이인지는 음성을 기준으로 확인 |

비교 단위는 단어 전체 또는 해당 발화 문맥에서 실현된 발음이다. 발음 변환 규칙으로 같은 소리가 된 경우를 정답과 동일하게 취급한다. 따라서 아래의 겹받침·종성 토큰 누락은 철자 토큰화 범위에 대한 검사 결과이며, 그 자체로 실사용 발음 인식의 실패나 탈락 근거가 아니다. 기존 토큰으로 해당 소리를 표현할 수 있는지와 실제 음성에서 그 소리를 제대로 출력하는지를 확인해야 한다.

**자모 출력과 실제 발음 출력은 학습 목표가 다르다.**

| 방식 | 출력 예시 또는 의미 | 이번 문제에 주는 이점 | 남는 한계 |
|---|---|---|---|
| 현재 음절 ASR | 완성형 글자 `놔` 하나를 선택 | 현재 아동 학습 결과와 기존 구현 활용 | 글자가 출력 목록에 없으면 그 철자 그대로 출력 불가 |
| 철자 기반 자모 ASR | `ㄴ`과 `ㅘ`를 출력하고 `놔`로 조합 | 필요한 자모가 있으면 새 음절을 조합 가능 | 올바른 음성을 정확히 듣는지는 별개이며 실제 발음 오류를 충실히 전사한다고 보장할 수 없음 |
| 음소 인식 | 발음 기호의 연속을 출력 | 문자 전사 후 발음으로 바꾸는 단계를 줄이고 소리 비교에 연결 가능 | 모델 오인식은 여전히 존재하고 실제 발음에 대한 검증 자료 필요 |

앞선 826개는 빠진 **철자** 수다. 현재 발음 변환기의 단독 음절 비교에서는 204개가 기존 출력 음절과 같은 결과를 낸다. 이것이 문맥에서도 같은 소리이거나 ASR이 실제로 대체 글자를 출력한다는 뜻은 아니다. 이 수치만으로 모델 교체 여부를 판단하지 않는다. [발음 중복 분석](data/vocabulary-pronunciation-groups-2026-09-13.json)

한국어 K-Wav2vec 2.0 연구에서는 자모 출력이 드문 음절과 목록 밖 음절 문제를 완화했지만, 데이터가 많은 조건에서 음절 출력이 더 좋은 경우도 있었다. 자모가 항상 더 정확하다는 근거로 읽으면 안 된다. [Interspeech 2022 원문](https://www.isca-archive.org/interspeech_2022/kim22e_interspeech.pdf)

Kkonjeong은 모델 카드 본문에 Apache 2.0을 명시한다. Miniijune V2·semi-supervised V2, SLPLab phone-mfa, raniczan은 저장소 메타데이터에 Apache-2.0을 표시한다. 모델 가중치의 공개 여부와 우리 환경의 성능 검증 여부는 별개다.

**공개 파일을 직접 검사하며 확인한 사항**

1. Kkonjeong: 원본 vocab은 자모 51개와 특수 기호를 포함해 54항목이고, 추가 토큰을 합친 출력 크기는 56이다. 현대 한글 전체를 호환 자모로 분해했을 때 필요한 기호 누락이 없었다. 악기놀이 12개 표현도 unknown 없이 토큰화됐다. 이는 **표현 가능성 검사**이며 정답 인식 실험이 아니다.
2. Miniijune V2: 기본 어휘와 추가 토큰 파일에 출력 ID 41의 글자 매핑이 없다. 이번 Transformers에서는 해당 ID를 `[UNK]`로 디코딩했고 다른 선언된 토큰 번호는 일치했다. 로딩 불가능한 모델이라는 뜻은 아니다. 별도 C# 디코더에서 같은 동작을 정의해야 한다. `eos_token_id=44`도 출력 크기 44의 범위 밖이라 로더 경고가 발생했으며, 이를 CTC 음성 인식 실패로 단정하지 않는다.
3. Miniijune의 [semi-supervised_V2](https://huggingface.co/Miniijune/wav2vec2-xls-r-300m-Korean-children-pronunciation-jamo-based-semi-supervised_V2)는 공개 가중치가 있고 추가 토큰을 포함한 출력 ID 매핑 누락은 없었다. V2와 모두 기본 자모 40개이며 `ㄳ·ㄵ·ㄶ·ㄺ·ㄻ·ㄼ·ㄽ·ㄾ·ㄿ·ㅀ·ㅄ`의 단일 토큰은 없다. 이를 두 자음으로 풀었는지, 발음대로 바꿨는지는 공개 카드로 확인되지 않는다. 실제 발음 형태를 학습했다면 겹받침 철자 토큰은 필요하지 않을 수 있다. 두 모델 모두 악기놀이 12개 표현의 기본 자모를 포함하지만, 학습 라벨의 규칙과 실음성 결과를 확인해야 한다.
4. raniczan: 설명에는 약 105토큰으로 적혀 있지만 실제 기본 vocab은 410항목, 출력 크기는 412다. NFD로 검사하면 종성 `ㄳ·ㄽ·ㄾ·ㄿ·ㅋ`에 해당하는 5개 기호가 없다. 이는 철자 토큰화의 누락이며 해당 발음 자체를 표현할 수 없다는 증거가 아니다. 현재 과제에서 낮은 우선순위인 주된 이유는 합성 한영 혼합 음성 중심의 학습 조건과 한국 아동 실음성 평가 근거 부족이다.
5. SLPLab phone-mfa: `N`, `oA` 등 소리 기호를 출력한다. 이를 한글 문자로 간주하거나 현재 한글 정리 함수에 그대로 통과시키면 안 된다. 모델 카드의 MFA–IPA 대응을 검토하여 현재 프로젝트의 세분화 수준으로 변환해야 한다.

공개 성능 표기는 Kkonjeong CER 7.3%, Miniijune V2 CER 7.87%, semi-supervised V2 CER 11.60%, SLPLab phone-mfa PER 3.88%다. **CER의 계산 단위와 평가 자료가 같지 않고 PER은 다른 지표이므로 이 숫자들로 우열을 정하지 않는다.** Miniijune의 제목만으로 보유 아동 자료와 잘 맞는다고 판단하지 않는다.

SLPLab phone-mfa와 같은 학습·평가 조건을 기술한 한국어 음소 연구는 전체 PER 3.88% 외에 일부 이중모음의 인식 오류도 보고한다. 전체 수치가 좋아도 개별 소리의 오류 안내가 정확한지는 따로 확인해야 한다. 우리 시스템에서는 철자 CER보다 발음 단위 오류율과 정상 발음에 대한 잘못된 지적 비율을 우선 본다. [한국어 음소 인식 연구 원문](https://www.eksss.org/archive/view_article?pid=pss-15-4-101)

**한국 아동에 직접 맞춘 1B 연구와 공개 학습 기반을 구분한다.**

Ahn 등의 연구는 XLS-R 1B를 한국 아동 137명의 73개 단어 자료로 파인튜닝했다. 95명·1.56시간을 학습에, 30명·0.54시간을 평가에 사용했고, 실제 들린 발음을 전사한 뒤 40개 자모로 분해했다. 보고된 PER은 10.25%이며 단어 정답률 89.75%를 뜻하지 않는다. 정답 철자와 다른 실제 발음을 학습 목표로 삼았다는 점이 현재 목적과 가깝다. [논문 원문](https://arxiv.org/html/2403.08187v1)

다만 이번 확인에서 그 연구의 **파인튜닝된 체크포인트 다운로드 경로는 찾지 못했다.** 논문에서 연결하는 [facebook/wav2vec2-xls-r-1b](https://huggingface.co/facebook/wav2vec2-xls-r-1b)는 후속 학습이 필요한 사전학습 모델이다. 아동 파인튜닝을 전제로 하는 현재 범위에서는 이 공개 1B 모델도 학습 기반 후보로 검토할 수 있다. 한국어 자모·음소 출력층과 라벨 체계를 구성해 학습해야 하며, 논문의 완성 체크포인트를 재현한 것으로 간주하지 않는다. 이 특정 사전학습 모델에 새 한국어 출력층을 학습하는 실험은 하지 않았다. 후속 실측에는 이미 한국어 출력층이나 어댑터가 있는 1B급 체크포인트 6개를 포함했다. 이 중 한 개는 토큰표 불일치로 출력 번호열만 보존하고 소리 오류율 집계에서 제외했다.

**현재 프로젝트에서 필요한 수정**

| 작업 | 이유 |
|---|---|

| Python·C# 양쪽에 출력 종류별 디코딩 추가 | 현재 두 구현 모두 완성형 한글과 공백만 남긴다. 자모를 그대로 넣으면 내용이 사라짐 |

**현재 아동 모델의 음성 처리부를 재사용하는 선택지도 있다.**

외부 모델로 교체하는 방법 외에, 현재 아동 모델의 음성 처리 가중치를 초기값으로 쓰고 자모 CTC 출력층과 토크나이저를 새로 만들어 학습할 수 있다. 기존 아동 적응을 출발점으로 활용할 수 있지만 자모 출력 학습이 필요하고 기존 음절 출력층은 그대로 쓸 수 없다. 경량화 효과도 자동으로 생기지 않는다. 현재 데이터 준비 코드와 학습 절차도 함께 수정해야 한다. Wav2Vec2의 CTC 모델은 음성 표현 위에 문자 출력을 위한 선형층을 두는 구조다. [Transformers 공식 문서](https://huggingface.co/docs/transformers/model_doc/wav2vec2)

**아동 파인튜닝을 거친 모델 선정 순서**

1. 완료: 기존 원본을 포함한 공개 64개 체크포인트의 실제 음성 추론을 비교했다. 성인 문장 208개, Zeroth 457개, 보유 단어 53개에 잡음·창 길이·임계값·연속 조건 검사를 적용했다. Miniijune V2를 우선 후보로 정하고 student-47 V5와 SLPLab 한국어 음소를 대조군으로 남긴다. 아동 학습 후 순위를 확정한 것은 아니다.
2. 후보 선정과 라벨 준비: 필요한 소리 구분을 출력 체계가 보존하는지, 우리 아동 전사를 그 체계에 일관되게 변환할 수 있는지 확인한다. 단어 인식용 기준 발음 라벨과 실제 발음 오류를 보존한 라벨을 구분한다. 완성형 글자 수보다 학습 목적·출력 체계·가중치 품질을 본다.
3. 아동 파인튜닝: 같은 아동 학습 자료와 화자 분할, 비교 가능한 학습 예산으로 후보를 적응시킨다. 후보별 설정은 검증 자료에서 선택하며, 평가 녹음으로 반복 조정하지 않는다. 현재 아동 모델은 기존 성능 기준으로 유지한다. 현재 아동 음성 처리부에 새 자모 출력층을 학습하는 경로도 비교 후보가 될 수 있다.
4. 학습 후 비교: 소리 단위 오류, 미지원 음절이 포함된 단어, `놔/와`·`잡아/작아`, 기존에 잘 되던 단어를 함께 평가한다. 모델별 정답 임계값은 검증 자료에서 정하고, 화자가 분리된 평가 자료에서 같은 허용 오확정률일 때의 정답 통과율을 비교한다. 정상 발음의 잘못된 지적과 실제 발음 차이의 누락은 실제 발음 라벨로 따로 측정한다.
5. 배포 검증: 학습 후 개선이 확인된 후보를 ONNX로 변환해 Unity의 지연 시간·메모리·Python과의 출력 일치를 점검한다. 최종 교체 판단은 아동 파인튜닝과 이 평가를 마친 뒤 한다.

실사용 판단에는 실제 소리를 목표로 학습한 방식과 검증 자료를 우선한다. 현재 음절 모델도 같은 발음을 안정적으로 보존한다면 비교 대상에서 제외하지 않는다. 자모·음소 출력이라는 이름이나 모든 철자를 표현할 수 있다는 사실만으로 교체를 결정하지 않는다. 기존 정답 문장을 기계적으로 발음 기호로 바꾼 라벨에는 아동이 실제로 낸 발음 차이가 자동으로 반영되지 않으므로, 발음 안내 성능을 위한 학습·평가에서는 실제 발음 라벨을 구분해야 한다.
