# 악기놀이 정답표 변경 적용 · 2026-09-09

> 이 문서는 당시 설정과 검증의 기록입니다. 현재 정답표·0.8.5 설정·오확정률은 [최신 적용 현황](MUSIC_DEMO_STATUS_2026-09-10.md)을 참고하세요.

웹과 Unity 0.8.2는 아래 9단계·12개 표현을 사용한다. 설정 원본은
[music_presentation.json](../shared/music_presentation.json), 프로필은 `music_demo_2026_09_09`이다.
기존 9월 7일 문서는 당시 정답표의 실험 기록이다.

| 단계 | 동작 | 기본 정답 표현 |
|---|---|---|
| ① | 실로폰채 들기 | 실로폰채 / 들어 / 잡아 |
| ② | 실로폰 치기 | 쳐 / 때려 / 연주해 |
| ③ | 실로폰채 놓기 | 놓아 / 놔 / 내려놔 |
| ④ | 탬버린 들기 | 들어 / 잡아 |
| ⑤ | 탬버린 치기 | 쳐 / 때려 |
| ⑥ | 탬버린 흔들기 | 흔들어 |
| ⑦ | 탬버린 놓기 | 놓아 / 놔 / 내려놔 |
| ⑧ | 북채 들기 | 북채 / 들어 / 잡아 |
| ⑨ | 북 두드리기 | 두드려 / 때려 / 쳐 |

`잡아·연주해·내려놔`를 추가하고 `실로폰·탬버린·북`을 정답 후보에서 제외했다.
삭제한 세 표현은 비슷한 정답으로 잘못 확정되지 않도록 비교 대상으로만 남겼다.
`내려와·잡아먹어`도 다른 동작의 비교 표현이다. 정답 결과로 반환하지 않는다.

## 내려놔를 따로 등록한 이유

이전 정책에서 표준 `내려놔` 음소를 `놔`에 비교하면 부분 점수는 약 0.992지만
전체 발화 점수는 0.26이다. `놔`의 하한 0.85를 충족하지 못해 정답 처리되지 않는다.
`놓아 / 놔` 두 후보를 함께 주어도 같았다. 따라서 `내려놔`를 명시적으로 유지했다.
정답 단어를 단순 문자열 포함 검사로 판정하는 구조가 아니므로, 뒷부분이 같다고 자동 허용되지 않는다.

## 새 단어의 임시 설정

| 표현 | 임계값 | 연속 확인 | 전체 점수 하한 | 다른 동작 비교 마진 |
|---|---:|---:|---:|---:|
| 잡아 | 0.97 | 3 | 0.00 | 0.50 |
| 연주해 | 0.90 | 2 | 0.00 | 0.20 |
| 내려놔 | 0.90 | 2 | 0.65 | 0.00 |

문장 속 `잡아·연주해`를 정확하게 인식해도 앞말과 뒷말 때문에 전체 점수가 낮았다.
이 두 표현은 전체 점수 하한을 해제하고 동작 비교 마진을 조정했다. 부분 발음 점수와
연속 확인 조건은 유지한다. `잡아`는 높은 점수를 3개 창에서 확인하도록 해,
2회 설정에서 통과할 뻔한 다른 발화를 차단했다. 횟수는 같은 발화의 연속 검사 횟수이며,
아동에게 단어를 3번 말하도록 요구하지 않는다.

신규 단어의 임계값 0.45~1.00, 확인 1~3회, 전체 점수 하한 0~0.85를 비교했다.
`잡아·연주해`는 동작 비교 마진 0~0.50도 확인했다. 설정에 사용하는 자료와 평가 자료가
겹치므로 아래 수치는 독립적인 새 아동의 정확도가 아니다.

기존에 유지된 9개 단어는 임계값·확인 횟수·전체 점수 하한·마진을 변경하지 않았다.
모델, 혼동 행렬, 2.5초 창, 0.5초 간격 및 모델 불확실성에 따른 발음 안내 보류 정책도 같다.
새 비교 표현과 단계별 후보 조합은 변경되었으므로 가능한 모든 입력의 판정이 같다는 뜻은 아니다.

## 실제 오디오 결과와 한계

아동 녹음은 발화 앞뒤를 자르지 않고 전체 파일을 사용했다. `잡아` 12개와 `연주해` 10개는
문장 안에 해당 표현이 들어간 자료이고, `내려놔` 1개는 기존 아동의 `내려놔요` 녹음이다.
모든 파일을 실제 아동 모델로 인식한 뒤 같은 스트리밍 판정으로 검사했다.

| 새 표현 | 아동 전체 발화 정답 처리 | 합성 단일 단어 정답 처리 | 기존 비교 음성 오확정 |
|---|---:|---:|---:|
| 잡아 | 12/12 | 0/2 | 0/4,995 |
| 연주해 | 9/10 | 1/2 | 0/4,996 |
| 내려놔 | 0/1 | 2/2 | 0/4,950 |

합성 음성은 Microsoft Heami의 보통·느린 속도로 만든 별도 테스트 자료이며 실제 아동이 아니다.
`잡아` 합성 단어는 모델이 `서랍`에 가까운 소리로, 느린 `연주해`는 `연심해`에 가까운 소리로
인식했다. `내려놔요` 아동 녹음도 `매어나요`에 가까운 소리로 인식했다. 이 차이만으로 실제
아동의 발음 오류라고 결론 내릴 수 없다. 이들을 모두 통과시키려고 기준을 크게 낮추지 않았다.
특히 아동 `내려놔요`를 살리는 낮은 임계값은 비교 음성에서 오확정을 만들었다.

기존 아동 83개·기존 합성 24개 중 유지된 9개 단어의 판정은 이전 프로필과 차이가 없었다.
새 3개 단어는 이 기존 자료와 다른 신규 발화에서도 오확정이 없었다.

| 현재 12개 단어 각각을 검사한 자료 | 정답 처리 | 다른 발화 오확정 |
|---|---:|---:|
| 기존 아동 녹음 | 6/9 | 1/946 |
| 기존 합성 녹음 | 16/18 | 0/252 |
| 이번 아동 전체 발화 | 21/23 | 0/251 |
| 이번 합성 단어 | 3/6 | 0/62 |
| 기존 비교 음성 4,998개 | 해당 없음 | 11/59,595 |

현재 9단계 조합의 기존 비교 음성 오확정은 29/44,295건이다. 같은 오디오를 여러 단어와
단계에 재사용한 검사 건수이므로 분모는 아동 수가 아니다. 해당 동작일 수 있는 활용형·문장은
오답 집계에서 제외했다. 단어 구성이 바뀌었으므로 이전 12단어의 총계와 직접 성공률을 비교하지 않는다.
기존 아동 `와`가 `놔`로 통과하는 1개 사례는 남아 있고 ③·⑦에서 각각 세어진다.

발표에서 미리 등록한 오디오를 정답으로 외우는 기능은 추가하지 않았다. 현장 마이크·새 아동의
발화는 위 자료와 다를 수 있으며, 특히 신규 단어의 단일 발화 인식 한계가 남아 있다.

## 적용과 확인

웹은 [발표 화면](http://127.0.0.1:7861)을 새로고침하고 단계를 다시 선택한다.
다시 시작하려면 `./start_music_demo.ps1`을 실행한다. 빌드 도구는 발표 카탈로그 4곳을 동기화한다.

Unity는 바탕화면의 `com.domicube.phoneme-matching-0.8.2.tgz`를 설치한다.
기존 `MusicPresentation.ApplyTo(listener, stage)`·`ListenStage(stage)` 사용자는 새 표가 적용된다.
자체 코드에 정답 배열을 직접 적었다면 위 표로 수정하거나 `GetStage(stage).Answers`로 연결한다.
아동 ONNX 모델은 재사용한다. 발음 안내는 기존처럼 `KoreanFeedback`을 표시한다.

단계별 정답·오답 경계, 제외한 악기 이름, 비슷한 다른 동작, 존댓말, 웹 파일 재생 및
`놔 → 와` 발음 안내 보류를 함께 검사한다. 원음 경로를 포함하는 실험 자료는 추적하지 않는
로컬 `.venv/music-update-0909/`에 있으며, 같은 폴더의 `evaluation.json`은 원음 경로를 제외한 집계다.

최종 검사에서 Python 전체 580개, C# 187개, Unity 2022.3의 패키지 설치·Editor 검사 41개가
통과했다. Unity 검사는 배포 파일과 바이트가 같은 `.tgz`를 설치해 기존 아동 모델 재사용,
실제 모델 준비, 새 단계 연결 및 발음 안내 보류를 확인했다. 실행 중인 웹의 9단계 목록도
확인했고, 아동·합성 전체 파일 6개를 업로드한 결과가 로컬 판정과 모두 일치했다.
