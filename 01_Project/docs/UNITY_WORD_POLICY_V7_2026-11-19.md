# 웹 v7 정답 후처리 통합 — 2026-11-19

공통 패키지 `0.9.2-preview.2`을 악기·공룡·화분에 동일하게 적용했다. 웹의 여러 후보 중 한 단어를 정답으로 판정하는 방식이다. 모델, 문서 공용 설치 위치, 단계별 정답 목록과 게임 진행 방식은 그대로 사용한다.

## 바뀐 판정

- 인식 결과에 남은 현대 초·중·종성을 IPA에 포함한다. 미완성 단어를 통째로 버리거나 자모를 지워서 점수를 올리지 않는다.
- 3음절 이상 비동작 명사는 같은 음절 수의 어근 뒤에 허용된 조사가 있을 때 어근을 비교한다. `실로펀 체를` → 비교용 `실로펀체` → 후보 `실로폰채`, 점수0.95다. `ᅵᆯ로폰채를`은0.94다. 둘 다 기본0.85 기준에서 두 번 확인해야 확정된다.
- `책ᄉ`은 추가 자음 때문에0.80으로 기본 기준 미달이다. `사과주스`의 임의 내부 자르기, 다른 동작, 동음 후보 동점, 바로 뒤의 `아니`·`말고` 제한을 유지한다. 일반적인 의미/의도 판정 기능은 아니다.
- 원문은 보존하고 후보별 `MatchSuffix`·`UncomposedJamo` 진단만 추가한다. 기본0.85·2회 확인·2.5초 창·0.5초 간격과 음량 검사, 확인 이력의 만료 규칙은 유지한다.
- v4/v5 식별자가 남은 프로젝트 정답 JSON도 현재 v7 정책으로 읽는다. 기존 유니티 연결 API를 바꾸거나 정답 JSON을 다시 만들 필요가 없다.

## 사용과 배포

`Packages/manifest.json`과 `packages-lock.json`은 `com.domicube.phoneme-matching-0.9.2-preview.2.tgz`를 참조한다. 기존 `Tools > 오디오 정답 처리 기능 > 음성 테스트` 또는 게임에서 확인한다. 모델 파일은 이미 설치된 최종3에포크 파일을 재사용한다. 새 다운로드나 학습은 없다. 이미 배포한 EXE에는 자동 반영되지 않으므로 적용한 프로젝트에서 다시 빌드해야 한다.

웹의 두 단어 모두 확인하는 모드 및 문장/LLM 모드는 이번 범위가 아니다. 기존 지속 마이크 입력, 질문별 오디오 저장, 비동기 추론, DB·PNG와 이전 눈 깜빡임 변경은 보존했다.

## 검증

Unity2022.3.62f2에서 각 프로젝트 PlayMode 패키지58개와 EditMode 연동23개, 합계81개씩 통과했다. 세 프로젝트 총243개 실행 통과, 실패·건너뜀0이다. 정답 표현은 악기82·공룡76·화분41개를 현재 프로젝트 설정으로 확인했다. 연동 검사는 합성 PCM으로 마이크 수명주기·구간 저장을 검사하며 실제 장치 입력은 아니다.

웹 관련 Python검사63개·하위검사67개가 통과했다. 웹의 실제 `WordGames.frame`을 기준으로11,844개 사례·98,251회 판정,74개 자모 변환을 대조했다. 후보별 점수·비교 범위·거절 이유·선택 및 확정 결과가 일치한다(점수 오차1e-9 이내). 소수점 누적 차이로 사실상 동점인 낮은 점수의 진단 행 순서는 달라질 수 있으며, 후보별 값과 선택·확정 검사는 생략하지 않는다.

기존11,804개 재생 사례의 기존 통과3,536개가 유지됐고34개가 추가 통과했다. 이는 동일 ASR 텍스트 재생 결과이며 새로운 실녹음 정답률이 아니다. 첫 확정에서 재생이 끝나고 기존 사례도 과거 확정 시점에서 잘렸을 수 있다.

초기 실행에서 발견한 기존 검사 문제도 정리했다. CTC검사는 원본 저장소 폴더 대신 패키지 내부 fixture를 읽고, 음악82개 고정 자료와 현재 콘텐츠의 설정 검사를 구분한다. 검사 실패를 숨기거나 제품 임계값을 낮추지 않았다.

아카이브 SHA-256: `f8d3a854014df0b22282f8b0e731166b5b027b73c659196af49c8f2df4de23f0`. 크기3,149,566바이트,214파일. 세 설치본과 원본 코드의 해시 일치를 확인했다. 보호 파일 악기106·공룡89·화분87개의 오디오/수집/정답 및 기존 변경을 대조했고 예상하지 않은 변경0건이다.

## 남은 확인

실마이크·HMD 및 새 Windows Player 전체 빌드는 수행하지 않았다. 다음 배포 전 실제 게임과 장치에서 확인한다. 새로운 발음 오류·잡음 환경의 정답/오답 허용률은 별도 녹음 평가로 측정해야 한다. 이번 작업에서 임계값 재보정이나 새로운 정확도 수치를 주장하지 않는다.

Claude 검수는 APPROVE이며 차단 지적0건이다. 후속 항목과 근거는 프로젝트 문서의 `review-resolution.md` 및 `web-oracle-provenance.json`에 기록했다. 구현 당시에는 화분만 로컬 커밋하고 나머지는 작업 트리에 보관했다. 이후 2026-11-19 사용자의 문서 최신화·커밋·푸시 요청에 따라 공통 패키지와 세 콘텐츠의 관련 변경을 각 저장소 커밋에 포함한다. 대상 브랜치는 Audio-Recognition `main`, Music `Hakju`, Dinosaurs `hakju`, Flower `yj_+main's_TeacherTimeline`이다. 기존 사용자 폰트·에디터 설정과 별도 웹 문장/LLM 작업은 제외한다. 새 GitHub Release 게시나 Player 빌드는 이번 작업에 포함하지 않는다.


## 재현 자료와 웹 작업 범위

Unity 패키지에는 웹에서 생성한 `Tests/Runtime/orthographic_word_vectors.json.gz`를 포함한다. 패키지의 회귀 검사는 이 고정 자료를 읽으므로 Python 웹 서버나 모델이 필요하지 않다. fixture와 각 콘텐츠의 `web-oracle-provenance.json`에 생성 시 사용한 웹·발음 변환 소스 9개의 SHA-256을 기록했다.

`python/tools/child_orthographic_web/export_unity_v7_vectors.py`는 해당 웹 v7 소스 스냅샷에서 기준 자료를 다시 만들 때 사용하는 개발 도구다. 기존 v5 기준 자료 11,804개를 별도 파일로 보존해 `--baseline`에 지정한다. 같은 작업 트리에 있는 웹 두 단어·문장/LLM 기능은 이번 Unity 패키지 게시에 포함하지 않으므로, 새 clone의 Python 웹 소스만으로 v7 fixture를 재생성할 수 있는 상태는 아니다. 재생성하려면 기록된 해시와 일치하는 웹 스냅샷과 웹 개발 환경을 먼저 준비해야 한다. 이 제약은 설치된 Unity 패키지 실행이나 동봉 fixture를 이용한 검사에는 적용되지 않는다.
