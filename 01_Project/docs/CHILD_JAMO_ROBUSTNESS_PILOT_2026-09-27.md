# 동일 발음의 음향 변화에 대한 비교 재학습 — 2026-09-27

## 근거와 목적

사용자가 직접 비교한 6쌍 모두에서 A/B의 발음이 같다고 답했다. 모델은 그중 기존
오류 3개에서 정답으로, 정상 인식 2개에서 오답으로 바뀌었다. `쌕` 사례는 변환해도
여전히 오답이었다. 따라서 해당 표본에서는 변환 때문에 발음이 달라졌다는 설명보다
모델의 음향 조건 민감성이라는 설명을 지지한다. 나이·기기의 원인이나 전체 오류의
단일 원인을 확정한 결과는 아니다.

기존 `data.collate`는 원래 파형을 읽고 길이를 맞춰 배치로 만들며, 음높이·속도 변환은
없었다. `train.build`의 특징 마스킹은 그대로 있었다. 이를 보완하는 음향 변화 학습이
실제 개선을 만드는지, 단순히 같은 자료를 추가 학습하는 효과와 구분한다.

## 결과를 보기 전에 고정한 비교

- 두 모델 모두 같은 기존 `main/best.pt`에서 시작한다.
- 수정된 학습 목록 150,252개에서 2,048개를 결정적으로 선정한다. 절반은 단독 단어의
  전사 종류를 균형 있게 고르고, 나머지는 전체 학습 풀에서 고른다. 모델 출력으로 선정하지 않는다.
- 두 모델의 선택 음성·순서·배치·업데이트 수·초기값·학습률을 동일하게 고정한다.
- 대조 모델은 원음을 추가 학습하고, 변환 모델은 절반의 원음을 그대로 두며 나머지에
  음높이·속도 변화 중 하나를 적용한다. 추론 입력은 양쪽 모두 원래 소리 그대로다.
- 변환은 음높이와 속도를 함께 ±2반음 상당 변경, 길이를 유지하고 음높이 ±2반음 변경,
  속도 0.65배의 다섯 조건이다. 변환 후 피크가 넘치면 감쇠하며 자모 정답은 바꾸지 않는다.
  CTC 정답을 표현하기에 너무 짧아지면 해당 변환만 적용하지 않는다.
- 48개 transformer 층 중 마지막 8개와 CTC head만 128회 업데이트한다. 전체 자료·전체
  모델을 다시 학습한 결과로 부르지 않는다. 두 조건의 작은 비교 실험이다.
- 마지막 고정 업데이트를 비교한다. 직접 녹음 결과를 보고 중간 모델을 고르지 않는다.

직접 녹음은 학습에 **0개** 포함된다. 이미 들었던 학습 예시 6개도 이번 추가 학습
표본에서는 제외했다. 원래 학습에 들어갔던 이력까지 없어지는 것은 아니다. 새 표본의
화자·PCM이 검증·테스트와 겹치지 않는지 확인하고, 읽은 원본·학습 구간 해시도 검증한다.

## 평가와 판단 기준

1. 기존 검증 1,500개의 원래 음성에서 성능 저하를 확인한다.
2. 미리 고른 검증 96개에 같은 다섯 변환을 적용해 음향 변화에 대한 반응을 비교한다.
   개별 변환 발음을 모두 사람이 확인한 것은 아니므로 이 집계는 보조 지표다.
3. 직접 녹음 13개와 사람이 확인한 6쌍을 진단한다. 모호한 기존 답변은 배타적 정답으로 세지 않는다.
4. 테스트 2,999개는 이 실험에서 다시 평가하지 않는다.

사전에 고정한 통과 조건은 변환 검증의 자모 오류율이 기존 모델과 대조 모델보다 낮을 것,
일반 검증의 오류율 상승이 기존 모델 대비 0.001 이하일 것, 직접 녹음에서 최소 1개가
추가로 맞고 기존 정답이 틀어지지 않을 것, 사람이 `쌕`으로 들은 소리를 `책`으로
정상화하지 않을 것이다. 이를 통과해도 일반화가 최종 입증된 것은 아니며 자동 배포하지 않는다.

## 실행과 검증

구현은 `python/tools/child_jamo_finetune/augmentation.py`와 `robustness.py`다.
파형의 주파수·길이 변화, 원음 보존, 재개 시 동일한 변환 선택, CTC 길이, 표본 선택,
원본 해시, 실제 길이 mask와 정답 보존에 대한 15개 검사와, 아래 상태 파일 저장
충돌에 대한 2개 검사를 합쳐 **17개 검사**를 통과했다.

```powershell
.venv-gpu/Scripts/python.exe -X utf8 python/tools/child_jamo_finetune/robustness.py --arm control
.venv-gpu/Scripts/python.exe -X utf8 python/tools/child_jamo_finetune/robustness.py --arm augmented
```

산출물은 `.venv/hubert-child-20260914/robustness-pilot-20260927/`에 저장한다.
`selection.json`, `plan.json`, 각 조건의 `config.json`, `progress.json`, `last.pt`,
`model.pt`, `result.json`, 마지막 `comparison.json`에 실행 조건과 결과를 기록한다.
실패 시 마지막 완료된 주기 체크포인트부터 같은 명령으로 재개하며, 코드·자료·설정이
달라지면 재개를 거부한다. 기존 모델과 기존 청취 DB는 덮어쓰지 않는다.

## 첫 128회 비교 결과

두 조건 모두 645개의 서로 다른 발화를 같은 순서로 학습했다. 전체 선정 표본은
2,048개지만 이 짧은 실험에서 모두 학습한 것은 아니다. 변환 모델의 실제 적용 수는
원음 336개, 음높이 올림 64·내림 70, 음높이·속도 함께 올림 66·내림 53, 속도 0.65배 56개다.

| 측정 | 기존 모델 | 원음 추가 학습 | 변환 추가 학습 |
|---|---:|---:|---:|
| 일반 검증 1,500개 자모 오류율 | 2.950% | 2.932% | 2.941% |
| 검증 96개 × 5개 변환의 자모 오류율 | 5.079% | 5.079% | 5.012% |
| 사람 정답이 있는 직접 녹음 11개 중 일치 | 2 | 2 | 2 |

표의 두 정답은 기존 대조 음성 `아빠`, `엄마`다. 기존 오류가 새로 해결된 사례는 없었다.
`책 → 샙`, `나비 → 나리`, `뛰어가요 → 귀어 가요`가 변환 학습 후에도 남았다.
특히 실제 `쌕`은 원래 `ㅐㄱ`이었으나 변환 학습 후 **`책`으로 바뀌었다.** 둘 다 실제
청취와 다른 결과지만, 후자는 전사만 기준으로 보면 좋아진 것처럼 오해할 수 있다.
따라서 사전에 정한 원래 문제 개선·`쌕` 보호 조건을 통과하지 못했고, 모델을 채택하지 않았다.

실제 학습한 645개에는 단독 `책` 1개, `나비` 문자열 포함 2개만 있었으며,
`뛰어가요`, `실로폰`, `놔요` 문자열을 포함한 사례는 없었다. 짧은 비교의 결과를
전체 자료·전체 모델 재학습의 결과로 확대하지 않는다. 기존 모델 파일의 해시 보존,
두 조건의 설정·노출 순서, 저장된 두 모델 해시까지 검증했다.

현재 기준 모델 검증은 과거 기록보다 자모 오류가 1개 많았다(979 대 978).
이 실행은 더 작은 평가 배치를 사용한다. 비교 표의 세 모델은 모두 동일한 현재 평가
조건으로 계산했으며, 직접 녹음 13개와 청취 파일 12개는 과거 출력을 모두 재현했다.

## 1,024회 후속 비교

첫 결과의 학습량 한계를 확인하기 위해 같은 2,048개 표본에서 각 조건을 1,024회
학습하는 별도 비교를 실행했다. 초기 모델·표본·변환·평가·통과 조건은 그대로다.
학습 도중 원래 문제 음성의 결과를 보고 모델을 선택하지 않는다. 이번에도 8개 층만
학습하는 개발 실험이며, 전체 학습 자료 150,252개를 재학습했다고 표현하지 않는다.

기준 모델·검증 표본·평가 코드가 모두 같아 기존 기준 평가 파일을 해시 검증 후
재사용했다. `baseline-reuse.json`에 이를 기록했으며, 추가 학습 모델의 평가는 새로 한다.
산출물은 `.venv/hubert-child-20260914/robustness-extended-20260927/`이다.

대조 조건 352회 완료 후 `progress.json`을 읽는 작업과 원자적 교체가 겹쳐 Windows
`WinError 5`가 발생했다. `last.pt`는 먼저 정상 저장돼 있었다. `common.dump`에
일시적인 `PermissionError`의 최대 2초 재시도를 추가했다. 계속 거부되면 오류를
전달하고 기존 파일을 보존한다. 일시·지속 잠금에 대한 두 검사를 통과했다.
학습 수학·표본·초기값·체크포인트의 RNG는 바꾸지 않고 352회 체크포인트부터 재개한다.
