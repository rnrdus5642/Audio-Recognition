# 20ms / 10ms 프레임 간격 비교 — 2026-09-27

10ms 출력 간격으로 실행할 수 있다. 다만 기존 가중치를 그대로 사용한 27개 비교에서는 개선과 악화가 함께 나타났으며, 전체 자모 오류 수는 증가했다. 현재 서비스와 저장된 모델 설정은 변경하지 않았다.

## 변경 범위

- 입력은 동일한 16kHz PCM이고, 모델 가중치·디코더·float32 추론 조건은 동일하다.
- 기존 합성곱 이동 폭은 `[5, 2, 2, 2, 2, 2, 2]`이며, 전체 이동 간격은 320샘플 = 20ms다.
- 실험에서는 마지막 층의 이동 폭만 2에서 1로 바꾸어 160샘플 = 10ms로 실행했다. 출력 길이를 계산하는 메모리상의 설정도 함께 맞췄다.
- 파형을 처음 처리하는 합성곱의 프레임당 수용 구간은 두 조건 모두 25ms다. 따라서 20ms는 출력 프레임의 이동 간격이며, 프레임 사이의 음성을 버린다는 의미가 아니다. 이후 문맥 모델은 여러 프레임을 함께 처리한다.
- 프레임 수는 약 두 배가 된다. 초 단위로 본 위치 문맥의 범위도 바뀌므로, 이번 비교만으로 오류 원인이 20ms 간격의 정보 손실이라고 판단할 수 없다.
- 추가 학습은 0회다. 실험 프로세스 안에서만 설정을 바꾸었으며 종료 전에 원래 이동 폭을 복원했다.

## 해석과 다음 단계

간격을 줄이는 것은 가능하지만, 설정 변경만으로 기존 문제가 해결되지는 않았다. 10ms 조건에서 두 녹음이 새로 맞았고 한 녹음은 새로 틀렸다. 완전 일치는 한 건 늘었지만, 틀린 결과의 자모 오류까지 합하면 23개에서 26개로 증가했다. 특히 실제 청취 기준이 `쌕`인 음성을 `책`으로 바꾼 결과는 개선으로 계산하지 않았다.
