# 마이크로 현재 모델 테스트

현재 모델의 평가·남은 오류·원인 분석은 [작업 현황](../../../docs/CHILD_JAMO_STATUS.md)에 정리한다.

주소: <http://127.0.0.1:8776/>

Chrome 또는 Edge에서 녹음 시작 → 마이크 허용 → 단어 말하기 → 녹음 끝내기
순서로 사용한다. 최대 15초에서 자동 종료한다. 결과 아래에서 같은 녹음을 다시
들을 수 있고, 최근 50개 결과를 선택하거나 JSON으로 내려받을 수 있다.
탭이나 정답 단어 입력은 없다.

## 실행

```powershell
powershell -ExecutionPolicy Bypass -File .\start_child_jamo_mic.ps1
```

이미 마이크 서버가 실행 중이면 주소를 표시한다. 새로 실행할 때는 이 명령의
터미널을 유지하고, 종료하려면 Ctrl+C를 누른다. 별도의 데이터셋·청취 뷰어를
종료하거나 포트를 바꾸지 않는다. 로컬 PC의 127.0.0.1에만 연결한다.

## 모델과 입력

- 현재 모델 `.venv/hubert-child-20260914/main/best.pt`를 기존 `engine.Engine`으로
  불러온다. 체크포인트 SHA-256은
  `5a330f1bea3a17d1d063fdfd71a0cc25394695b0b797de01b293f6f688257aa7`이다.
- 이번에 채택하지 않은 추가 학습 실험 모델은 사용하지 않는다.
- 기존 FP32 추론, 실제 길이 마스크, greedy CTC 및 자모 조합을 그대로 사용한다.
  예상 단어나 사전으로 결과를 바꾸지 않으며, 조합되지 않은 자모도 표시한다.
- 브라우저의 실제 AudioContext 샘플률로 녹음한다. 서버가 기존 업로드 처리로
  16kHz 모노 PCM을 만들며, 사용자가 재생하는 WAV와 모델 입력은 동일하다.
- 앞뒤 여백 자르기, 무음 추가, 음량 정규화를 하지 않는다. 브라우저에는 자동
  음량 조절·소음 억제·에코 제거를 끄도록 요청한다. OS나 마이크 자체의 처리는
  별도 장치 설정에 달려 있다.

## 저장과 다음 분석

실제 녹음은 `.venv/child-jamo-web-20260916/microphone/recordings/`에 UUID별
WAV와 JSON으로 보관한다. JSON에는 원문 출력·자모·토큰, PCM 및 모델 해시,
녹음 길이·시각·인식 시간이 있다. 새로고침해도 기록이 유지된다.
`GET /api/history`는 최근 50개, `GET /api/audio/{id}`는 해당 모델 입력을 돌려준다.
새 음성 인식은 `POST /api/transcribe`의 WAV 파일로 수행한다.

현재 기록에는 사용자가 의도한 단어와 청취로 확인한 실제 발음 라벨이 없다.
후속 분석에서는 녹음 ID에 청취 판단을 연결해야 하며, 모델 출력만 보고 실제 발음을
정답으로 붙이지 않는다. 여러 표기로 들리는 녹음은 모호함을 유지한다.

발음대로 적혀 낯선 표현과 실제 자음 누락을 구분한다. 발음한 초성이 빠지거나
서로 구별해 말한 소리가 같은 단어로 바뀌는 현상은 개선 대상이다.

## 확인한 동작

`test_microphone.py`의 6개 검사를 통과했다. 신호 보존 및 재생 파형 일치,
자모 출력 보존, 48kHz 입력 처리, 손상·초과 길이 거절, 모델 신원, HTML과
로컬 요청 처리 등을 검사한다.

`qa_microphone.py`는 Edge의 파일 기반 가상 마이크를 실제 녹음 경로에 연결한다.
실제 GPU 모델 추론, 수동 종료, 15초 자동 종료, 오디오 재생, 기록 복원·선택,
결과 다운로드, 작은 화면, 권한 거부 안내를 확인했다. 권한 거부는 브라우저에서
예외를 주입한 검사이며 실제 사용자 마이크로 녹음했다고 주장하지 않는다.
검사 중 생긴 녹음은 QA 디렉터리에 옮겨 실제 테스트 목록과 섞이지 않게 한다.

검사 기록과 화면은 `.venv/child-jamo-web-20260916/microphone/qa/`에 있다.
