# 오디오 정답 처리 — 공용 모델 패키지

버전 **0.9.2-preview.2**. Unity 2022.3 / Sentis 1.2.0-exp.2, Windows PC·PC 연결 VR용입니다. 최종 3에포크 HuBERT 정서법 자모 모델과 웹사이트의 단어 후보 판정 `orthographic-word-context-v7`을 사용합니다. GPUCompute 경로를 유지합니다.

## 웹 v7 후처리

불완전한 현대 자모가 섞인 인식 결과도 단어 전체를 점수 계산에 넣습니다. 자모를 삭제하거나 누락된 소리를 정답으로 채우지 않으므로 `책ᄉ`의 추가 소리도 감점됩니다. 3음절 이상 비동작 명사에서는 정답과 같은 음절 수의 어근 뒤에 알려진 조사가 붙었을 때 어근만 비교합니다. 예를 들어 `양쪽 손으로 실로펀 체를 들어`에서 `실로펀체`를 `실로폰채`와 비교하며, 기본 0.85 임계값과 2회 확인을 거칩니다. 정확히 등록된 긴 후보가 있으면 그 후보가 우선합니다.

`WordCandidateScore.MatchSuffix`와 `UncomposedJamo`로 비교한 조사와 불완전 자모 여부를 확인할 수 있습니다. 원본 인식 문장은 보존합니다. 기존 v4/v5 정답 JSON과 정답 목록을 그대로 사용하며 모델 재다운로드는 필요 없습니다. 임의의 합성어 내부 자르기, 동음 후보 동점 허용, 동작어 대체는 하지 않습니다. 부정 표현의 바로 다음 어절 검사도 유지합니다. 일반적인 문장 의미 이해나 발화자 구분 기능은 아닙니다.

이번 이식은 여러 후보 중 하나를 판정하는 모드입니다. 웹의 두 단어 모두 확인·문장/LLM 모드는 포함하지 않습니다. 웹 구현이 만든 11,844개 재생 사례(기존 11,804개 + v7 대조 40개), 98,251회 판정과 74개 자모 변환 기대값을 `Tests/Runtime/orthographic_word_vectors.json.gz`에 보관합니다. 이는 구현 일치 검증 자료이며 실사용 정답률 측정값은 아닙니다.

Sentis 1의 외부 모델을 준비할 때는 Unity 스레드에서 `await SentisPhonemeRecognizer.CreatePreparedAsync(path, vocabulary, 2.5f, cancellationToken)`을 사용할 수 있습니다. 파일 읽기는 백그라운드에서 수행하며 GPU 워밍업 완료 후 인식기를 반환합니다. 준비 중에는 답변 타이머를 시작하지 말고, 문항마다 같은 인식기를 재사용한 뒤 소유 객체 종료 시 `Dispose()`하세요. 취소 후에도 진행 중인 GPU 작업이 끝나야 자원이 해제됩니다. 기존 동기 생성자·`Warmup` API는 유지됩니다. 초기 GPU 업로드와 개별 레이어 실행에는 일회성 프레임 지연이 남을 수 있습니다.

앱이 콘텐츠 동안 마이크를 유지할 때는 `ListenFrom(new AudioWindowBuffer(2.5f, .5f))`로 질문을 시작하고, 청취 중에만 그 버퍼에 새 16kHz 모노 PCM을 `Append`합니다. 리스너는 질문 시작 때 버퍼를 초기화하며 외부 마이크를 열거나 닫지 않습니다. 기존 `Listen()`은 질문별로 마이크를 소유합니다. 답변 구간 저장과 콘텐츠 수명주기는 앱이 맡습니다. 화분에 먼저 연결했으며 다른 프로젝트의 설치된 패키지는 자동으로 변경되지 않습니다.

## 음성 추론과 프레임 지연

게임의 `PronunciationListener`는 `IAsyncPhonemeRecognizer`를 감지해 GPU 추론을 여러 프레임에 나눕니다. 프레임마다 최대 128개 레이어 또는 CPU 스케줄링 2ms까지 예약하고, GPU 읽기 완료 콜백에서 결과를 가져옵니다. 2ms는 예약 예산이며 개별 레이어의 실행 시간이나 전체 게임 프레임 시간을 보장하는 수치는 아닙니다. D3D11 등 비동기 GPU 읽기를 지원하는 환경이 필요합니다.

추론 대기 중에도 마이크 입력과 문항 제한 시간 검사는 계속합니다. 한 모델에서 동시에 하나만 실행하고, 완료된 창은 오디오의 원래 순서·시각으로 판정합니다. 정지·문항 전환 시 이전 결과는 버리되 GPU 작업이 끝난 뒤 자원을 해제합니다. 추론 예외는 기록하고 청취를 중단합니다. 게임은 `IsListening == false`를 감지해 입력 오류·재시도 대기로 전환합니다. `OnTimedOut`은 실제 시간 초과 때만 보냅니다. 연결 코드는 다음 `Prepare()`에서 `IsFaulted` 모델을 해제·재생성해야 합니다. 장치 손실로 GPU 콜백 자체가 돌아오지 않는 경우의 강제 복구는 제공하지 않습니다.

사용자 정의 래퍼도 `IAsyncPhonemeRecognizer`를 구현해 `RecognizeAsync`와 `IsRecognizing`을 전달해야 합니다. 직접 세션을 사용하는 경우 `TryAdvance`를 프레임마다 호출합니다. 기존 동기 `RecognizeWithText`·`Push`·`TryPush`는 호환용이며 프레임 지연을 줄이려면 비동기 경로를 사용해야 합니다. 모델 준비는 위 `CreatePreparedAsync`로 전환할 수 있으며 기존 생성자와 `Warmup`을 직접 호출하는 앱은 동기 동작을 유지합니다. 모델·2.5초 창·0.5초 간격·정답 판정 v7 및 PNG 캡처와 추론 스케줄링은 별도 기능입니다. Unity Profiler에서 `DomiCube.Model.LoadFile`, `DomiCube.Model.CreateWorker`, `DomiCube.Inference.Schedule` 구간을 확인할 수 있습니다.

## 사용 방법
`Tools > 오디오 정답 처리 기능`에 세 메뉴만 제공합니다.

- **초기 세팅**: 메뉴를 누르면 바로 실행하며 화면 중앙 진행창에 현재 단계와 진행률(%)을 표시합니다. 취소 버튼으로 중단할 수 있고 완료·실패·취소 시 자동으로 닫힙니다. 엔진 설치 단계는 UPM이 진행률을 제공하지 않아 단계 안내만 표시합니다. 완료·실패 내용은 Console에도 남깁니다. 추론 엔진·정답 데이터·공용 모델을 확인합니다. Windows 문서/오디오정답처리/Models의 정상 모델은 재사용하고, 없거나 손상됐으면 GitHub Release에서 자동 설치합니다. 위치 선택·수동 등록은 없습니다. 한 PC의 모든 콘텐츠가 같은 파일을 읽습니다.
- **음성 테스트**: 마이크와 단계를 선택해 게임과 같은 모델·정답·후처리로 확인합니다.
- **정답 단어 설정**: 현재 프로젝트의 단계별 표현을 편집·검증·저장합니다. 끝의 물음표는 표시용으로 유지하며 재학습은 필요 없습니다.

프로젝트 연결은 Assets/Resources/CRC/AudioAnswerProject.json의 displayName과 targetsResourcePath를 사용합니다. 정답 JSON은 프로젝트 Assets에 보관합니다. 현재 세 콘텐츠는 각각 9절차입니다.
정답 단어의 비교용 IPA는 내장 한국어 발음 규칙과 자모 변환 코드로 만듭니다. 별도 IPA 모델이나 Python 설치는 필요 없습니다.

## 모델
파일: `hubert_ko_child_jamo_epoch3_sentis1.sentis`, 3,851,161,113 bytes.
SHA-256: `1ce1f13e3497844a6632cae3d6925f3aae64159f6d5ab2b60c84613493dcbea3`.
배포: [최종 3에포크 모델 Release](https://github.com/rnrdus5642/Audio-Recognition/releases/tag/model-v4-child-jamo-epoch3-sentis1).

문서 폴더의 위치는 고정이며 같은 버전을 사용하는 모든 콘텐츠가 한 파일을 공유합니다. 이전 2에포크 모델은 다른 파일명으로 남겨 두므로 구형 앱을 깨뜨리지 않습니다. 패키지를 갱신한 프로젝트에서 초기 세팅을 한 번 실행하면 새 모델이 설치됩니다. 기존 프로젝트의 v4/v5 정답 JSON도 현재 v7 후처리로 읽으며, 단계와 정답 목록을 덮어쓰지 않습니다. 이미 만들어진 실행 파일에는 새 패키지가 자동 반영되지 않으므로 다시 빌드해야 합니다.

## 정답 판정 흐름

최근 2.5초의 16kHz 모노 PCM을 0.5초 간격으로 받아씁니다. 정답 후보는 음성 모델에 전달하지 않습니다. 모델이 출력한 문장은 그대로 보존하고, 후처리에서 문장 중간을 포함한 띄어쓰기 단위와 명시한 조사·서술형·인용 표현을 비교합니다. `이건 사과인 거 같아요`, `동생도 사과를 따요`에서 `사과`를 비교하므로 앞뒤의 다른 말이 그 점수를 깎지 않습니다.

- 기본 유사도 기준 0.85, 같은 후보의 확인 2회입니다. 확인 사이에 불확실한 검사 1회만 허용하며 오래된 증거는 만료됩니다.
- 문장 중간의 한 음절 후보는 발음이 같아야 인정합니다. 다른 동작어, 동음이의 후보 동점, 바로 뒤의 `아니`·`말고`는 제한합니다.
- 서로 떨어진 정확한 정답이 여러 개 있으면 마지막 단어를 선택합니다. `먹이를 주자`의 `먹이`·`주자`가 모두 후보면 `주자`를 선택합니다.
- 임의의 내부 글자 자르기나 1.2~1.5배 문자 창은 적용하지 않았습니다. `사과주스`는 `사과`로 분리하지 않지만, ASR이 `사과 주스`로 띄어 쓰거나 중간에 `사과`만 출력하면 통과할 수 있습니다.
- 표면 규칙이며 문장의 의미·의도를 이해하지 않습니다. ASR 오류, 띄어쓰기, 합성어, 아동의 변형 발음에 대한 한계가 남습니다. 점수는 정답 확률이 아닙니다.

기존 `PronunciationSession.ForOrthographicWord`와 `PronunciationListener` 연결을 그대로 사용합니다. 상세 결과의 `SelectionReason`은 별도 위치의 정확한 후보 중 마지막 것을 고른 이유를, `CandidateScores`의 `MatchStart`·`MatchEnd`는 텍스트 토큰 위치를 나타냅니다. 음성 시간 위치가 아닙니다.

## 설치 검증

다운로드와 SHA-256 검증은 백그라운드에서 진행하고 검증 후 원자적으로 설치합니다. 취소·손상·동시 설치를 처리합니다. 설치기가 `.verified` 표식을 남기며 Runtime은 크기·수정 시각·표식을 확인한 뒤 읽기 전용 FileStream에서 로드합니다. 게임 스레드에서 전체 해시를 다시 계산하지 않습니다.
Windows 빌드 앱은 시작 화면에서 같은 문서 위치를 확인합니다. 정상 설치 기록이 있으면 파일 크기·수정 시각·작은 표식만 읽고 게임을 시작합니다. 기록이 없거나 파일이 변경됐으면 백그라운드에서 전체 검증하며, 파일이 없거나 손상됐으면 공개 Release에서 다운로드합니다. 진행 단계·퍼센트·취소·실패 시 다시 시도·종료 버튼을 표시합니다. 모델은 빌드에 포함되지 않으며 새 PC에서 Unity나 Python을 설치할 필요가 없습니다. 최초 다운로드에는 인터넷과 모델 약 3.85GB를 저장할 공간이 필요합니다. 교체 중에는 기존 파일과 임시 파일이 함께 존재할 수 있습니다.

개발자는 초기 세팅을 한 번 실행한 뒤 Windows로 빌드합니다. 초기 세팅은 패키지 시작 씬을 `Assets/AudioAnswerStartup/AudioModelStartup.unity`에 복사해 Build Settings 첫 씬에 추가하고, 원래 첫 번째 게임 씬을 `Assets/Resources/CRC/AudioAnswerLaunch.json`에 기록합니다. 시작 씬 확인이 끝나야 기존 게임 씬을 로드하므로 설치 중 게임·마이크 초기화가 시작되지 않습니다. 사용자 빌드 스크립트도 이 시작 씬을 첫 항목으로 포함해야 합니다. 기존 씬 인덱스가 한 칸 이동하므로 새 콘텐츠에서 숫자 인덱스로 씬을 불러오는 코드가 있다면 경로나 이름을 사용하세요.

초기 세팅 메뉴를 직접 누르면 전체 SHA-256을 재검사하므로 이미 설치된 PC에서도 시간이 걸릴 수 있습니다. 정상 빌드 앱의 반복 실행에서는 이 검사를 생략하지만 모델 메모리 로드와 GPU 준비 시간은 별도로 필요합니다. PC 연결 VR의 최초 설치 화면은 PC 창에 표시됩니다.

현재 공유 바이너리는 Sentis 1.2 전용입니다. Unity 6용 모델·외부 로더와 CPU 자동 전환은 이번 범위에 포함하지 않습니다. 이전 API는 호환용으로 남겨 두되 구형 설치·발표 메뉴는 노출하지 않습니다. [이전 버전 문서](Documentation~/legacy-package-0.8.7.md)는 역사적 참고 자료입니다.
