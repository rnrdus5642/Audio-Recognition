# 악기놀이 발표 적용 · 0.8.6

## 새 프로젝트와 기존 프로젝트

1. Unity의 `Window > Package Manager > + > Add package from tarball…`에서
   `com.domicube.phoneme-matching-0.8.6.tgz`를 선택합니다. 기존에 설치된 같은 이름의
   패키지는 이 버전으로 교체됩니다. 먼저 삭제할 필요가 없습니다.
2. `Tools > Phoneme Matching > 악기놀이 발표 설정`을 실행합니다.
   필요한 경우 Unity 2022.3에는 Sentis 1.2.0-exp.2, Unity 6에는 Inference Engine 2.6.1을
   설치하고 아동 모델을 내려받습니다. 엔진 설치로 재컴파일되면 이어서 진행합니다.
3. 열린 테스트 창에서 **악기놀이 단계**를 고르고 **시작 (마이크 켜기)**를 누릅니다.
   단계 대신 `직접 단어 입력`을 선택하면 등록된 12개 정답 중 하나씩 검사할 수 있습니다.

처음 받는 모델은 약 1.18GB이며 다운로드와 Unity 임포트가 필요합니다.
이미 `Assets/Resources/Models/wav2vec2_ko_child.onnx`가 있으면 재사용합니다.
다른 프로젝트에 모델이 있으면 `아동 음향 모델 파일에서 가져오기…`로 가져올 수 있습니다.
성인 모델만 있는 프로젝트에는 아동 모델을 한 번 추가해야 합니다.

발표용 정답·혼동 행렬·어휘는 **설치된 패키지의 Resources**에서 읽습니다.
`Assets/StreamingAssets`에 예전 정답 JSON이 있어도 발표 모드에는 새 패키지의 값이 적용됩니다.
일반 단어용 JSON이나 게임 이벤트를 덮어쓰지 않습니다. 일반 `초기 세팅`만 실행하거나
패키지만 업데이트하는 것으로 기존 게임의 모드가 바뀌지는 않으므로 아래 API를 연결하세요.

## 게임에 바로 넣기

`GameObject > Phoneme Matching > 악기놀이 발표`를 선택하면
`MusicPresentationLesson`과 `PronunciationListener`가 있는 오브젝트를 만듭니다.
Play 후 **준비 → 단계 선택 → 시작**으로 체험할 수 있습니다. 자동으로 녹음을 시작하지 않습니다.
`PronunciationListener.OnConfirmed(string, float)`를 기존 성공 애니메이션이나 다음 단계 처리에 연결하세요.

기본 화면은 정답 확정 후 모델 혼동을 고려한 발음 안내도 표시합니다.
`놔 → 와`처럼 모델의 인식 누락과 아동 발음을 구분할 자료가 부족한 경우에는
정답 판정을 유지하고 내부적으로 해당 지적을 보류합니다. 0.8.3부터 표시할 지적이 남지 않으면
`발음에 문제 없어요.`라고 안내합니다. 일부 안내가 남으면 해당 부분만 보여줍니다.
자체 UI는 `OnConfirmedDetailed`의
`KoreanFeedback.Summary`와 `Items`를 사용하세요. `RawKoreanFeedback`은 원본 확인용입니다.
기존 0.8.0~0.8.5 사용자는 패키지를 한 번 업데이트하고 실행 중인 세션을 다시 준비하면 됩니다. 아동 모델은 재사용합니다.
발표 API로 연결한 게임은 변경된 정답표도 자동으로 읽습니다. 자체 코드에 정답 배열을 직접 적었다면
아래 표로 수정하거나 `GetStage`·`ApplyTo`를 사용하세요.

자체 UI가 있으면 `Show Controls`를 끄고 아래 메서드를 호출합니다.

```csharp
using DomiCube.PhonemeMatching.Unity;

// music은 씬에 추가한 MusicPresentationLesson 컴포넌트입니다.
music.Prepare();       // 로딩 중 한 번: 아동 모델과 발표 데이터 준비
music.ListenStage(2); // 쳐 / 때려 / 연주해 검사와 마이크 시작
music.Stop();         // 수업 일시 정지 시
```

이미 아동 모델 인식기를 `PronunciationListener`에 연결한 게임은 컴포넌트를 추가할 필요 없이,
각 단계가 시작될 때 다음 두 줄을 사용하면 됩니다.

```csharp
MusicPresentation.ApplyTo(listener, stage: 8); // 북채 / 들어 / 잡아, 단어별 조정값 적용
listener.Listen();
```

`ApplyTo`는 진행 중인 청취를 정지하고 데이터·단계 정답·2.5초 창·0.5초 간격을 적용합니다.
이미 연결된 인식기와 `OnConfirmed` 등 이벤트는 유지합니다. **인식기는 아동 모델용이어야 합니다.**
모델 연결까지 맡기려면 위 `MusicPresentationLesson`을 사용하세요.
자체 asmdef를 쓰는 코드는 기존 코어·Unity 참조에 더해 컴포넌트 사용 시
`DomiCube.PhonemeMatching.Music`을 참조합니다.

앱이 자체적으로 마이크를 수집한다면 추가로 마이크를 열지 않고 같은 정책을 사용할 수 있습니다.

```csharp
var profile = MusicPresentation.Load();
var session = profile.CreateSession(childRecognizer, audioBuffer);
session.Begin(profile.GetStage(8).Answers);
// 기존 방식대로 audioBuffer에 PCM을 전달하고 session.TryPush(out var frame)를 호출합니다.
```

## 포함된 단계와 판정

| 단계 | 동작 | 기본 정답 표현 |
|---|---|---|
| 1 | 실로폰채 들기 | 실로폰채 / 들어 / 잡아 |
| 2 | 실로폰 치기 | 쳐 / 때려 / 연주해 |
| 3 | 실로폰채 놓기 | 놓아 / 놔 / 내려놔 |
| 4 | 탬버린 들기 | 들어 / 잡아 |
| 5 | 탬버린 치기 | 쳐 / 때려 |
| 6 | 탬버린 흔들기 | 흔들어 |
| 7 | 탬버린 놓기 | 놓아 / 놔 / 내려놔 |
| 8 | 북채 들기 | 북채 / 들어 / 잡아 |
| 9 | 북 두드리기 | 두드려 / 때려 / 쳐 |

현재 단계에 있는 표현만 정답 후보로 사용합니다. 12개를 한꺼번에 후보로 넣지 마세요.
정답별 임계값, 연속 확인 수, 발화 전체 점수, 다른 동작과의 비교 조건을 함께 적용합니다.
`흔들어`는 1회, 나머지는 2회 판정이 필요합니다. `잡아`는 3회에서 2회로 줄였습니다.
이는 같은 발화를 여러 오디오 창에서 확인하는 횟수로, 단어를 여러 번 말하라는 뜻은 아닙니다.

프로필은 `music_demo_2026_09_12`입니다. 일반 조건과 짧은 발화의 보완 조건 중 하나를
충족한 뒤에도 다른 동작과의 비교 및 연속 확인을 거쳐야 합니다. 점수는 확률이 아닙니다.

| 표현 | 일반 임계값 / 전체 점수 하한 | 짧은 발화 임계값 / 단어 전체 점수 하한 | 허용 추가 음소 | 비교 마진 |
|---|---|---|---|---|
| 잡아 | 0.97 / 0.00 | 0.85 / 0.85 | 0 | 0.50 |
| 쳐 | 0.69 / 0.70 | 없음 | — | 0.00 |
| 때려 | 0.83 / 0.20 | 0.56 / 0.65 | 0 | 0.15 |
| 연주해 | 0.90 / 0.00 | 0.75 / 0.75 | 2 | 0.20 |
| 내려놔 | 0.90 / 0.65 | 0.49 / 0.63 | 0 | 0.00 |

짧은 발화 보완은 인식된 음소 수가 정답 음소 수 + 허용 추가 음소 이하이고,
정답 단어 자체와 비교한 전체 점수가 표의 하한 이상일 때만 사용합니다.
동작 비교 마진은 클수록 다른 동작 때문에 거부하는 조건이 완화됩니다.
`북채`의 일반 임계값은 0.74, 전체 점수 하한은 0.65입니다. 나머지 6개 정답의 설정은 0.8.3과 같습니다.

위 5개 동작에는 `실로폰채를·실로폰을·탬버린을·북채를·북을·악기를·손을` 중
동작에 맞는 접두 표현이 등록되어 있습니다. 예를 들어 `실로폰채를 쳐`는 동작 앞의
악기 이름을 확인한 뒤 남은 발화로 전체 점수와 다른 동작을 비교합니다.
접두 표현 점수 0.80 이상, 동작 구간과 겹치지 않는 음소가 필요합니다.
악기 이름만 말해서 동작이 통과하는 것을 막습니다. 임의의 모든 문장을 이해하는 기능은 아닙니다.

`놔`만으로는 `내려놔`가 전체 발화 검사에서 탈락하므로 두 표현을 별도로 등록했습니다.
삭제한 `실로폰·탬버린·북`과 다른 동작인 `내려와·잡아먹어`는 비교용으로만 사용합니다.

아래 수치는 이전 0.8.4를 0.8.3과 비교한 결과입니다. 보유 아동 음성 775개와 합성 음성 24개에서 얻은 동일한 모델 출력을 사용했습니다.
아동 정답 발화는 `잡아` 65→68/77, `때려` 1→7/64, `연주해` 23→24/33,
`내려놔요` 0→1/1, `쳐` 4→4/111입니다. 기존에 통과한 발화가 새로 실패한 사례는 없었습니다.
합성 단일 발화는 `잡아` 0→0/2, `때려·연주해` 각각 1→2/2입니다.
별도 비교 자료 약 5천 발화에서 정답별 오확정은 `잡아` 0→1, `쳐` 6→3,
`때려` 0→3, `연주해` 0→1, `내려놔` 0→5건이었습니다.
일부 오확정이 늘어난 발표용 절충이며 새 아동·성인·현장 마이크의 성공률을 보장하지 않습니다.
특히 `잡아 → 서랍` 같은 큰 모델 오인식과 기존 `와 → 놔` 혼동은 남아 있습니다.


## 0.8.6: 북채와 잡아 조정

새 두 사람의 녹음에서 `북채`는 `똑제/똑재`로 인식되어 0.749~0.769점으로 기준 0.78에 못 미쳤습니다.
기준을 0.74로 낮추고 전체 점수 하한 0.65와 연속 2회 확인을 적용합니다.
`잡아`는 `접어` 등으로 인식된 프레임의 음향 근거가 기존 제한을 조금 벗어나 연속 확정되지 않았습니다.
`acoustic_keyword_policy.min_log_probability`를 -14, `max_log_gap`을 13으로 조정합니다.
`작아`와의 허용 차이 6, 최소 음소 점수 0.65, 인식 음소 3~6개, 일반/짧은 발화 기준 및 연속 2회는 유지합니다.

아래 0.8.5의 수치는 이전 버전 기록입니다. 새 설정도 모든 녹음을 통과시키지는 않습니다.
`들어·놓아·놔·내려놔`는 모델 전사 및 경쟁 동작 비교로 인한 실패가 남아 있으며,
이 버전에는 해당 단어의 기준 완화나 새 모델 학습을 포함하지 않습니다.

## 0.8.5: 실제 녹음에 따른 잡아 보완 (이전 설정·검증 기록)

‘잡아’와 실제 ‘작아’가 모두 `작아`로 인식되는 경우가 있어 음소 임계값만 낮추지 않았습니다.
잡아에만 `acoustic_keyword_policy`를 추가합니다. 기존 일반/짧은 발화 판정이 실패했을 때,
같은 모델 추론의 CTC 후보 점수로 다시 판단합니다. 인식 문구를 잡아로 바꾸거나 녹음 파일을 외워서 통과시키지 않습니다.

- 음소 점수 0.65 이상, 인식 음소 3~6개.
- 잡아의 CTC 로그확률 -11 이상, 원래 인식 문구와의 로그확률 차이 9 이하.
- 작아와의 로그확률 차이 6 이하. 모든 값은 자연로그이며 정답 확률/백분율이 아닙니다.
- 기존 동작 비교 검사와 연속 2회 확인을 그대로 적용합니다.
- 다른 11개 단어 설정, 모델 파일, 마이크 입력은 유지합니다.

사용자가 제공한 잡아 5개는 기본 재생 조건에서 0→4개 통과, 작아 2개는 모두 거절했습니다.
시작 시점을 0/125/250/375ms 바꾼 반복 재생에서는 잡아 0→15/20, 작아 오확정 0/8입니다.
독립 녹음 수는 7개이며, 같은 녹음의 반복 재생을 새 화자 검증으로 해석하면 안 됩니다.
47번은 서랍/저랍으로 인식되어 계속 실패하고, 45번은 250ms 이동 조건에서 실패합니다.

잡아가 포함된 기존 아동 발화는 68/77로 유지됐습니다. 비교 자료 4,995개 중 1개,
기존 아동의 다른 발화 698개 중 14개의 오확정도 증가하지 않았습니다.
새 비교 발화는 작아/접어/서랍/잡아먹/잡아당/잡지 각 30개입니다.
작아·서랍·잡지는 각각 0/30, 접어는 기존과 같은 1/30입니다.
잡아먹/잡아당 문장은 앞부분에서 기존 판정이 먼저 확정하는 문제가 각각 21/30, 25/30 남아 있습니다.
이번 보완으로 새 오확정은 생기지 않았지만, 모든 유사 표현을 구분하는 기능은 아닙니다.

`PronunciationSession`과 `PronunciationListener`는 자동 연결합니다.
직접 `StreamingMatcher.Push`를 호출하는 구현은 인식 직후
`AcousticEvidence.Collect(recognizer, candidates)`를 두 번째 인자로 넘겨야 합니다.
CTC 점수를 제공하지 않는 기존 인식기는 기존 방식으로 동작합니다.

보조 판정으로 확정한 경우 발음 차이는 원본 기록에 남기되 오류 안내에서는 제외합니다.
기존 발표 문구 ‘발음에 문제 없어요.’를 표시합니다. 음향 후보 점수는 발음 진단의 근거가 아닙니다.
진단 JSON의 `acoustic_keyword_policy` 및 `acoustic_*_log_probability`에서 적용 여부를 확인할 수 있습니다.

## 실패한 인식 기록하기

Play 중 또는 타임아웃 직후 `PronunciationListener` 컴포넌트 메뉴에서
`Save recognition diagnostics / 인식 진단 저장`을 선택하면 Console에 JSON 경로가 나옵니다.
`Application.persistentDataPath/PhonemeMatchingDiagnostics` 아래에 최근 120프레임을 저장합니다.
다음 청취를 시작하면 이전 이력은 비워지므로 재시도 전에 저장하세요.
파일에는 원본 음성이 아닌 모델 인식 문구·음소·RMS/peak 음량·점수·적용 임계값·연속 횟수가 있습니다.

`decision_reason`은 `below_threshold`(점수 부족), `whole_utterance_rejected`(전체 발화 조건),
`other_action_scored_higher`(다른 동작 우세), `waiting_for_confirmation`(연속 확인 대기),
`no_recognized_phonemes`(인식 음소 없음), `confirmed` 등입니다. 아동의 발음 오류 판정이 아닙니다.
게임의 개발용 UI는 `OnFrameScoredDetailed` 또는 `LastFrameScored`를 읽을 수 있습니다.

## 이미 Git URL로 설치했다면

이번 `.tgz`를 설치하면 바로 로컬 수정본으로 업데이트할 수 있습니다.
해당 파일은 프로젝트가 다시 열리거나 다른 PC에서 복원할 때도 찾을 수 있도록 보관하세요.
팀 공유 시 프로젝트의 공유 가능한 위치에 함께 두거나, 원격 게시 후 Git 참조로 전환하세요.

Git 방식은 `packages-lock.json`에 커밋이 고정되어 저장소 수정이 자동으로 반영되지 않습니다.
원격에 수정본을 게시한 뒤 `Add package from git URL…`에 동일 URL을 다시 넣거나
새 커밋/태그를 지정해 **패키지를 한 번 업데이트**해야 합니다.
아동 ONNX 모델을 다시 받을 필요는 없습니다.
[Unity의 Git 업데이트 설명](https://docs.unity3d.com/2022.3/Documentation/Manual/upm-git.html#git-locks),
[로컬 tgz 설치 설명](https://docs.unity3d.com/2022.3/Documentation/Manual/upm-ui-tarball.html).
