## 새 원문 자모 모델 학습

**이 실험의 본학습 3에포크와 최종 테스트는 완료됐다.** 아래는 당시 실행·일시정지·재개 방법의 기록이다.
모델 사용을 위해 학습을 다시 시작할 필요가 없다. 완료 상태는 `main/progress.json`, 선택은 `main/selection.json`에 있다.

`start_orthographic_training.ps1`은 3~6세 원문 라벨의 새 69출력 HuBERT 학습을 숨김으로 실행한다.
최종 데이터·코드에 대한 GPU 사전 검사와 재개 검증을 통과한 경우에만 실행된다.
원본 WAV의 앞뒤·중간 무음은 그대로 사용한다. 기존 마이크 모델의 교체는 별도다.

상위 `Audio-Recognition`에서:

```powershell
powershell -ExecutionPolicy Bypass -File .\05_Run\start_orthographic_training.ps1
powershell -ExecutionPolicy Bypass -File .\05_Run\start_orthographic_training.ps1 -Status
```

중단·강제 종료·재부팅 후에는 같은 경로에서 아래 명령으로 이어간다.

```powershell
powershell -ExecutionPolicy Bypass -File .\05_Run\start_orthographic_training.ps1 -Resume
```

`-Pause`는 현재 업데이트를 저장하고 멈추며, 검증 중이면 현재 검증 커서를 저장하고 멈춘다.
운영체제 시작 시 자동 실행을 등록하지 않는다. 실행 중인 같은 작업이 있으면 중복 실행을 거부한다.
모델·양쪽 옵티마이저·데이터 순서·난수 상태는 100업데이트 또는 약10분마다 저장한다.
저장 중 종료되면 직전 정상본을 사용하며, 마지막 저장 이후 작업은 다시 수행한다.
코드·데이터·환경이 달라졌으면 임의로 섞어서 재개하지 않고 오류로 알린다.

진행률·로그·체크포인트는 `04_Models_and_Experiments/orthographic-jamo-20261027/main/`에 있다.
`progress.json`의 단계와 최신 업데이트를 확인한다. `head_gate_failed` 또는
`diagnosis_required`로 멈추면 단순 재실행을 반복하지 않고 손실·검증 결과를 먼저 조사한다.
학습·재개 검증의 세부 근거는 [학습 계획](../01_Project/docs/ORTHOGRAPHIC_JAMO_FINETUNE_PLAN_2026-10-27.txt)에 있다.

### 결과 자동 보고

`start_training_reports.ps1`은 학습 결과를 30초마다 확인하고, 완료된 중간 검증·연령 분포
비교·모델 선택·최종 테스트·오류/비정상 종료를 등록한 Codex 대화에 전달한다.
연령별 CER와 동일 검증셋 대비 변화량을 보고하며, 체크포인트 저장마다 알리지는 않는다.
학습 소스와 모델을 변경하지 않는 별도 Python 프로세스이며 GPU를 사용하지 않는다.

```powershell
powershell -ExecutionPolicy Bypass -File .\05_Run\start_training_reports.ps1 -Status
powershell -ExecutionPolicy Bypass -File .\05_Run\start_training_reports.ps1
powershell -ExecutionPolicy Bypass -File .\05_Run\start_training_reports.ps1 -Stop
```

첫 설정에는 보고를 허용한 Codex 세션의 환경이 필요하며 이후에는 저장한 대화를 재사용한다.
`main/reporting/`에 보고 원본, 전송 대기/접수 상태와 확인 기록을 보관한다.
전송 실패는 재시도하고, 이미 접수된 결과는 중복 전송하지 않는다. 전송 접수와 사용자의
화면 표시/읽음은 다르며, 대화가 작업 중이면 그 작업 이후 전달될 수 있다.
컴퓨터와 Codex 앱을 켜 두어야 즉시 확인할 수 있다. 컴퓨터를 재시작한 뒤 학습의
`-Resume`을 실행하면 설정된 감시기도 함께 재시작한다. OS 자동 시작은 등록하지 않는다.
`-Stop`은 보고 감시만 중지하며 학습을 중지하지 않는다.

원문 자모 성능 테스트는 최종 선택된 **3에포크 모델**을 사용하는 `정답 판정`
전용 웹사이트다. 한글 정답 후보를 쉼표 또는 줄바꿈으로 입력하고 **듣기 시작**을 누른다.
2026-10-31부터 기본 번들은 `04_Models_and_Experiments/orthographic-jamo-20261027/releases/epoch3-final-web-20261031`이다.
기존 화면에 문장 안의 정답을 찾는 후처리 v5를 적용했다. 자유로운 글자 절단·공백 소실 보완안은 적용하지 않았다.
Unity의 배포 모델은 별도로 유지한다. 웹 화면에 `3.00에포크 최종 선택 모델`이 표시되는지 확인한다.
후보는 최대 20개, 각각 1~20글자이며 중복은 합친다. 예: `책, 사과, 자동차`.
`들까요?`처럼 끝에 붙은 물음표(`?`, `？`)는 생략해 `들까요`와 같은 후보로 비교한다.
물음표만 있는 입력은 허용하지 않는다. 질문 억양을 별도로 판정하는 기능은 아니다.
최근 2.5초 음성을 약 0.5초마다 인식하고, 문장 어느 위치에 있든 공백 경계의 온전한
단어·구절과 각 후보를 발음기호로 변환해 유사도를 비교한다.
`이건 사과인거 같아요`, `사과를 먹었어요`에서는 정해진 조사·어미를 분리해 `사과`를 비교한다.
명사 뒤의 조사·서술격 표현과 인용 표현을 한정된 목록으로 처리하며, 일반 형태소 분석기는 아니다.
등록된 동작 표현은 인용 표현을 제외하면 임의로 어미를 제거하지 않는다.
`안녕하세요 들어야지`와 `들 거예요`도 비교할 수 있다.
한 단어만 입력하는 테스트도 지원한다.
모델 추론에는 정답·연령을 전달하지 않는다. 기본 유사도 85점, 같은 후보를 2회 확인하면 정답을
확정하고 마이크를 자동 종료한다. 최근 3회 안에서 인식이 한 번 비거나 미완성이거나 같은 후보의
점수가 기준보다 5점 이내로 잠깐 낮아지면 기다린다. 기다린 검사는 통과 횟수에 더하지 않는다.
다른 후보·명확히 다른 단어·해결되지 않은 동점·긴 검사 간격은 횟수를 초기화한다.
`먹이를 주자`처럼 서로 겹치지 않는 위치에서 여러 후보가 정확한 철자로 확인되면 뒤에 나온
정답을 선택한다. 한 소리가 여러 후보와 일치하는 `낫, 낮` 같은 경우는 계속 보류한다.
시간 제한 없이 정답 확정 또는 수동 중지까지 듣는다.
화면의 `현재 인식 텍스트`에 각 검사 시점의 모델 출력을 바로 보여 준다. 듣는 동안 갱신하고,
테스트 종료 시 마지막 인식 결과를 남기며 새 테스트에서는 초기화한다. 후보 목록과 판정은
옆에 표시하고, 확정 후 선택된 단어를 크게 표시한다. 후보별 점수는 `후보별 점수 보기`에서
확인한다. 같은 목록은 **다시 듣기**로
반복 테스트한다. `판정 설정`에서 기준 70~100점, 확인 횟수 2~4회를 바꿀 수 있다.
`후보별 점수 보기`의 `비교한 인식 부분`에서 전체 문장 중 실제로 비교한 부분을 확인한다.

이 기준은 새 모델에 대한 초기 테스트값이며, 연령별 통과율·오통과율을 보정한 값은 아니다.
기존 음소 비교 비용을 재사용하되 자유롭게 글자를 자르지 않으므로 `책상 → 책`, `물고기 → 물`
같은 비교 구간은 만들지 않는다. 새로 검사하는 문장 중간의 한 글자 정답은 발음기호가 같아야
한다. `다 먹어요 → 따` 같은 오통과를 막기 위한 제한이며, 문장 끝에서는 기존 발음 허용치를 유지한다.
앞말이 띄어쓰기 없이 합쳐지거나 정답 자체를 잘못 인식하면 여전히 실패할 수 있다.
명시적인 바로 뒤의 `아니…`·`말고…`는 제외하지만, 일반적인 뜻·의도나 동음이의어까지
판별하지는 않는다. 예를 들어 `알 수 있어요`의 `알`과 공룡알의 `알`은 이 규칙으로 구분하지 못한다.
앞말에만 남은 미완성 자모는 뒤의 완성된 단어를 무효화하지 않는다.
`들어들어`처럼 목록의 두 글자 이상 정답을 2~4번 완전히 반복한 경우 한 단어로 비교한다.
일반 단어 안에서 정답 일부를 찾아내거나 한 글자 반복을 줄이지 않는다. 실제 ASR 출력은 보존한다.
사용자가 제공한 활동 목록의 동작 15종·표현 135개로 다른 동작을 구분한다. 인식된 말이
`쳐요`인데 후보가 `줘요`인 경우처럼 서로 다른 동작으로 분명히 인식되면 유사도가 높아도 보류한다.
같은 동작의 어미 차이에 대한 기존 허용은 유지한다. 이 표는 허용 정답을 추가하지 않는다.
점수가 높은데 확정하지 않는 이유와 반복을 줄인 비교 표현은 후보별 점수에서 확인한다.
인식 결과의 발음기호 변환은 비교 단계에만 적용한다. 모델 학습 방식이나 가중치를 바꾸지 않는다.
정답 확정·재시도·수동 중단 결과, 설정, 검사별 기록과 대표 음성을 저장한다. 정답 확정은
확정 순간의 입력 2.5초를, 미확정은 가장 유사했던 입력 구간을 보존한다. 네트워크 재전송은
연속 횟수나 저장 기록을 중복 증가시키지 않는다. 선택된 단어·후보별 점수도 기록한다.
장시간 듣기에서도 음성은 최근 2.5초와 대표 구간만 보관하며, 검사 기록은 최근 240회와
생략한 검사 수를 저장한다. 활성 세션은 계속 갱신하고, 10분간 요청이 없으면 만료된다.
후보가 여러 개면 실제 정답 전사가 지정되지 않았으므로 CER를 계산하지 않고, 기존 CER
집계에서도 제외한다. 한 후보만 지정한 테스트의 CER와 게임 통과 판정도 서로 별도다.
현재 웹 화면에서는 실시간 받아쓰기·녹음 후 분석·WAV 업로드 모드를 제거했다.
이전 테스트의 녹음과 결과는 보존하며, `저장된 테스트 결과`는 현재 인식 텍스트와 구분해서 표시한다.
