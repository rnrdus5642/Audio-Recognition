# 아동 발화 튜닝 (2026-08-11)

AI Hub 아동 음성으로 매칭 파라미터와 confusion matrix 를 실측 조정한
기록입니다. **결과는 저장소에 반영하지 않았습니다** — 이번 주 배포가 성인
대상이고, 아동 값을 성인에 쓰면 임계값이 지나치게 관대해집니다.

나중에 아동 대상으로 넘어갈 때 이 폴더의 스크립트로 재현하거나,
`ko_child_v2.json` 과 아래 설정을 그대로 가져다 쓰면 됩니다.

---

## 한 줄 결론

**파라미터 튜닝은 상한에 닿았습니다.** 아동 발화에서 검출 48.7%인데, 임계값을
넘을 수 있는 케이스가 애초에 52.8%뿐입니다. 나머지 47%는 wav2vec2 가 아이
목소리를 다른 말로 알아들어서, 어떤 설정으로도 못 잡습니다.

그 이상은 음향 모델 fine-tune 으로만 풀립니다.

## 측정 결과

### 데이터

| split | 구성 | 화자 |
|---|---|---|
| tune | free 6~7세 + formatted 6~7세 | 116명 |
| valid | free 8~9세 | 46명 |
| check | formatted 5세 | 30명 |

화자 단위로 분리했습니다. 같은 아이가 두 split 에 들어가면 목소리에 맞춘
값이 검증도 통과해버립니다.

### 튜닝 전후

| | 검출 (tune) | 오확정 (10초 세션) |
|---|---|---|
| 시작 (성인용 설정) | 46.6% | 2.99% |
| 튜닝 후 | **49.5%** | **0.70%** |

검증셋에서 61.7% 로 튜닝셋보다 높아, 화자 과적합은 없습니다.

### 예산별 트레이드오프

| 예산 | tune | valid (8~9세) | check (5세) |
|---|---|---|---|
| 0.5% | 36.7% | 48.4% | 19.8% |
| 1.0% | 48.7% | 62.4% | 28.2% |
| **2.0%** | **53.6%** | **68.2%** | 30.8% |
| 3.0% | 55.4% | 71.0% | 33.7% |
| 5.0% | 57.8% | 70.7% | 37.1% |
| 10.0% | 61.6% | 73.8% | 41.8% |
| 제한 없음 | 89.3% | 94.7% | 76.5% |

**1% → 2% 가 가장 남는 구간**입니다 (검출 +4.9%p, 오확정 +0.7%p). 그 뒤로는
거의 1:1 교환입니다.

"제한 없음" 89.3% 이 말해주는 것: 매칭 엔진 자체는 아이 발음을 잡습니다.
48.7% 는 엔진의 한계가 아니라 오확정을 막느라 낸 비용입니다.

### 파라미터 영향력

제안 설정에서 하나씩만 흔들었을 때의 검출 변동폭입니다.

| 파라미터 | 검출 | 오확정 |
|---|---|---|
| `skip_cost` | ±51.4%p | ±2.05%p |
| 연속 확인 | ±45.6%p | ±2.30%p |
| 임계값 | ±34.3%p | ±4.48%p |
| 문맥 배수 | ±29.9%p | ±0.25%p |
| 커버리지 | ±4.1%p | ±1.60%p |

`skip_cost` 가 압도적입니다. 0.05(성인용)는 아동 발화에 3배쯤 비쌉니다.

**문맥 배수는 넓힐수록 검출이 오르는데 오확정은 거의 안 오릅니다** (4배 41%
→ 8배 46%, 오확정 0.87% → 0.95%). 넓은 문맥이 파편 매칭을 억제하기
때문입니다. 그 덕에 연속 확인이 1회로 내려가 확정 지연이 절반이 됩니다.

### 왜 낮은가

검출 케이스 1,950건에서 낼 수 있는 최고 점수 분포입니다.

| 최고 점수 | 건수 |
|---|---|
| 0.00~0.50 | 432 (22.2%) |
| 0.50~0.70 | 239 (12.3%) |
| 0.70~0.85 | 306 (15.7%) |
| 0.85~1.00 | 955 (49.0%) |
| 1.00 | 18 (0.9%) |

**빈 출력은 0건**입니다. 모델이 침묵한 게 아니라 다른 말로 알아들었습니다.
22% 는 점수 0.5 도 안 나옵니다.

성인과 비교하면 원인이 분명합니다.

| | ASR 문자 오류율 | 검출 |
|---|---|---|
| 성인 (Zeroth) | 1.7% | 87.5% (142단어) |
| 아동 (AI Hub) | — | 48.7% |

같은 엔진인데 반으로 줍니다. 모델이 성인 음성으로만 학습됐고, 아이는 성도가
짧아 포먼트가 높습니다.

### 오확정의 실태

180건을 뜯어보면 세 종류입니다.

**진짜 그 소리가 난 경우 (막을 수 없음)**

```
사과  0.820   매칭 [s,a,k,w,a]     "과연 수영장에서" → 사...과연
와요  0.820   매칭 [a,j,o]         "잡아요" "놀아요" "있어요"
```

한국어 어미가 전부 `~아요/어요` 라 `와요` 는 구조적으로 취약합니다.

**한 음소만 다른 경우**

```
친구  0.750   매칭 [tɕʰ,i,n,k,a]   "신나게" → 진나가
```

**음소가 꽤 다른데 통과 (매칭 문제, 약 30%)**

```
바나나 0.667  매칭 [p͈,a,l,t,a]    "빨리"
```

**커리큘럼에서 `와요`·`가요`·`사과` 는 피하는 게 좋습니다.** 임계값으로 막을
수 있는 건 세 번째 종류뿐입니다.

## 아동용 설정 (반영하지 않음)

예산 1% 기준입니다. 2% 로 가려면 `budget_curve.py` 출력의 해당 행을 쓰세요.

```
matrix        ko_child_v2.json (이 폴더)
skip_cost     0.02     (성인 0.05)
커버리지        0.9      (성인 0.8)
문맥 배수       8.0      (성인 4.0)
연속 확인       1회      (성인 2회)
임계값         3음소 0.875 · 4음소 0.875 · 5음소 0.85
              6음소 0.80  · 7음소 0.775 · 8음소 0.70
```

### confusion matrix 학습

`ko_child_v1.json` 을 정렬 빈도로 보정한 것이 `ko_child_v2.json` 입니다.
26~43쌍만 갱신되고 나머지 79쌍은 손으로 넣은 값 그대로입니다 — 관측 5회
미만이거나 음소 자체가 드문 것은 건드리지 않았습니다.

크게 바뀐 것:

| 관측 | 치환 | 학습 | 기존 |
|---|---|---|---|
| 42 | `m → n` | 0.58 | 0.50 |
| 34 | `m → l` | 0.55 | 0.35 |
| 34 | `ʌ → a` | 0.49 | 0.40 |
| 26 | `u → o` | 0.33 | 0.30 |
| 22 | `k͈ → k` | 0.30 | 0.20 |
| 19 | `ɛ → a` | 0.32 | 0.50 |
| 15 | `a → ʌ` | 0.61 | 0.40 |

대부분 **기존값을 조금씩 올리는 방향**입니다. 손으로 넣은 값이 전반적으로
관대했다는 뜻이고, 오확정 분석과 일치합니다. `ɛ → a` 만 반대로 싸졌습니다 —
아이가 `ㅐ` 를 `ㅏ` 로 내는 게 실제로 흔합니다.

음운론적 직관이 대체로 맞았고 데이터가 보정하는 형태라, 완전히 뒤집혔다면
오히려 학습 쪽을 의심해야 했을 겁니다.

## fine-tune 방침 (2026-08-11 결정)

파라미터 튜닝이 상한에 닿았으므로 다음 단계는 음향 모델입니다. 그때의 방침을
미리 정해둡니다.

### 성인 모델과 아동 모델을 따로 둡니다

아동 데이터에 **최대한 맞추되 성인 성능도 남기는** 것이 목표입니다. 두
데이터를 섞어 한 모델로 둘 다 잡으려 하면 양쪽 다 어중간해지므로, 타협하지
않고 모델을 나눕니다.

```
wav2vec2_ko.onnx           현재 모델. 손대지 않음
wav2vec2_ko_child.onnx     아동 전용 fine-tune 결과
```

성인 모델은 [Release `model-v1`](https://github.com/rnrdus5642/Audio-Recognition/releases/tag/model-v1)
에 있고 SHA-256 이 `ModelDownloader` 에 박혀 있습니다. **이 Release 를 지우면
안 됩니다** — 지우는 순간 성인 경로가 사라집니다.

아동 모델은 `model-v2-child` 로 별도 Release 를 만듭니다. 서로 건드리지
않습니다.

이렇게 하면 "fine-tune 하면 성인 성능이 떨어지지 않나" 라는 걱정 자체가
사라집니다. 성인용은 그대로 두니까요.

### 학습에 성인 데이터를 섞지 않습니다

catastrophic forgetting 을 막으려고 성인 데이터를 섞는 것이 표준 대응이지만,
여기서는 **일부러 하지 않습니다.** 성인 성능은 별도 모델이 담당하므로,
아동 모델은 아동에만 맞추는 것이 낫습니다.

### 앱에서 고르는 방법

`IPhonemeRecognizer` 뒤에 있어 파일만 바꾸면 됩니다. 매칭·임계값·Unity 코드는
그대로입니다.

```csharp
var model = Resources.Load<ModelAsset>("Models/wav2vec2_ko_child");
var recognizer = new SentisPhonemeRecognizer(model, vocab);
```

### 같이 갈라야 하는 것

| | 성인 | 아동 |
|---|---|---|
| 모델 | `wav2vec2_ko.onnx` | `wav2vec2_ko_child.onnx` |
| matrix | `ko_child_v1.json` | `ko_child_v2.json` (이 폴더) |
| 임계값 | `targets.json` (현재) | 별도 빌드 필요 |

**어휘(`vocab.json`)는 공유하는 편이 낫습니다.** fine-tune 때 토큰 집합을
바꾸지 않으면 그대로 쓸 수 있고, 바꾸면 모델 전용 vocab 을 따로 관리해야
합니다.

`targets.json` 의 임계값은 빌드 타임에 박히므로, 모델별로 다른 값을 쓰려면
빌드를 갈라야 합니다. fine-tune 결과가 나온 뒤에 정하면 됩니다.

### 학습 후 반드시 잴 것

프레임 캐시가 남아 있으므로 새 모델로 추론만 다시 돌리면 두 숫자가 바로
나옵니다. **추측하지 말고 확인한 뒤에** 쓸지 정합니다.

```
아동   AI Hub 5~9세      지금 48.7% (상한 52.8%)
성인   Zeroth test        지금 87.5% (142단어)
```

성인이 얼마나 떨어지는지는 아동 모델을 성인 대상으로 쓸 일이 없다면 참고
수치일 뿐입니다.

### 데이터 (2026-08-13 수정)

Validation 만으로는 부족합니다. **시간이 아니라 화자가 모자랍니다.**

캐시된 2,850건을 화자별로 갈라 분산을 분해했더니 이렇게 나왔습니다.

| | 분산 | 비중 |
|---|---|---|
| 나이 | 0.0077 | 20% |
| **아이별 개인차** | **0.0115** | **29%** |
| 표본 우연 | 0.0162 | 41% |

같은 나이 안에서도 아이마다 0%~94% 로 갈립니다. 나이대를 맞추는 것보다
**아이를 많이 넣는 것**이 중요하다는 뜻입니다.

그런데 Validation 의 5~7세는 148명뿐이고, 그 전원이 이미 평가에 쓰였습니다.
학습·평가로 가르는 것 자체가 불가능했습니다.

그래서 Training 셋을 받습니다. 목표는 **5~7세 화자 500명 이상** — 학습 350 /
평가 150 으로 갈라도 양쪽 다 믿을 수 있는 규모입니다.

받는 이유가 "많이 학습시키려고"가 아니라는 점은 짚어둘 만합니다. 학습셋은
150~200시간에서 끊는 게 낫고, 그 이상은 epoch 시간만 늘어납니다.

정리는 [tools/aihub](../aihub/README.md) 가 합니다.

## 다시 돌리는 법

### 1. 데이터 정리

[tools/aihub](../aihub/README.md) 가 받은 것을 그대로 받아 정리합니다.

```bash
python python/tools/aihub/index.py
python python/tools/aihub/organize.py
python python/tools/aihub/splits.py
python python/tools/aihub/verify.py
```

`index.csv` 에 나이·화자·전사·길이·발화구간이 다 있어서, 이후로는 라벨을
다시 읽을 일이 없습니다.

### 2. 프레임 캐시

```bash
python python/tools/child_tuning/tune_frames.py     # free 6~7세 (~98분)
python python/tools/child_tuning/valid_frames.py    # free 8~9세 (~60분)
python python/tools/child_tuning/more_speakers.py   # formatted 6~7세 (~69분)
```

**이게 전체 비용의 99% 입니다.** 프레임별 IPA 를 한 번 뽑아두면 이후 설정을
바꿔가며 재는 건 몇 초입니다. 파라미터는 음소에서 점수를 내는 단계에만
영향을 주고, 소리에서 음소를 뽑는 단계와는 무관하기 때문입니다.

단 `hop` 이나 창 길이를 바꾸면 캐시가 무효가 됩니다.

이 세 스크립트는 옛 폴더 구조와 옛 분할을 가리킵니다. `tools/aihub` 로 다시
정리한 뒤에는 `splits.json` 을 읽도록 고쳐 써야 합니다. 표본 설계(분할별 몇
발화, 어떤 단어)는 분할 크기가 나온 뒤에 정합니다.

### 3. 튜닝

```bash
python python/tools/child_tuning/learn_matrix.py    # 정렬 빈도로 matrix 추정
python python/tools/child_tuning/autotune.py        # matrix ↔ 파라미터 교대 (~11분)
python python/tools/child_tuning/budget_curve.py    # 예산별 트레이드오프
python python/tools/child_tuning/sensitivity.py     # 파라미터 영향력
```

## 겪은 함정

**되먹임 고리.** 정렬을 학습 중인 matrix 로 판정하면 비용이 싸질수록 나쁜
정렬이 통과하고, 그래서 더 싸집니다. 첫 시도에서 쓰이는 정렬이 554 → 872 로
늘기만 하고 수렴하지 않았습니다. 정렬 필터는 **고정된 기준(손으로 만든
matrix)** 으로 한 번만 판정해야 합니다.

**희귀 쌍.** `tɕ → tɕʰ` 가 2회 관측으로 손으로 넣은 값을 덮어썼습니다. 쌍
단위 최소 관측(5회)과 기존값 쪽으로의 수축이 필요합니다.

**성공만 학습.** 통과한 케이스에서만 세면 이미 되는 패턴만 강화됩니다.
전사에 단어가 있는 케이스는 통과 여부와 무관하게 전부 씁니다.

**화자 수.** 15명으로 튜닝했을 때 3음소 임계값 0.925 같은 극단값이 나왔고,
118명으로 늘리자 0.875 로 내려왔습니다. 화자가 적으면 그 아이들의 발음
특성에 맞춰집니다. `verify.py` 가 이제 이 조건을 검사합니다.

**분할을 나중에 만들면 늦습니다.** 필요할 때마다 덧붙여 만든 탓에 `tune`
화자가 15명뿐인 채로 튜닝이 돌았고, 5~7세는 전원이 평가에 들어가 학습에
쓸 화자가 남지 않았습니다. 데이터를 정리하는 시점에 분할까지 정해야 합니다.

**옮길 때는 복사.** `aihub_sort.py` 가 tar 에서 꺼내며 원본을 남기지 않아,
나중에 확인하려 했을 때 5~9세 말고는 오디오가 없었습니다. 무엇을 가지고
있는지 모르는 상태가 됩니다.

**Windows 소파일 I/O.** 라벨 27만 개를 하나씩 여는 데 22분 걸립니다. 조사
목적이면 표본만 읽으세요.

## 알아둘 것

- 이 코퍼스는 **정상 발달 아동**입니다. 이 시스템의 대상인 발달지연 아동
  코퍼스는 개인정보·의료정보라 공개된 것이 사실상 없습니다
- `free` 에는 5세가 없습니다. 어린 나이대를 보려면 `formatted`(동화 낭독)를
  써야 하고, 발화 성격이 다릅니다
