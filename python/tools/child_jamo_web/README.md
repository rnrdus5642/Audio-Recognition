# 아이 음성 인식 확인 뷰어

최근 작업의 결론과 문서 목록은 [현재 상태](../../../docs/CHILD_JAMO_STATUS.md)에 있다.
마이크로 직접 단어를 말해 보려면 8776 포트의 [마이크 페이지](README_MICROPHONE.md)를 사용한다.
아래는 기존 데이터셋·아동 녹음 뷰어의 사용법이다.

직접 미세조정한 한국어 HuBERT 자모 모델이 아이 음성을 어떻게 알아듣는지
브라우저에서 직접 듣고 확인하는 로컬 페이지입니다.

## 실행

```powershell
powershell -File start_child_jamo_web.ps1               # 백그라운드 실행
powershell -File start_child_jamo_web.ps1 -OpenBrowser  # 실행 후 브라우저 열기
powershell -File start_child_jamo_web.ps1 -Stop         # 이 스크립트가 띄운 서버만 종료
```

주소는 <http://127.0.0.1:8768/aihub> (말뭉치) 와
<http://127.0.0.1:8768/recordings> (직접 녹음한 아동 음성) 입니다. 창 없이 실행되므로 터미널을 닫아도
서버는 계속 살아 있습니다. 모델이 3.85 GB라 첫 기동에 30초쯤 걸리고,
런처는 실제로 `/api/status` 가 준비 완료로 응답할 때까지 기다린 뒤에만
"준비 완료"라고 알려 줍니다.

로그는 `.venv/child-jamo-web-20260916/server.log`,
실행 중인 PID는 같은 폴더의 `server.pid.json` 에 있습니다.

## 화면에 보이는 것

| | |
|---|---|
| **원문** | 말뭉치에 적힌 문장 |
| **예상 발음 표기** | 그 문장을 프로젝트 음운 규칙으로 바꾼 발음 표기 (학습 목표) |
| **모델 인식 결과** | 모델이 소리만 듣고 내놓은 결과 |

이 모델은 **발음 나는 대로 적은 표기**를 학습 목표로 삼아 훈련했습니다.
한국어는 적힌 대로 소리 나지 않는 경우가 많아서 (`익은` → `이근`), 원문과
예상 발음 표기를 따로 보여 줍니다. 모델 결과는 가운데 칸과 비교하는 것이
맞습니다. 학습 목표가 실제 발음에 대한 전문가 표기는 아니라는 점은 아래
한계에 적어 두었습니다.

## 정직하게 보여 주는 규칙

- 모델 출력 후보는 **42개**(자모 40 + 단어 경계 + CTC blank)입니다. blank는
  무음이나 띄어쓰기 판정이 아니라 해당 시점에 자모를 출력하지 않는 후보입니다. 예측한
  자모를 음절로 합칠 수 있을 때만 합치고, 합쳐지지 않는 자모는 빨간색으로
  **그대로** 남겨 둡니다. 사전이나 원문으로 고쳐 쓰지 않습니다.
- 원문·정답은 예측이 **끝난 뒤** 점수를 매길 때만 씁니다. 추론 경로에는
  들어가지 않습니다 (`test_compose.py` 에서 확인).
- 자모 오류율은 학습 때와 같은 방식입니다. **띄어쓰기 토큰은 빼고**,
  대체·삽입·삭제를 합한 **편집 횟수**를 예상 발음 자모 수로 나눕니다. 모델이 말을 덧붙이면 100%를 넘을 수
  있고, 그 값을 임의로 100%로 깎지 않습니다.
- 화면 아래의 전체 테스트 성적(자모 오류율 2.89%)은 **과거 집계**입니다.
  지금 보고 있는 음성의 점수와는 별개이며 그렇게 적어 두었습니다.
- 재생되는 소리는 모델에 들어간 신호를 그대로 WAV로 만든 것이라, 들은 것과
  인식한 것이 어긋날 수 없습니다. 올린 파일도 한 번 WAV로 만든 뒤 그것을
  다시 읽어 추론하므로, 재생본과 입력이 같은 배열입니다.
- 화면이 가리키는 모델은 `best.pt` 의 SHA256 으로 식별하며, 과거 테스트
  성적은 `result.json` 이 **바로 그 체크포인트**를 가리킬 때만 보여 줍니다.
- 원본 음성은 감사 때 기록한 PCM 해시와 대조합니다. 길이가 같아도 내용이
  달라졌다면 오류로 멈추고, 옛 결과를 새 음성에 붙이지 않습니다.

## 볼 수 있는 음성 — 출처별로 페이지가 나뉘어 있습니다

두 음성은 성격이 아주 다른 자료라 **한 목록에 섞지 않고 페이지를 나눴습니다.**
위쪽 탭으로 오갑니다. 평범한 링크라서 새로고침·뒤로 가기·즐겨찾기가 그대로
동작하고, 페이지를 옮기면 그 출처의 필터도 자연스럽게 초기화됩니다.

| 페이지 | 주소 | 데이터셋 | 개수 | 비교 | 필터 |
|---|---|---|---|---|---|
| AIHub 데이터 | `/aihub` | 테스트(기본) / 검증 / 학습 | 2,999 / 1,500 / 150,253 | 전사 있음 | 나이 |
| 직접 녹음한 아동 음성 | `/recordings` | 단어별(기본) / 원본 전체 | 83 (아동1 48, 아동2 35) / 4 | 단어별만 있음 | 아동 |

- 한쪽 페이지에서는 **그 출처의 데이터셋만** 고를 수 있습니다.
- 데이터셋 주소도 그대로 씁니다: `/recordings?split=original&child=child2`,
  `/aihub?split=valid`. 데이터셋을 바꾸면 주소도 따라 바뀝니다.
- 다른 출처의 데이터셋 이름을 넣으면(`/aihub?split=personal`) 그 페이지의
  기본값으로 엽니다. 남의 페이지 자료를 보여 주지 않습니다.
- 예전 주소 `/?split=personal`, `/?split=original` 도 계속 직접 녹음한
  음성으로 열리고, 주소만 `/recordings` 로 정리됩니다. 그냥 `/` 는 예전처럼
  AIHub 입니다.
- **인식 기록도 출처별로 나뉩니다.** `/api/history?source=` 가 서버에서
  먼저 걸러낸 뒤 최근 50개를 돌려주므로, 한쪽에서 많이 돌렸다고 다른 쪽
  기록이 밀려나지 않습니다.

기록된 전체 테스트 성적(자모 오류율 2.89%)은 **말뭉치 테스트 세트의 과거
집계**라서 `/aihub` 에만 적습니다. `/recordings` 에는 그 숫자를 쓰지 않고,
어디에 있는 점수인지와 이 음성들의 정확도가 아니라는 사실만 적어 둡니다.
직접 녹음한 음성에 대한 별도의 종합 점수는 만들지 않습니다.

## 직접 녹음한 아동 음성

바탕화면의 원본 폴더를 **읽기만** 합니다 (`CHILD_PERSONAL_AUDIO_ROOT` 로 위치를
바꿀 수 있습니다). 만들어 쓰는 파일은 앱 작업 폴더 안의 16kHz 사본뿐입니다.

- **단어별 83개**는 함께 주신 한글 전사(HWP)에서 옮긴 라벨을 그대로 씁니다.
  전사에 `야옹이`라고 적혔으면 `야옹이`이고, 질문이 노리던 정답 `고양이`는
  8개 행에만 있는 **별도 주석**으로만 보여 줍니다. 전사의 `두르려` 도
  `두드려`로 고치지 않았습니다. `북을 쳐요` 는 한 발화 그대로입니다.
- 구간 경계는 전사 순서와 음량으로 맞춘 것이고 **전부 청취 검수된 자료가
  아닙니다**. 화면에 검수 상태와 우선 검수 대상 여부를 적어 둡니다.
- 아이들의 나이는 자료에 없습니다. 그래서 **나이 미상**이라고만 적습니다.
- **원본 전체 4개**는 받은 녹음 그대로 통째로 재생됩니다. 전체에 맞춰진 전사가
  없으므로 정답과 비교하지 않고, 오류율 자리에는 `비교 불가` 라고 적습니다.
  0%가 아닙니다.
- 원본은 12초 안팎의 구간으로 나눠 인식합니다. 경계는 근처에서 가장 조용한
  곳으로 옮기고, 그래도 말 중간일 수 있으면 그 구간에 표시합니다. 구간은
  **빠짐없이 한 번씩** 전체를 덮으며 (샘플 수로 확인합니다), 구간 결과를
  이어 붙이거나 겹치는 말을 지우지 않습니다. 모델이 낸 그대로입니다.
- 구간 옆 `여기서 듣기` 는 잘라 놓은 조각을 트는 것이 아니라, 재생 중인
  **원본 전체**를 그 시각으로 옮깁니다. 재생본과 인식에 들어간 신호는
  같은 배열입니다.
- 클립은 매번 파일 해시와 샘플 수를, 원본은 PCM 해시를 대조한 뒤 읽습니다.

## 발음 확인 (`/review`)

모델이 기대 발음과 다르게 낸 자음을 모아 두고, **사람이 듣고 실제로 어떻게
들리는지** 남기는 화면입니다. 모델이 맞았는지 채점하는 곳이 아니고, 여기서
답을 저장해도 **인식 결과·점수·다른 화면은 달라지지 않습니다.**

```powershell
# 1. 기준 예측을 만듭니다 (오프라인, 중단되면 이어서 돌아갑니다)
.venv-gpu\Scripts\python.exe python\tools\child_jamo_web\audit.py --baseline
#    이어 돌 때 저장된 기록의 음성 해시까지 대조하려면 --verify-audio
# 2. 자음 오류를 셉니다
.venv-gpu\Scripts\python.exe python\tools\child_jamo_web\audit.py --analyse
# 3. (선택) 학습 분할 후보군을 만듭니다 — 오디오 복사 없이 목록만
.venv-gpu\Scripts\python.exe python\tools\child_jamo_web\candidates.py
```

이어 돌 때 "그 id 는 이미 있다" 로 건너뛰지 않습니다. 저장된 기록은 그때 그
녹음에 대한 것이므로, 샘플 수·기준 자모·전사·구간 정책에 더해 **카탈로그가 들고
있는 PCM 해시까지 매번 대조**합니다. id·길이·기준이 모두 같아도 음성만 바뀌었으면
다시 계산합니다. `--verify-audio` 는 그 위에 파일을 실제로 읽어 다시 해시하는
물리 확인을 더합니다.

기록 파일의 무결성도 실행 전에 봅니다. 마지막 줄이 쓰다 만 상태면 잘라 내고,
마지막 기록이 **완전한데 줄바꿈만 없으면** 줄바꿈을 채웁니다(그대로 덧붙이면 두
기록이 한 줄로 붙어 둘 다 잃습니다). 끝이 아닌 곳의 줄이 깨져 있으면 **파일을
고치지도, 덧붙이지도 않고 멈춥니다** — 설명되지 않은 손상 위에 쓰지 않습니다.

실행 중에는 `baseline-state.json` 이 `status: running` 으로 먼저 쓰이고 100개마다
원자적으로 갱신되며, 중단되면 `interrupted`, 실패하면 `failed` 로 끝납니다. 지난
실행의 `complete` 가 남아 있어 끝난 것처럼 보이는 일이 없습니다. `pool_coverage`
는 저장된 기록 수가 아니라 **지금 카탈로그에 있는 녹음 중 아직 유효한 기록을 가진
것**만 셉니다. 기준이 달라져 다시 계산하려다 실패한 녹음은 옛 기록이 파일에 남아
있어도 덮인 것으로 세지 않습니다.

이미 만들어 둔 예측이 있는데 기록 형식만 바뀐 경우에는 다시 추론하지 않고
`--migrate` 로 현재 음성·기준과 대조해 신원만 갱신합니다. 갱신은 **채워 넣기만**
합니다. 기록이 들고 있지 않은 신원 항목은 채우지만, 이미 들고 있는 값이 지금과
다르면(라벨 버전·디코더·입력 정책·정밀도, 또는 전사·기준·샘플 수·구간 정책)
덮어쓰지 않고 거부하거나 빼 둡니다. 같은 체크포인트라도 다른 방식으로 계산된
기록에 이번 신원을 찍어 주는 일은 없습니다.

그다음 <http://127.0.0.1:8768/review> 를 열면 **우선 확인 18개**가 나옵니다.
직접 녹음 83개와 말뭉치 검증 1,500개를 대상으로 하고, 목록에는 서로 다른 자음
혼동, 두 아이, 이전에 문제로 지목된 녹음, 그리고 맞게 인식된 대조군이 섞여
있습니다. 나머지(직접 녹음 26개, 말뭉치 268개)도 볼 수는 있지만 **전부
확인하실 필요는 없습니다.**

화면에서 하는 일:

- 모델에 들어간 소리를 그대로 듣습니다. 직접 녹음한 클립은 **원본의 앞뒤까지**
  따로 들어 볼 수 있습니다(참고용이라고 적어 둡니다).
- 전사와 모델 결과는 **듣고 난 뒤에 펼쳐 보도록** 접어 두었습니다.
- 전사대로 / 모델이 쓴 대로 / **다르게 들림(직접 입력)** / 판단하기 어려움 중
  하나를 고릅니다. **미리 선택된 답은 없습니다.**
- 구간이 잘못 잘렸거나 여러 사람 목소리가 섞였으면, 발음을 고르지 않고도
  표시할 수 있습니다.
- 직접 적으신 글자는 **입력하신 그대로** 저장합니다. 음운 규칙을 적용하거나
  전사 쪽으로 고치지 않습니다.

답은 `.venv/child-jamo-web-20260916/consonant-review/reviews.sqlite3` 에
이력과 함께 쌓이고, 브라우저를 새로 고치거나 서버·PC 를 다시 켜도 남습니다.
`/api/review/export` 로 출처·음성 해시·기준 예측·결속값까지 붙은 JSON 을 받을
수 있습니다. `판단하기 어려움`·`쓸 수 없음` 은 **정답 목록에 들어가지 않고**
따로 나옵니다.

답이 어떤 음성에 대한 것인지 묶어 둡니다. 항목을 열 때 음성·기준·예측을 묶은
값과 현재 리비전을 함께 받고, 저장할 때 그대로 돌려보냅니다. 그 사이 음성이나
기준이 바뀌었거나 다른 창에서 더 새로운 답이 저장되었으면 **덮어쓰지 않고
거절**합니다. 이미 저장된 답이라도 음성이 바뀌면 **완료로 세지 않고** 다시
들어 보시도록 표시합니다.

화면을 옮기는 동안에도 답이 사라지지 않습니다. 저장이 오가는 동안에는 저장·다음·
목록·페이지 버튼까지 전부 잠기고, 답이 돌아올 화면은 처음 물어본 그 화면입니다.
다음 음성을 불러오는 동안에는 **떠나는 음성의 입력칸을 먼저 비우고 잠급니다** —
불러오는 사이에 적은 답이 도착과 함께 조용히 지워지던 문제를 막습니다. 저장하지
않은 답이 있는 채로 다른 음성을 고르면 먼저 물어보고, 취소하면 적으신 답은 그대로
남습니다.

내보낸 결과는 **사람이 듣고 남긴 검토**이지 전문가 음성 전사나 임상 판정이
아닙니다. 모든 항목에 `training_eligible=false` 가 붙습니다 — 직접 녹음 83개와
검증 분할은 개발·평가용이고 학습에 넣지 않습니다.

## 기능

- 테스트 2,999개 / 검증 1,500개 전체를 검색·필터(나이, 길이, 낭독·자유발화)
  하고 넘겨 볼 수 있습니다. 학습 15만 개는 처음 고를 때 뒤에서 읽어 옵니다.
  직접 녹음한 음성은 아동 1 / 아동 2 로 걸러 볼 수 있습니다.
- 나이는 말뭉치에만, 아동은 직접 녹음한 음성에만 있는 항목이라 서로 숨겨집니다.
  **숨겨진 필터는 걸리지 않습니다.** 고른 값은 남아 있어서 그 데이터셋으로
  돌아오면 다시 보이면서 다시 적용됩니다. 보이는 필터만 목록을 좁힙니다.
- 음성을 고르면 **바로 인식합니다**(버튼을 따로 누르지 않아도 됩니다).
  `이 음성 인식하기` 는 같은 음성을 다시 인식할 때 씁니다. 이전/다음/무작위
  버튼도 고르는 즉시 인식합니다.
- `여기서부터 10개 인식` 은 **지금 고른 음성부터** 현재 필터 안에서 다음
  10개를 인식합니다. 보고 있는 페이지가 아니라 선택 위치가 기준이며,
  성공/요청 개수를 함께 보여 줍니다. 모두 실패하면 0%가 아니라 실패로
  표시합니다.
- 자모 단위 비교를 펼치면 어디가 어떻게 달랐는지(바뀜·빠짐·덧붙음) 보입니다.
- 내 WAV/FLAC/OGG 파일도 올려 볼 수 있습니다. 30초·20MB를 넘으면 자르지 않고
  거절합니다. 파일은 이 컴퓨터 안에서만 처리됩니다.

## 구성

```
compose.py            예측 자모 -> 읽을 수 있는 한글 (합쳐지지 않으면 그대로 둠)
engine.py             best.pt 를 한 번만 올려 두고, 한 번에 하나씩 추론
samples.py            감사 완료된 매니페스트 검색/페이지 처리
personal.py           직접 녹음한 음성의 카탈로그·출처 확인·원본 구간 나누기
audit.py              자음 오류 집계 (오프라인, 이어서 돌 수 있는 기준 예측)
review.py             청취 검토 저장소(SQLite, 이력 포함)와 우선 확인 목록
candidates.py         학습 분할에서 뽑은 후보군 목록 (오디오 복사 없음)
server.py             FastAPI, 127.0.0.1 전용
static/               HTML/CSS/JS (별도 프런트엔드 도구 없음)
validate_spread.py    테스트 셋 고정 표본으로 실제 성능 기록
validate_personal.py  직접 녹음한 83개 + 원본 4개 전부 실제 추론 기록
qa_browser.py         실제 브라우저 점검 (별도 QA 가상환경에서 실행)
qa_personal.py        직접 녹음한 데이터셋 브라우저 점검
qa_fixes.py           필터 전환·업로드 전환·원본 커버리지 표시 집중 점검
qa_sources.py         두 출처 페이지 분리·주소·뒤로 가기·기록 분리 점검
test_compose.py       합성·지표 단위 테스트
test_routes.py        신원·출처·업로드·경로 테스트
test_personal.py      직접 녹음 자료의 출처·전체 포함·비교 불가 처리 테스트
test_audit.py         자음 집계 규칙 (어두/받침, 빠짐/덧붙음, 음운 변동)
test_review.py        검토 저장소·이력·내보내기·우선 목록
test_review_routes.py 검토 경로 (별도 임시 DB 로만 실행)
qa_review.py          발음 확인 화면 브라우저 점검 (임시 서버 + 임시 DB)
```

작업 산출물은 전부 `.venv/child-jamo-web-20260916/` 아래에만 씁니다.
학습 산출물(`best.pt`, 매니페스트, `result.json`)과 `labels.py` 는 읽기만
하며 건드리지 않습니다.

## 알아 두실 한계

- 자모 오류율은 전사에서 유도한 **예상 발음 표기**와 비교한 값입니다. 아이가
  실제로 낸 소리에 대한 전문가 표기가 아니므로, 발음 오류 진단이나 합격
  판정으로 읽으면 안 됩니다.
- 전체 테스트 성적은 고정된 체크포인트의 과거 집계이며, 지금 보고 있는 개별
  결과와 다릅니다.
- 검증 음성은 체크포인트를 고르는 데 쓰였으므로 테스트만큼 "본 적 없는"
  음성이 아닙니다. 기본값은 테스트입니다.
- 모델이 낼 수 있는 기호는 자모 40개뿐이라, 겹받침처럼 어휘에 없는 형태는
  원리상 나올 수 없습니다.
- 업로드는 WAV/FLAC/OGG 만 받습니다. ffmpeg 가 필요한 형식은 지원하지 않습니다.
- 직접 녹음한 83개의 라벨은 **사람이 쓴 전사**이지만, 어디서 어디까지가 한
  단어인지는 음량으로 맞춘 것이고 전부 들어 본 자료가 아닙니다. 여기 나오는
  자모 오류율은 그 전사에서 유도한 목표와의 차이일 뿐, 아이 발음에 대한
  평가가 아닙니다.
- 원본 전체 4개에는 비교할 전사가 없습니다. 구간 경계가 말 중간을 지날 수
  있고, 그런 구간은 화면에 표시하지만 그 구간의 앞뒤 글자는 잘린 말일 수
  있습니다. 구간 결과를 이어 붙여 하나의 전사로 읽으면 안 됩니다.
- 원본의 구간 결과는 서로 다른 조각을 따로 인식한 것이라, 한 번에 통째로
  인식한 결과와 같지 않습니다. 긴 녹음을 한 덩어리로 넣지 않기 위한
  선택이며, 그 사실을 감추지 않습니다.
